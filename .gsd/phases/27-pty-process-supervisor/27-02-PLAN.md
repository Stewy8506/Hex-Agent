# Plan 27.02: Gateway Process Tools, ReAct Loop, TUI, and CLI Integration

## Objective
Expose the PTY Process Supervisor to autonomous agents and developers by registering four dedicated tools (`start_process`, `read_terminal`, `kill_process`, `list_processes`) in `ToolGateway` with default-deny policy gating (`R0` for non-mutating inspections, `R2` for process spawns/kills), integrating background process control into the multi-turn `ReActLoop`, adding interactive `/ps` and `/processes` slash commands to `HexConsole` TUI, implementing the `hex ps` CLI subcommand, and verifying with a comprehensive integration test suite.

  <action>
    Integrate `ProcessRegistry` into `ToolGateway` and register all process management tools:

    1. Register Tool Schemas in `TOOL_DEFINITIONS` in `src/harness_core/gateway.py`:
       - `start_process`:
         - description: "Spawn a background command in an asynchronous pseudo-terminal (PTY) or pipe (R2)."
         - risk_class: `RiskClass.R2`
         - parameters: `command` (str, required), `cwd` (str, default=""), `pty` (bool, default=True).
       - `read_terminal`:
         - description: "Read output slice from a running or completed background process buffer (R0)."
         - risk_class: `RiskClass.R0`
         - parameters: `process_id` (str, required), `offset` (int, default=0), `limit` (int, default=2000).
       - `kill_process`:
         - description: "Terminate an active background process by process_id (R2)."
         - risk_class: `RiskClass.R2`
         - parameters: `process_id` (str, required), `force` (bool, default=False).
       - `list_processes`:
         - description: "List all background processes and their current status (R0)."
         - risk_class: `RiskClass.R0`
         - parameters: `status` (str, optional, enum: ["running", "completed", "failed", "killed", "all"]).

    2. Wire Handlers in `ToolGateway`:
       - Initialize `self.process_registry = process_registry or get_process_registry()` in `ToolGateway.__init__`.
       - Implement `_tool_start_process(workspace_dir: Path, args: dict[str, Any]) -> dict[str, Any]`:
         - Confine `cwd` to `workspace_dir` (or default to `workspace_dir`).
         - Delegate to `self.process_registry.spawn(...)`.
         - Scrub secrets from command and initial output with `redact_secrets`.
       - Implement `_tool_read_terminal(workspace_dir: Path, args: dict[str, Any]) -> dict[str, Any]`:
         - Delegate to `self.process_registry.read_output(...)`.
         - Scrub secrets from returned text slice.
       - Implement `_tool_kill_process(workspace_dir: Path, args: dict[str, Any]) -> dict[str, Any]`:
         - Delegate to `self.process_registry.kill(...)`.
       - Implement `_tool_list_processes(workspace_dir: Path, args: dict[str, Any]) -> dict[str, Any]`:
         - Delegate to `self.process_registry.list_processes(...)`.
       - Update existing `_tool_process` to delegate to `self.process_registry` for backward compatibility.

    3. ReActLoop Tool Calling Compatibility:
       - Verify in `src/harness_core/react_loop.py` that the ReAct loop executes `start_process`, `read_terminal`, `kill_process`, `list_processes` and appends their observation output cleanly without truncation errors.

    4. Author Initial Integration Test Suite in `tests/test_gateway_process_tools.py`:
       - Test `ToolGateway` dispatch of `start_process` spawning a background task.
       - Test `read_terminal` polling stream slices incrementally.
       - Test `list_processes` reflecting state transitions.
       - Test `kill_process` cleanly terminating background jobs.
       - Test `R0` vs `R2` risk gating policies.
