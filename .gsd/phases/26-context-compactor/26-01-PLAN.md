# Plan 26.01: Stale Tool Demotion & Atomic Tool-Boundary Preservation

<objective>
Implement Phases 1 & 2 of the context compactor in `src/harness_core/context_compressor.py` matching Hermes Agent (`context_compressor.py` and `context_compressor_tail.py`). This delivers deterministic stale tool result demotion (truncating bulky historical outputs while retaining head+tail summaries and omitted line counts, leaving recent turns intact) and atomic tool-pair boundary protection (guaranteeing assistant tool calls and corresponding tool results are never split across compaction cuts).

Purpose: Prevent context blowout from long-running tool outputs while avoiding model amnesia on recent actions and preventing API 400 Bad Request errors caused by orphaned tool calls/results.
Output: `src/harness_core/context_compressor.py` core module with Phase 1 & Phase 2 implementations, and unit test suite in `tests/test_context_compressor_tail_pruning.py`.
</objective>

  <name>Task 1: Token Estimation, Elision Markers & Stale Tool Demotion</name>
  <files>src/harness_core/context_compressor.py</files>
  <action>
    Create `src/harness_core/context_compressor.py` with foundational token estimation and stale tool demotion logic:
    1. Define token estimation helpers:
       - `estimate_tokens_rough(text: str) -> int` (approx. 4 chars per token with minimum 1 token for non-empty text).
       - `estimate_message_tokens(msg: dict[str, Any]) -> int` (sums content, role overhead, and tool_calls serialized length).
       - `estimate_messages_tokens(messages: list[dict[str, Any]]) -> int`.
    2. Implement non-imitable elision markers and string elision utilities matching Hermes `compression_marker.py`:
       - `HEX_COMPRESSION_MARKER_PREFIX = "⟪HEX-CONTEXT-COMPRESSION:"`.
       - `elide(text: str, limit: int) -> str` and `elide_middle(text: str, head_chars: int, tail_chars: int) -> str` inserting accurate omitted character and line counts.
    3. Implement recovery stubs and stale tool demotion (`demote_stale_tail_tools`):
       - Parameterize `keep_tool_rounds: int = 4` and `min_demote_chars: int = 1000`.
       - Identify tool result messages in both structured format (`role == "tool"`) and XML format (`role == "user"` with `<observation tool="...">`).
       - Protect the newest `keep_tool_rounds` tool executions from demotion.
       - For older tool messages exceeding `min_demote_chars`, replace verbose content with a structured recovery stub:
         `"[{tool_name} output demoted at compaction — {omitted_chars:,} chars ({omitted_lines} lines) omitted; head and tail preserved]\n{head}\n⟪HEX-CONTEXT-COMPRESSION: {omitted_chars} chars omitted⟫\n{tail}"`
         or a clean one-line stub `"[tool {name} output demoted at compaction — {content_len:,} chars preserved in session history]"` when content is uniform.
       - Never demote error messages or failure suffixes so the agent retains knowledge of failed attempts.
    AVOID: Truncating short outputs or outputs in the protected recent tail (within `keep_tool_rounds`), because this breaks the active ReAct cycle.
  </action>

  </verify>
  <done>

<task type="auto">
  <name>Task 2: Atomic Tool-Pair Boundary Protection & Alignment</name>
  <files>src/harness_core/context_compressor.py</files>
  <action>
    Add Phase 2 atomic tool-call and tool-result boundary protection logic to `src/harness_core/context_compressor.py`:
    1. Implement tool pair grouping & detection:
       - Structured format: Match assistant message `tool_calls` (`id` / `call_id`) with subsequent tool messages (`tool_call_id`). Handle parallel tool calls where one assistant message issues $M$ calls followed by $M$ tool responses.
       - XML / Text format: Match assistant messages containing `<tool_call>...</tool_call>` with following messages containing `<observation ...>` or `<tool_result>`.
    2. Implement boundary alignment algorithms:
       - `find_tool_call_groups(messages: list[dict[str, Any]]) -> list[tuple[int, int]]`: Return list of `(start_idx, end_idx)` spans representing atomic call-and-response clusters.
       - `align_boundary_forward(messages: list[dict[str, Any]], cut_idx: int) -> int`: If `cut_idx` falls inside any tool call group, advance `cut_idx` to `group.end_idx + 1` so all matching tool results are included in the prior segment.
       - `align_boundary_backward(messages: list[dict[str, Any]], cut_idx: int) -> int`: If `cut_idx` falls inside any tool call group, retreat `cut_idx` to `group.start_idx` so the assistant call and its responses remain together in the subsequent segment.
    3. Add validation helper `validate_atomic_boundaries(messages: list[dict[str, Any]]) -> bool`:
       - Confirms no orphaned `role: "tool"` exists without its preceding assistant `tool_calls`.
       - Confirms no assistant with `tool_calls` is severed from its tool responses.
    AVOID: Allowing any compaction cut index to split an assistant's tool calls from their results, because Anthropic, OpenAI, and Gemini APIs return immediate HTTP 400 Bad Request when tool pairs are severed.
  </action>
  <verify>
    .venv/bin/python -c "from harness_core.context_compressor import align_boundary_forward, align_boundary_backward, validate_atomic_boundaries; msgs = [{'role': 'user', 'content': 'hi'}, {'role': 'assistant', 'content': '', 'tool_calls': [{'id': 'call_1', 'function': {'name': 'test'}}]}, {'role': 'tool', 'tool_call_id': 'call_1', 'content': 'ok'}, {'role': 'user', 'content': 'next'}]; assert align_boundary_forward(msgs, 2) == 3; assert align_boundary_backward(msgs, 2) == 1; print('Phase 2 Atomic Alignment verified')"
  </verify>
  <done>
    `align_boundary_forward` and `align_boundary_backward` strictly prevent tool-call and tool-result pairs from being severed, verified across both single and parallel tool calls.
  </done>
</task>
