# Plan 16.02: Tool Gateway Registration, Autonomous Repair Pre-Flight Interceptor & CLI/TUI Ergonomics

<objective>
Expose Language Server Protocol (LSP) capabilities through `ToolGateway` as read-only R1 tools (`lsp_diagnostics`, `lsp_definition`, `lsp_references`, `lsp_hover`), intercept syntax and compiler errors before slow test suite execution via a compiler pre-flight gate in the autonomous repair loop, and deliver complete CLI (`hex lsp`) and TUI (`/lsp`) ergonomics.

Purpose: Accelerate autonomous repair cycles by failing fast on compiler errors, while providing operators and coding agents with precision IDE navigation and diagnostic telemetry.
Output: Integrated `ToolGateway` LSP tools, pre-flight compiler gate in `HarnessOrchestrator`, `hex lsp` CLI subcommand, `/lsp` TUI slash command, and complete integration test suite in `tests/test_lsp_gateway_and_repair.py`.
</objective>

  <name>Register Read-Only LSP Tools in ToolGateway</name>
  <files>src/harness_core/gateway.py</files>
  <action>
    In `src/harness_core/gateway.py`:
    1. Import `LSPManager` from `harness_core.lsp.manager`.
    2. Update `ToolGateway.__init__`:
       - Accept optional `lsp_manager: LSPManager | None = None`. If not provided, lazily initialize with the workspace directory upon first LSP tool invocation.
    3. Implement and register 4 read-only R1 tools in `_register_builtin_tools()`:
       - `lsp_diagnostics`:
         - Description: "Query compiler syntax errors, type mismatches, and linter warnings from active language servers across workspace or specific file (R1)."
         - Risk class: `RiskClass.R1` (eligible for Fast-Path and 0ms memoization).
         - Arguments: `file_path` (optional str), `severity` (optional str: "error", "warning", "all", default "all").
         - Handler: queries `self.lsp_manager.get_diagnostics(file_path=file_path, severity=severity)` and returns structured JSON list:
           `{"diagnostics": [...], "error_count": int, "warning_count": int, "total_count": int}`.
       - `lsp_definition`:
         - Description: "Find symbol definition URI, line, and column coordinates using language server (R1)."
         - Risk class: `RiskClass.R1`.
         - Arguments: `file_path` (str), `line` (int 1-based), `character` (int 1-based).
         - Handler: queries `self.lsp_manager.get_definition(file_path, line, character)` and returns `{"definitions": [{"file": ..., "line": ..., "character": ...}]}`.
       - `lsp_references`:
         - Description: "Find all reference locations and call sites for a symbol across the workspace (R1)."
         - Risk class: `RiskClass.R1`.
         - Arguments: `file_path` (str), `line` (int 1-based), `character` (int 1-based), `include_declaration` (bool, default True).
         - Handler: queries `self.lsp_manager.get_references(file_path, line, character, include_declaration)` and returns `{"references": [...]}`.
       - `lsp_hover`:
         - Description: "Retrieve type signatures and markdown docstrings for a symbol at coordinates (R1)."
         - Risk class: `RiskClass.R1`.
         - Arguments: `file_path` (str), `line` (int 1-based), `character` (int 1-based).
         - Handler: queries `self.lsp_manager.get_hover(file_path, line, character)` and returns `{"hover": {"contents": str}}`.
    4. Ensure graceful degradation:
       - If no language server is available or installed for the target file's language, return clean fallback response `{"status": "no_server_available", "language": ..., "diagnostics": []}` rather than raising uncaught exceptions.

    AVOID: Modifying workspace files or triggering destructive actions in LSP inspection tools; keep all LSP tools strictly read-only (`RiskClass.R1`).
  </action>

<task type="auto">
  <name>Integrate Pre-Flight Compiler Diagnostic Interceptor into Autonomous Repair Loop</name>
  <files>src/harness_core/orchestrator.py</files>
  <action>
    In `src/harness_core/orchestrator.py`:
    1. Initialize `self.lsp_manager = LSPManager(self.default_workspace)` in `HarnessOrchestrator.__init__` and pass to `ToolGateway`.
    2. Implement `_run_compiler_preflight(attempt_ws: Path, modified_files: list[str]) -> dict[str, Any]`:
       - For each file in `modified_files`:
         - Resolve relative to `attempt_ws`. If file does not exist or language server not available, skip.
         - Sync document with LSP client via `did_open` or `did_change` with current file content.
       - Poll `self.lsp_manager.get_diagnostics(severity="error")` for the modified files with a bounded timeout (up to 1.5s).
       - If any compiler/syntax errors (severity=1) are found:
         - Format errors into readable diagnostic summaries:
           `[file:line:col] [ERROR] code: message`
         - Return `{"passed": False, "error_count": len(errors), "errors": errors, "summary": formatted_summary}`.
       - If no errors found or language servers unavailable, return `{"passed": True, "error_count": 0, "errors": []}`.
    3. Integrate pre-flight gate into `_execute_standard_dag`:
       - In the verification cycle (after DAG step execution and after each repair patch application, BEFORE running slow test suites in `run_verification_and_build_proof`):
       - Execute `preflight = self._run_compiler_preflight(attempt_ws, modified_files)`.
       - If `not preflight["passed"]`:
         - Record hash-chained task event `LSP_COMPILER_PREFLIGHT_FAILED` in `LedgerStore` with failure details (`error_count`, `errors`).
         - Synthesize compiler diagnostic message directly into `failure_digest`:
           `f"Compiler Diagnostic Pre-Flight Failed ({preflight['error_count']} compiler/syntax error(s)):\n{preflight['summary']}"`
         - Short-circuit verification: set `ver_outcome = {"passed": False, "verification_results": {"test_output_excerpt": failure_digest, "compiler_preflight": preflight}}`.
         - Immediately feed this digest into `generate_repair_patch` for the next repair attempt, saving minutes of failed test execution time.
       - If pre-flight passes, proceed to standard test verification.

    AVOID: Blocking or failing the repair loop if language servers are not installed on the system; the pre-flight gate must seamlessly pass-through when no server binary exists.
  </action>
  <verify>python -c "from harness_core.orchestrator import HarnessOrchestrator; orch = HarnessOrchestrator(':memory:'); print(hasattr(orch, '_run_compiler_preflight'))"</verify>
  <done>Pre-flight compiler diagnostic gate is integrated into `_execute_standard_dag`, catching syntax and compiler errors before test runner invocation and logging `LSP_COMPILER_PREFLIGHT_FAILED` events.</done>
</task>
