<task type="auto">
  <name>Implement System Diagnostics Suite (HexDoctor), Auto-Remediation (--fix), Live Model Ping (--live) & hex doctor CLI</name>
  <files>src/harness_core/doctor.py, src/harness_core/cli.py</files>
  <action>
    Create `src/harness_core/doctor.py`:
    1. Dataclasses:
       - `DoctorCheckResult`:
         - `name: str` (e.g. "Python Version", "M4 Acceleration", "APFS CoW Support", "Bubblewrap Sandbox")
         - `category: str` ("python", "hardware", "cow", "sandbox", "credentials", "git", "storage", "directories")
         - `status: str` ("ok" | "warning" | "error" | "fixed")
         - `message: str` (descriptive message)
         - `remediation: str | None = None` (actionable guidance)
         - `fixable: bool = False` (whether --fix can resolve it)
       - `DoctorReport`:
         - `checks: list[DoctorCheckResult]`
         - `passed: int`
         - `warnings: int`
         - `errors: int`
         - `fixed: int`
         - `is_healthy: bool` (true if errors == 0)
         - `to_dict() -> dict[str, Any]`
         - `format_summary(color: bool = True) -> str`: produces human-readable diagnostic report with category grouping, check marks, and remediation hints.
    2. `HexDoctor`:
       - `__init__(self, workspace_root: Path | str | None = None, data_dir: Path | str | None = None)`:
         - Initializes paths, resolving `.hex/` and data directories.
       - Diagnostic check methods:
         - `check_python() -> list[DoctorCheckResult]`: checks Python version >= 3.10, virtual environment activation, critical dependencies (`pydantic`, `rich`, `alembic`, `asyncpg` optional).
         - `check_hardware_acceleration() -> list[DoctorCheckResult]`: detects Darwin arm64, Apple Silicon chip family (M1/M2/M3/M4 via `sysctl -n machdep.cpu.brand_string` or `platform.processor()`), `mlx` and `mlx_lm` package availability, Metal support. On Linux/other, checks CUDA/MPS/CPU status.
         - `check_cow_providers() -> list[DoctorCheckResult]`: inspects active CoW provider via `get_default_snapshot_provider()`, tests `cp -c` on APFS, or OverlayFS / Btrfs capability on Linux.
         - `check_sandboxes() -> list[DoctorCheckResult]`: inspects default sandbox via `get_default_sandbox()`, checks availability of `bwrap`, `docker`, `podman`, and confirms fallback restricted subprocess sandbox.
         - `check_credentials() -> list[DoctorCheckResult]`: checks presence of API tokens (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, Antigravity credentials in `~/.hex/antigravity_auth.json`). Does not expose secrets in output.
         - `check_git() -> list[DoctorCheckResult]`: checks `git` binary availability, whether current directory is inside a git worktree, and whether repository is clean or dirty.
         - `check_storage() -> list[DoctorCheckResult]`: checks available disk space in workspace and data directory (warns if < 2GB free).
         - `check_directories_and_config() -> list[DoctorCheckResult]`: checks existence and permissions of `.hex/`, `.hex/data/`, `skills/custom/`, `.hex/quarantine/`, and readability of `.hex/config.yaml`. Marks missing directories and missing config as `fixable=True`.
       - Remediation method:
         - `apply_fixes(checks: list[DoctorCheckResult]) -> list[DoctorCheckResult]`:
           - For fixable issues: auto-creates missing `.hex/`, `.hex/data/`, `skills/custom/`, `.hex/quarantine/`.
           - Generates minimal default `.hex/config.yaml` if missing.
           - Ensures standard user permissions (`0o755`).
           - Marks resolved checks as status `fixed`.
       - Live check method:
         - `run_live_pings() -> list[DoctorCheckResult]`:
           - Bounded, read-only external API ping test (timeout: 3.0s). Tests configured cloud model provider or Antigravity endpoint. If credentials missing, returns informational skip.
       - Main runner:
         - `run_diagnostics(fix: bool = False, live: bool = False) -> DoctorReport`:
           - Runs all diagnostic checks.
           - If `fix` is True, executes `apply_fixes` for any fixable failures and re-checks.
           - If `live` is True, executes `run_live_pings`.
           - Returns consolidated `DoctorReport`.

    3. Wire `hex doctor` CLI subcommand in `src/harness_core/cli.py`:
       - Subcommand: `hex doctor`
       - Arguments:
         - `--fix`: Automatically resolve fixable diagnostic issues (directories, config, permissions).
         - `--live`: Perform live read-only model API connectivity ping.
         - `--json`: Output raw JSON report instead of formatted text.
         - `--workspace`: Custom workspace root.
       - Dispatches to `HexDoctor(workspace_root=args.workspace, data_dir=args.data_dir).run_diagnostics(fix=args.fix, live=args.live)`.
       - Exits 0 if healthy (errors == 0), exits 1 if errors remain.
  </action>
  <verify>

  </verify>
  <done>
    `HexDoctor` correctly diagnoses Python runtime, M4/GPU hardware, CoW providers, sandboxes, credentials, git, storage, and directory health. Supports `--fix` for self-healing and `--live` for connectivity pings. CLI subcommand `hex doctor` is registered and functional.
  </done>

<task type="auto">
  <name>Implement Multi-Framework Recipe Detector & Wire into ToolGateway and HarnessOrchestrator</name>
  <files>src/harness_core/recipes.py, src/harness_core/gateway.py, src/harness_core/orchestrator.py, src/harness_core/cli.py</files>
  <action>
    1. Create `src/harness_core/recipes.py`:
       - Dataclass `Recipe`:
         - `name: str` (e.g. "Python (pytest)", "Python (uv pytest)", "Node.js (pnpm)", "Rust (cargo)", "Go (go test)")
         - `kind: str` ("python" | "nodejs" | "rust" | "go" | "makefile" | "docker")
         - `bootstrap: str | None = None` (e.g. "uv pip install -e .", "pnpm install", "cargo build")
         - `build: str | None = None` (e.g. "npm run build", "cargo build", "go build ./...")
         - `test: str` (e.g. "pytest", "npm test", "cargo test", "go test ./...")
         - `test_cmd_args: list[str]` (tokenized command list suitable for subprocess/sandbox execution, e.g. `["pytest"]` or `["npm", "test"]`)
         - `start: str | None = None` (e.g. "npm start", "python -m uvicorn app:main")
         - `port: int | None = None` (e.g. 3000, 8000)
         - `evidence: list[str] = field(default_factory=list)` (marker files detected, e.g. `["package.json", "pnpm-lock.yaml"]`)
         - `to_dict() -> dict[str, Any]`
       - Function `detect_recipe(root: Path | str) -> Recipe | None`:
         - Checks markers in strict precedence:
           a. **Node.js**:
              - Markers: `package.json`, plus lockfiles (`pnpm-lock.yaml` -> pnpm, `yarn.lock` -> yarn, `bun.lockb` -> bun, `package-lock.json` -> npm).
              - Inspects `package.json` JSON: reads `scripts.test`, `scripts.build`, `scripts.start`.
              - Detects framework: Next.js (port 3000), Vite (port 5173), Express/Nest (port 3000/8000).
              - Sets `test_cmd_args` to `[pm, "test"]` or `[pm, "run", "test"]`.
           b. **Python**:
              - Markers: `uv.lock` -> `["uv", "run", "pytest"]`, `poetry.lock` -> `["poetry", "run", "pytest"]`, `Pipfile` -> `["pipenv", "run", "pytest"]`, `pyproject.toml`, `requirements.txt`, `setup.py`, `pytest.ini`.
              - Framework detection: Django (`manage.py` -> `["python", "manage.py", "test"]`), FastAPI/Uvicorn, pytest vs unittest.
              - Default python test fallback: `["pytest"]` if `pytest.ini` or `test_*.py` exists, else `[sys.executable, "-m", "unittest"]`.
           c. **Rust**:
              - Marker: `Cargo.toml`.
              - Commands: bootstrap="cargo build", build="cargo build", test="cargo test", `test_cmd_args=["cargo", "test"]`.
           d. **Go**:
              - Marker: `go.mod`.
              - Commands: bootstrap="go mod download", build="go build ./...", test="go test ./...", `test_cmd_args=["go", "test", "./..."]`.
           e. **Makefile**:
              - Marker: `Makefile` or `makefile`.
              - Inspects Makefile content: if `test:` target exists, sets test="make test", `test_cmd_args=["make", "test"]`.
           f. **Docker Compose**:
              - Marker: `docker-compose.yml` or `compose.yaml`.
              - Commands: start="docker compose up -d", test="docker compose run --rm test".
         - Returns `Recipe` instance if detected, or `None` if directory has no recognizable build/test markers.

    2. Wire recipe detection into `ToolGateway._tool_run_tests` (`src/harness_core/gateway.py`):
       - If `args.get("command")` is explicitly passed, use it.
       - If `args.get("targets")` is provided:
         - If targets specified, append to detected or default test command.
       - If neither explicit command nor targets provided:
         - Call `detect_recipe(workspace_dir)`.
         - If recipe detected, use `recipe.test_cmd_args`.
         - If no recipe detected, fall back to default unittest discovery `[sys.executable, "-m", "unittest", "discover", "-s", ".", "-p", "test_*.py"]`.
       - Record detected recipe name in the tool execution result metadata (`result["recipe"] = recipe.name if recipe else None`).

    3. Wire into `HarnessOrchestrator` (`src/harness_core/orchestrator.py`):
       - In `_execute_standard_dag` and task execution initialization, detect workspace recipe via `detect_recipe(workspace_dir)`.
       - Inject detected recipe name and test command into `task.context["recipe"]` and verification plan metadata so reasoner and repair loop know the exact test runner.

    4. Add `hex recipe [workspace]` subcommand in `src/harness_core/cli.py`:
       - Shows detected recipe, kind, bootstrap, build, test, and start commands, with evidence markers.
  </action>
  <verify>
    <command>python3 -c "from harness_core.recipes import detect_recipe; r = detect_recipe('.'); assert r is not None; print('Detected repository recipe:', r.name, '| Test command:', r.test)" && python3 -m harness_core.cli recipe --help</command>
  </verify>
  <done>
    `detect_recipe` accurately discovers project recipes across Python, Node.js, Rust, Go, Makefile, and Docker. `ToolGateway` and `HarnessOrchestrator` automatically use the detected test command when none is explicitly provided. CLI subcommand `hex recipe` is functional.
  </done>

  <name>Implement Graphify Incremental Disk Cache & Multi-Language Symbol Extraction (Python, TS/JS, Rust, Go) with Comprehensive Test Suite</name>
  <files>src/harness_core/graphify.py, tests/test_doctor_and_recipes.py</files>
  <action>
    1. Enhance `src/harness_core/graphify.py`:
       - Persistent Disk Caching:
         - Add cache file management targeting `.hex/graph.json` (or `workspace_root / ".hex" / "graph.json"`).
         - Cache format:
           ```json
           {
             "version": 1,
             "created_at": "...",
             "workspace_root": "...",
             "files": {
               "src/module.py": {
                 "mtime": 1730000000.0,
                 "sha256": "...",
                 "symbols": [...]
               }
             }
           }
           ```
         - In `ActiveGraphifyAdapter.build_or_refresh()`:
           - Load existing cache if present and version matches.
           - For each file in workspace matching supported extensions (`.py`, `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.rs`, `.go`):
             - Check `os.stat().st_mtime`. If mtime matches cached entry, reuse cached `SymbolDef` instances without file re-reading or re-parsing.
             - If mtime differs or entry missing, compute SHA-256 and parse file.
           - Remove deleted files from cache.
           - Save updated cache atomically to `.hex/graph.json` using temp file + `os.replace`.
           - Cold start takes standard time; warm startup executes in < 30ms.
       - Multi-Language Symbol Extraction:
         - Support file extensions:
           - Python: `.py` (via `ast.parse` as before)
           - JavaScript/TypeScript: `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`
             - Extract functions (`function name(...)`, `const/let name = (...) => ...`, `async function name(...)`), classes (`class Name extends Base`), imports (`import { ... } from '...'`), calls (`name(...)`).
           - Rust: `.rs`
             - Extract `fn name(...)`, `pub fn name(...)`, `struct Name`, `enum Name`, `impl Name`, `impl Trait for Struct`, `mod name`, calls.
           - Go: `.go`
             - Extract `func Name(...)`, `func (r *Receiver) Method(...)`, `type Name struct/interface`, imports, calls.
         - Ensure clean qualified names (e.g. `src/utils.ts:calculateTotal`, `src/lib.rs:process_event`).
         - Ensure reverse caller index (`callers_of`) and NetworkX graph (when available) correctly link cross-file calls for polyglot repositories.

       - `test_recipes_nodejs_detection`: tests detection of `package.json` with npm, pnpm, and yarn lockfiles.
