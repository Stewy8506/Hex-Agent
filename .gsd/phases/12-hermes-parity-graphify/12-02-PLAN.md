  <name>Implement SQLite FTS5 Full-Text Search Virtual Table, BM25 Ranking, LedgerStore Sync & hex search CLI</name>
  <files>src/harness_core/search.py, src/harness_core/db.py, src/harness_core/cli.py</files>
  <action>
    1. Create `src/harness_core/search.py`:
       - Query sanitization function `sanitize_fts5_query(query: str) -> str`:
         - Cleans query against FTS5 special operators and punctuation (`"`, `*`, `^`, `:`, `{`, `}`, `(`, `)`, `+`, `-`, `OR`, `AND`, `NOT`, `/`, `\`, `~`).
         - Normalizes tokens to prevent syntax errors on arbitrary operator strings.
         - Supports prefix wildcard matching on individual search tokens (e.g. `auth*` for words beginning with "auth").
       - Dataclasses:
         - `TaskSearchResult`:
           - `task_id: str`
           - `project_id: str`
           - `goal: str`
           - `status: str`
           - `snippet: str` (highlighted match snippet)
           - `score: float` (BM25 relevance score)
           - `matched_field: str` ("goal" | "tool_calls" | "execution_logs")
           - `to_dict() -> dict[str, Any]`
       - Class `TaskSearchIndex`:
         - `__init__(self, db_path: Path | str | sqlite3.Connection)`:
           - Opens or attaches SQLite connection.
           - Initializes virtual table:
             ```sql
             CREATE VIRTUAL TABLE IF NOT EXISTS task_search_fts USING fts5(
                 task_id UNINDEXED,
                 project_id UNINDEXED,
                 status UNINDEXED,
                 goal,
                 tool_calls,
                 execution_logs,
                 tokenize = 'unicode61 remove_diacritics 2'
             );
             ```
             (Includes fallback to default tokenizer if specific options are unsupported on certain platforms).
         - `index_task(task_id: str, project_id: str, goal: str, status: str, tool_calls_text: str = "", logs_text: str = "") -> None`:
           - Deletes existing entry for `task_id` if present, then inserts current task goal, tool calls, and logs text.
         - `append_tool_call(task_id: str, tool_name: str, args_text: str, result_text: str) -> None`:
           - Updates `tool_calls` column for the given `task_id`, appending the latest tool call transcript.
         - `search(query: str, project_id: str | None = None, limit: int = 20) -> list[TaskSearchResult]`:
           - Sanitizes input query via `sanitize_fts5_query`.
           - Queries `task_search_fts` using `bm25(task_search_fts)` and `snippet(task_search_fts, -1, '<b>', '</b>', '...', 16)`.
           - Filters by `project_id` if specified.
           - Returns ranked `list[TaskSearchResult]`.
         - `reindex_all(ledger: LedgerStore) -> int`:
           - Clears `task_search_fts` and iterates over tasks in `ledger`, indexing goal, status, tool calls, and event logs. Returns total indexed tasks.

    2. Integrate search into `LedgerStore` (`src/harness_core/db.py`):
       - Lazily initialize or attach `TaskSearchIndex` to `LedgerStore`.
       - On `create_task`: automatically call `search_index.index_task(...)`.
       - On `transition_task`: update status in `search_index`.
       - On `seal_tool_call`: call `search_index.append_tool_call(...)`.
       - Add `search_tasks(query: str, project_id: str | None = None, limit: int = 20) -> list[dict[str, Any]]` helper method to `LedgerStore`.

    3. Wire `hex search` CLI subcommand in `src/harness_core/cli.py`:
       - Subcommand: `hex search <query>`
       - Arguments:
         - `query`: Search terms or pattern.
         - `--project`: Optional project filter.
         - `--limit`: Max results (default: 20).
         - `--reindex`: Trigger full reindex from ledger before searching.
         - `--json`: Output raw JSON list of search results.
       - Outputs formatted results table with task ID, status badge, relevance score, and highlighted match snippets.
  </action>

<task type="auto">
  <name>Implement State Backup, Safe Restore with Zip-Slip Defense & Plain-Text Support Dump</name>
  <files>src/harness_core/backup.py, src/harness_core/cli.py</files>
  <action>
    1. Create `src/harness_core/backup.py`:
       - Function `create_backup(output_path: Path | str | None = None, data_dir: Path | str | None = None, workspace_root: Path | str | None = None, quick: bool = False) -> dict[str, Any]`:
         - Resolves `.hex` configuration directory, data directory, and workspace root.
         - Collects critical assets to archive:
           - Configuration files: `config.yaml`, `.hex/config.yaml`.
           - Database files: `hex.db`, `harness.db` (executes `PRAGMA wal_checkpoint(TRUNCATE)` before reading if SQLite database is active).
           - Cron schedules: `schedules.json`.
           - Custom skills: `skills/custom/` and `.hex/skills/`.
           - Quarantined items: `.hex/quarantine/`.
           - Anthropic/Antigravity local metadata (excluding plain API keys if configured).
         - Explicit exclusion filter:
           - Excludes: `.hex/cow_workspaces/`, `.hex/cache/`, virtualenvs (`.venv/`, `env/`, `venv/`), `__pycache__`, `.git`, socket files, lock files, and large binary artifacts (> 50MB).
           - If `quick=True`, archives only database files and config files.
         - Generates timestamped zip archive: `hex-backup-<YYYYMMDD-HHMMSS>.zip` (default path: current working directory or `data_dir / "backups"`).
         - Calculates SHA-256 hash of generated zip file.
         - Returns summary dictionary: `{"backup_path": str(zip_path), "files_archived": count, "size_bytes": size, "sha256": hash_str, "quick": quick}`.

       - Function `restore_backup(archive_path: Path | str, target_dir: Path | str, dry_run: bool = False) -> dict[str, Any]`:
         - Validates that `archive_path` exists and is a valid zip archive.
         - **Strict Zip-Slip Path Traversal Protection**:
           - Checks every `ZipInfo` filename in archive:
             - Rejects filenames starting with `/` or containing `..` path traversals.
             - Resolves destination path `(target_dir / member.filename).resolve()`.
             - Asserts destination path starts with `target_dir.resolve()`. If not, raises `SecurityViolationError` or `ValueError("Zip-slip path traversal attempt detected")`.
         - If `dry_run=True`: returns list of files that would be restored without writing to disk.
         - If `dry_run=False`: extracts files into `target_dir`, restoring configuration, database, schedules, and skills.
         - Returns restored summary: `{"target_dir": str(target_dir), "restored_files": list_of_rel_paths, "dry_run": dry_run}`.

       - Function `generate_dump(data_dir: Path | str | None = None, workspace_root: Path | str | None = None) -> str`:
         - Generates clean, uncolored, deterministic plain-text system diagnostic profile designed for pasting into support tickets or GitHub issues.
         - Integrates `HexDoctor` diagnostics and `LedgerStore` metrics.
         - Output sections:
           1. **HEADER & SYSTEM INFO**: OS, kernel release, Python version, platform architecture, timestamp.
           2. **HARDWARE & ACCELERATION**: CPU model, Apple Silicon chip family (M1/M2/M3/M4), Unified Memory, MLX availability, GPU/Metal status.
           3. **STORAGE & LEDGER METRICS**: Storage path, DB engine (SQLite WAL / PostgreSQL), database file size, total task count, total tool call count, completed vs failed task breakdown.
           4. **WORKSPACE & COW ISOLATION**: Snapshot provider in use (APFS, OverlayFS, Btrfs), sandbox backend (Bubblewrap, Docker, Subprocess), free disk space.
           5. **ACTIVE INTEGRATIONS & RECEPTORS**: Configured model providers (redacted: e.g. `OPENAI_API_KEY: [CONFIGURED - REDACTED]`), Antigravity status, Webhook notifier destinations.
           6. **SCHEDULES & CUSTOM SKILLS**: Scheduled jobs list (cron expressions + goals), registered custom skills list.
           7. **RECENT ERRORS**: Plain-text summary of the last 5 failed tasks (task ID, goal, error message, terminal reason).

    2. Wire CLI subcommands into `src/harness_core/cli.py`:
       - `hex backup`:
         - `--output`: Custom zip file destination.
         - `--quick`: Quick backup (db + config only).
         - Prints backup path, file count, and SHA-256.
       - `hex restore <archive>`:
         - `archive`: Path to zip archive.
         - `--target`: Destination directory (defaults to current data dir).
         - `--dry-run`: Inspect archive contents without extracting.
         - Prints restored file count and confirmation.
       - `hex dump`:
         - `--output`: Optional file path to save plain-text dump (defaults to stdout).
         - Prints diagnostic summary.
  </action>
  <verify>
    <command>python3 -c "from harness_core.backup import generate_dump; d = generate_dump(); assert 'SYSTEM INFO' in d and 'STORAGE' in d; print('Diagnostic dump generated successfully (length:', len(d), 'chars)')" && python3 -m harness_core.cli backup --help && python3 -m harness_core.cli restore --help && python3 -m harness_core.cli dump --help</command>
  </verify>
  <done>
    `create_backup` bundles configuration, ledger, skills, and schedules into a timestamped zip archive while excluding transient files. `restore_backup` extracts archives with strict zip-slip defense. `generate_dump` outputs clean plain-text diagnostic profiles with secret redaction. CLI subcommands `hex backup`, `hex restore`, and `hex dump` are functional.
