# Plan 09.01: Telegram Bidirectional Bot Gateway & Interactive Callback Engine

<objective>
Implement the Telegram Bidirectional Bot Gateway (`src/harness_core/gateways/telegram_bot.py`) and package the `src/harness_core/gateways` module. Build `TelegramBotGateway` with support for long-polling (`getUpdates`) and webhook receiver updates, strict operator whitelist access control (`allowed_user_ids`, `allowed_chat_ids`) with security audit logging, conversational task delegation and slash command routing (`/start`, `/help`, `/task <goal>`, `/status [id]`, `/cancel [id]`, `/diff [id]`), and an interactive inline keyboard callback handler (`approve:<id>`, `reject:<id>`, `diff:<id>`, `cancel:<id>`) that edits messages in-place, records decisions in `LedgerStore`, and automatically resumes or cancels tasks in `HarnessOrchestrator`. Author a comprehensive unit and integration test suite in `tests/test_telegram_gateway.py`.

Purpose: Deliver the Telegram half of Pillar 3 (Bidirectional Multi-Platform Chat Gateways), empowering operators to converse with HEX, submit coding tasks, review workspace diffs, and decide gated R3/R4 approvals from Telegram on mobile.
Output: `src/harness_core/gateways/__init__.py`, `src/harness_core/gateways/telegram_bot.py`, and `tests/test_telegram_gateway.py`.
</objective>

  <name>Implement Core Telegram Bot Gateway Runner, Whitelisting & Transport Layer</name>
  <files>src/harness_core/gateways/__init__.py, src/harness_core/gateways/telegram_bot.py</files>
  <action>
    Create `src/harness_core/gateways/__init__.py` and `src/harness_core/gateways/telegram_bot.py`:
    1. Module package:
       - Create `src/harness_core/gateways/__init__.py` exporting `TelegramBotGateway`, `TelegramConfig`.
    2. Configuration dataclass `TelegramConfig`:
       - `bot_token: str | None = None`
       - `allowed_user_ids: set[str | int] = field(default_factory=set)`
       - `allowed_chat_ids: set[str | int] = field(default_factory=set)`
       - `poll_interval: float = 1.0`
       - `poll_timeout: int = 30`
       - `webhook_url: str | None = None`
       - `dry_run: bool = False`
       - `from_env() -> TelegramConfig`: parses `HEX_TELEGRAM_BOT_TOKEN` / `HARNESS_TELEGRAM_BOT_TOKEN`, comma-separated `HEX_TELEGRAM_ALLOWED_USERS` / `HARNESS_TELEGRAM_ALLOWED_USERS`, comma-separated `HEX_TELEGRAM_ALLOWED_CHATS` / `HARNESS_TELEGRAM_ALLOWED_CHATS`, `HEX_TELEGRAM_POLL_INTERVAL`, etc.
    3. Transport abstraction:
       - `TelegramTransport` protocol:
         - `call_api(method: str, payload: dict[str, Any] | None = None, timeout: float = 30.0) -> dict[str, Any]`
       - `HttpTelegramTransport(bot_token: str, base_api_url: str = "https://api.telegram.org")`:
         - Uses `urllib.request.urlopen` with JSON payloads and timeouts.
         - Handles `HTTPError` and network errors gracefully with informative error logging.
       - `MockTelegramTransport`:
         - In-memory mock tracking recorded calls (`sent_messages`, `edited_messages`, `answered_callbacks`, `api_calls`).
         - Configurable mock responses and queue of incoming updates for test polling.
    4. Operator whitelist access control:
       - `is_user_authorized(user_id: str | int | None) -> bool`:
         - If `allowed_user_ids` is non-empty, checks if stringified `user_id` is in `allowed_user_ids`. If `allowed_user_ids` is empty, returns `False` by default (strict default-deny).
       - `is_chat_authorized(chat_id: str | int | None) -> bool`:
         - If `allowed_chat_ids` is non-empty, checks if stringified `chat_id` is in `allowed_chat_ids`.
       - `check_access(user_id: str | int | None, chat_id: str | int | None) -> tuple[bool, str]`:
         - Verifies authorization. If denied, writes security warning log with details (`SECURITY_AUDIT: Dropped unauthorized Telegram update from user=%s chat=%s`) and returns `(False, "Unauthorized operator")`.
    5. Polling and update processing engine:
       - `TelegramBotGateway`:
         - `__init__(self, orchestrator: HarnessOrchestrator | None, config: TelegramConfig, transport: TelegramTransport | None = None)`
         - `poll_once() -> int`: calls `getUpdates` with `offset=self._last_update_id + 1` and `timeout=config.poll_timeout`, dispatches each update, updates `self._last_update_id`, and returns count of updates processed.
         - `start_polling(stop_event: threading.Event | None = None)`: runs continuous polling loop with backoff on errors until stopped.
         - `process_update(update: dict[str, Any]) -> dict[str, Any] | None`: routes `message` updates to `handle_message(message)` and `callback_query` updates to `handle_callback_query(callback_query)`.

    AVOID: Blindly accepting messages without user ID verification. Enforce strict default-deny whitelist checking before any task execution or state mutation.
  </action>

<task type="auto">
  <name>Implement Conversational Task Delegation, Slash Commands & Interactive Callback Engine</name>
  <files>src/harness_core/gateways/telegram_bot.py</files>
  <action>
    Extend `TelegramBotGateway` in `src/harness_core/gateways/telegram_bot.py` with full conversational command dispatch and interactive button callbacks:
    1. Conversational task delegation & slash commands:
       - `handle_message(message: dict[str, Any]) -> dict[str, Any]`:
         - Extracts `user_id = message.get("from", {}).get("id")`, `chat_id = message.get("chat", {}).get("id")`, and `text = message.get("text", "").strip()`.
         - Validates operator access via `check_access(user_id, chat_id)`. If unauthorized, sends polite refusal: `⛔ Unauthorized operator. Access denied.` and returns.
         - Slash commands routing:
           - `/start`, `/help`: sends formatted Markdown guide with available commands (`/task <goal>`, `/status [id]`, `/diff [id]`, `/cancel [id]`, `/help`) and current gateway status.
           - `/task <goal>`: extracts goal text. Submits task via `self.orchestrator.submit_and_run(TaskSubmitRequest(goal=goal, project_id="telegram", workspace_root=str(self.orchestrator.default_workspace)))`. Returns confirmation card with `task_id`, `status`, and goal.
           - Direct text messages not beginning with `/` (e.g. `"Fix memory leak in worker"`): treats text as a task goal, calling task submission and replying with progress alert.
           - `/status [task_id]`:
             - If `task_id` is supplied: queries `self.orchestrator.ledger.get_task(task_id)` and proof bundle. Formats card with state, step, timestamps, and terminal reasons.
             - If no `task_id`: calls `self.orchestrator.ledger.list_tasks(limit=5)` and formats a concise list of recent tasks.
           - `/diff [task_id]`:
             - Looks up task, active attempt workspace, and base checkpoint snapshot.
             - Computes workspace diff using `compute_workspace_diff`.
             - Formats unified diff snippet inside Telegram ````diff ... ```` markdown. If length > 3500 chars, truncates cleanly with indicator.
           - `/cancel [task_id]`:
             - Calls `self.orchestrator.cancel_task(task_id, actor=f"tg:{user_id}")`.
             - Replies confirming task cancellation and CoW rollback.
    2. Interactive inline keyboard approval cards:
       - `send_approval_request(approval_record: dict[str, Any], chat_id: str | int | None = None) -> dict[str, Any]`:
         - Formats approval alert using `_extract_approval_fields(approval_record)` and secret redaction.
         - Attaches Telegram `inline_keyboard` with 4 interactive callback buttons:
           - Row 1: `[✅ Approve]` (callback_data: `approve:<approval_id>`), `[❌ Reject]` (callback_data: `reject:<approval_id>`)
           - Row 2: `[🔍 View Diff]` (callback_data: `diff:<approval_id>`), `[⏹ Cancel Task]` (callback_data: `cancel:<approval_id>`)
         - Sends message via `self.transport.call_api("sendMessage", ...)`.
    3. Interactive callback query handler:
       - `handle_callback_query(callback_query: dict[str, Any]) -> dict[str, Any]`:
         - Extracts `user_id = callback_query.get("from", {}).get("id")`, `data = callback_query.get("data", "")`, `msg = callback_query.get("message", {})`, `chat_id = msg.get("chat", {}).get("id")`, `message_id = msg.get("message_id")`.
         - Validates access via `check_access(user_id, chat_id)`. If unauthorized, answers callback with `⛔ Unauthorized` alert and returns.
         - Parses callback data format `<action>:<target_id>`:
           - `approve:<approval_id>`:
             - Looks up approval record via `self.orchestrator.ledger.get_approval(approval_id)`.
             - Calls `self.orchestrator.ledger.decide_approval(approval_id, "APPROVED", decided_by=f"tg:{user_id}")`.
             - Calls `self.orchestrator.resume_task(rec["task_id"])`.
             - Edits the original message in-place via `editMessageText` removing buttons and appending: `\n\n✅ *APPROVED by @{user_id}* — Task execution resumed.`
             - Acknowledges query with `answerCallbackQuery(text="Approval recorded! Task resumed.")`.
           - `reject:<approval_id>`:
             - Calls `self.orchestrator.ledger.decide_approval(approval_id, "REJECTED", decided_by=f"tg:{user_id}")`.
             - Edits original message in-place via `editMessageText` removing buttons and appending: `\n\n❌ *REJECTED by @{user_id}* — Action rejected.`
             - Acknowledges query with `answerCallbackQuery(text="Action rejected.")`.
           - `diff:<approval_id>`:
             - Looks up approval record and associated task.
             - Computes workspace diff between base checkpoint and attempt workspace.
             - Sends fresh message with diff preview ````diff\n{diff_text}\n````.
             - Acknowledges query with `answerCallbackQuery(text="Displaying workspace diff.")`.
           - `cancel:<approval_id>`:
             - Looks up approval record, calls `self.orchestrator.cancel_task(rec["task_id"], actor=f"tg:{user_id}")`.
             - Edits original message in-place with: `\n\n⏹ *CANCELED by @{user_id}* — Workspace rolled back.`
             - Acknowledges query with `answerCallbackQuery(text="Task canceled.")`.

    AVOID: Modifying message texts without answering the callback query (which causes Telegram clients to show a hanging spinner). Always call `answerCallbackQuery`.
  </action>
