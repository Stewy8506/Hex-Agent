  <name>Implement Discord Interaction Bot Gateway & Interactive Message Components</name>
  <files>src/harness_core/gateways/discord_bot.py, src/harness_core/gateways/__init__.py</files>
  <action>
    Create `src/harness_core/gateways/discord_bot.py` and export symbols in `src/harness_core/gateways/__init__.py`:
    1. Configuration dataclass `DiscordConfig`:
       - `bot_token: str | None = None`
       - `application_id: str | None = None`
       - `public_key: str | None = None`
       - `webhook_url: str | None = None`
       - `allowed_user_ids: set[str] = field(default_factory=set)`
       - `allowed_guild_ids: set[str] = field(default_factory=set)`
       - `allowed_channel_ids: set[str] = field(default_factory=set)`
       - `dry_run: bool = False`
       - `from_env() -> DiscordConfig`: parses `HEX_DISCORD_BOT_TOKEN`, `HEX_DISCORD_APPLICATION_ID`, `HEX_DISCORD_PUBLIC_KEY`, comma-separated `HEX_DISCORD_ALLOWED_USERS`, `HEX_DISCORD_ALLOWED_GUILDS`, etc.
    2. Transport abstraction:
       - `DiscordTransport` protocol:
         - `send_message(channel_id: str, payload: dict[str, Any]) -> dict[str, Any]`
         - `edit_message(channel_id: str, message_id: str, payload: dict[str, Any]) -> dict[str, Any]`
         - `create_interaction_response(interaction_id: str, interaction_token: str, response: dict[str, Any]) -> dict[str, Any]`
       - `HttpDiscordTransport(bot_token: str, base_api_url: str = "https://discord.com/api/v10")`: standard HTTP transport via `urllib.request`.
       - `MockDiscordTransport`: in-memory transport recording sent messages, edits, and responses.
    3. Whitelist access control:
       - `is_user_authorized(user_id: str | None) -> bool`: checks membership in `allowed_user_ids` (default-deny if empty).
       - `is_channel_authorized(channel_id: str | None) -> bool`: checks `allowed_channel_ids` if set.
       - `check_access(user_id: str | None, guild_id: str | None, channel_id: str | None) -> tuple[bool, str]`: verifies permissions and logs `SECURITY_AUDIT: Dropped unauthorized Discord interaction` on failure.
    4. Discord interaction engine (`DiscordBotGateway`):
       - `__init__(self, orchestrator: HarnessOrchestrator | None, config: DiscordConfig, transport: DiscordTransport | None = None)`
       - `handle_interaction(interaction: dict[str, Any]) -> dict[str, Any]`:
         - Type 1: PING -> returns immediate PONG `{"type": 1}`.
         - Type 2: APPLICATION_COMMAND (`/task`, `/status`, `/diff`, `/cancel`, `/help`):
           - Checks user authorization. If unauthorized, returns ephemeral error `⛔ Unauthorized operator.`
           - Command `/task`: extracts `goal` parameter from options, calls `self.orchestrator.submit_and_run(TaskSubmitRequest(goal=goal, project_id="discord"))`. Returns response `{"type": 4, "data": {"content": "Task submitted: ..."}}`.
           - Command `/status`: queries task status or recent tasks. Returns embed status card.
           - Command `/diff`: computes workspace diff and returns code block.
           - Command `/cancel`: calls `cancel_task` with CoW rollback.
           - Command `/help`: returns command descriptions.
         - Type 3: MESSAGE_COMPONENT (button click):
           - Checks user authorization.
           - Parses custom ID:
             - `hex:approve:<approval_id>`: calls `decide_approval(approval_id, "APPROVED", decided_by=f"discord:{user_id}")`, calls `resume_task`, and returns `{"type": 7, "data": ...}` updating the embed color to green (0x00FF00), disabling action buttons, and appending approval audit details.
             - `hex:reject:<approval_id>`: calls `decide_approval(approval_id, "REJECTED", decided_by=f"discord:{user_id}")`, returns `{"type": 7, "data": ...}` updating embed color to red (0xFF0000) and disabling buttons.
             - `hex:diff:<approval_id>`: calculates workspace diff and returns ephemeral message `{"type": 4, "data": {"content": f"```diff\n{diff}\n```", "flags": 64}}`.
             - `hex:cancel:<approval_id>`: calls `cancel_task`, returns `{"type": 7, "data": ...}` updating embed to canceled status.
    5. Outbound interactive approval cards:
       - `send_approval_request(approval_record: dict[str, Any], channel_id: str) -> dict[str, Any]`:
         - Builds rich Discord Embed from `_extract_approval_fields(approval_record)`.
         - Adds ActionRow component (type 1) with 4 Button components (type 2):
           - `[✅ Approve]` (style 3: Success, custom_id: `hex:approve:<id>`)
           - `[❌ Reject]` (style 4: Danger, custom_id: `hex:reject:<id>`)
           - `[🔍 View Diff]` (style 2: Secondary, custom_id: `hex:diff:<id>`)
           - `[⏹ Cancel]` (style 2: Secondary, custom_id: `hex:cancel:<id>`)
         - Sends payload via `transport.send_message(channel_id, payload)`.

    AVOID: Unhandled interaction timeouts. Discord requires an interaction response within 3 seconds; ensure commands return immediate type 4 or type 7 responses.

  <name>Implement Multi-Gateway Supervisor (GatewayManager) & Wire `hex gateway` CLI Subcommand</name>
  <files>src/harness_core/gateways/manager.py, src/harness_core/cli.py, src/harness_core/gateways/__init__.py</files>
  <action>
    Implement `GatewayManager` in `src/harness_core/gateways/manager.py` and register `hex gateway` subcommand in `src/harness_core/cli.py`:
    1. Implement `GatewayManager` in `src/harness_core/gateways/manager.py`:
       - `__init__(self, orchestrator: HarnessOrchestrator, telegram_gateway: TelegramBotGateway | None = None, discord_gateway: DiscordBotGateway | None = None)`:
         - Stores references to orchestrator and configured gateways.
         - Maintains runtime state: `is_running`, `start_time`, `update_counts`, stop event (`threading.Event`).
       - `start(self, daemon: bool = True, poll_interval: float = 1.0) -> None`:
         - If `telegram_gateway` is present, starts its polling loop in a worker thread.
         - If `discord_gateway` is present, registers it in supervisor runtime.
         - Installs signal handlers for `SIGINT` and `SIGTERM` calling `self.stop()`.
         - If `daemon` is False, enters supervisor wait loop monitoring gateway health until stopped.
       - `stop(self, timeout: float = 5.0) -> None`:
         - Signals stop event, shuts down background gateway threads, and logs clean supervisor exit.
       - `get_status(self) -> dict[str, Any]`:
         - Returns structured status:
           - `status`: "running" | "stopped"
           - `uptime_seconds`: elapsed time since `start_time`
           - `gateways`: list of active gateways with name, configured allowed users, and update stats.
           - `orchestrator_tasks`: count of active and queued tasks from ledger.
    2. Wire `hex gateway` CLI subcommand in `src/harness_core/cli.py`:
       - Add `p_gw = sub.add_parser("gateway", help="Manage bidirectional chat gateways (Telegram & Discord)")`:
         - Add subparsers:
           - `p_gw_start = sub_gw.add_parser("start", help="Start bidirectional chat gateway daemon")`:
             - `--telegram`: explicitly enable Telegram gateway (default: enabled if token is set in env).
             - `--discord`: explicitly enable Discord gateway (default: enabled if token is set in env).
             - `--poll-interval`: polling interval in seconds (default: 1.0).
             - `--project`: project ID (default: "default").
             - `--workspace`: workspace path (default: repo root).
             - `--data-dir`: ledger data directory.
           - `p_gw_status = sub_gw.add_parser("status", help="Inspect gateway health and status")`:
             - `--data-dir`: ledger data directory.
       - In `main()` dispatch:
         - Handle `if args.cmd == "gateway":`:
           - If `args.gateway_cmd == "start"`: instantiate `GatewayManager`, wire configured `TelegramBotGateway` and/or `DiscordBotGateway`, and run supervisor.
           - If `args.gateway_cmd == "status"`: inspect and print JSON gateway status.
    3. Export `GatewayManager` in `src/harness_core/gateways/__init__.py`.

    AVOID: Blocking the main thread without catching KeyboardInterrupt. Ensure `GatewayManager.start()` handles `SIGINT` gracefully and allows testing with `--once` or programmatic stops.
  </action>
