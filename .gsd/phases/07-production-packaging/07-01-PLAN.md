# Plan 07.01: Remote Approval Webhooks & Interactive Decision Endpoints

<objective>
Implement remote outbound approval webhooks (Telegram Bot API and Discord Webhooks) in `src/harness_core/webhooks.py` and interactive decision endpoints in `src/harness_core/server.py`. When an R3 or privileged tool call requires human authorization, `ToolGateway` and `HarnessOrchestrator` generate an approval record and trigger `WebhookNotifier` to format and dispatch rich notifications containing task details, risk level, blast-radius summaries, and scrubbed action parameters. Each notification includes direct action URLs (`/v1/approvals/{id}:decide?decision=approve` or `reject`). Enhance `HarnessAPIApp` to support browser clicks via GET/POST with query parameters and styled HTML feedback or JSON responses, automatically resuming approved tasks. Prove complete functionality with unit and integration tests in `tests/test_webhooks.py`.

Purpose: Enable asynchronous, remote mobile/chat operations where harness owners can review and approve or reject privileged R3/R4 actions from Telegram or Discord without needing direct terminal access.
Output: `src/harness_core/webhooks.py`, enhanced `src/harness_core/server.py`, `src/harness_core/gateway.py`, `src/harness_core/orchestrator.py`, and `tests/test_webhooks.py`.
</objective>

  <name>Implement Outbound Webhook Manager with Telegram & Discord Formatters and Secret Scrubbing</name>
  <files>src/harness_core/webhooks.py</files>
  <action>
    Create `src/harness_core/webhooks.py` providing outbound notification capabilities for approval requests and decision broadcasts:
    1. Define configuration:
       - `WebhookConfig` dataclass:
         - `telegram_bot_token: str | None = None`
         - `telegram_chat_id: str | None = None`
         - `discord_webhook_url: str | None = None`
         - `public_base_url: str = "http://127.0.0.1:8420"`
         - `dry_run: bool = False`
         - `timeout: float = 5.0`
         - Class method `from_env()` checking environment variables `HARNESS_TELEGRAM_BOT_TOKEN`, `HARNESS_TELEGRAM_CHAT_ID`, `HARNESS_DISCORD_WEBHOOK_URL`, and `HARNESS_PUBLIC_BASE_URL` (or `HARNESS_BASE_URL`).
    2. Implement formatters:
       - `format_telegram_approval(approval_record: dict[str, Any], base_url: str) -> dict[str, Any]`:
         - Extracts `approval_id`, `task_id`, `step_id`, `action_type`, `action_params`, `blast_radius_summary`, and risk level (e.g. `R3`).
         - Applies `redact_secrets` from `gateway.py` to all `action_params` and summary text.
         - Constructs message text with bold header: `🚨 *Harness Approval Request (R3)*`.
         - Formats clean Markdown/HTML fields for Task ID, Step ID, Tool Name, Risk Class, Blast Radius Summary, and scrubbed JSON arguments snippet (capped to 1,000 chars to avoid exceeding message length limits).
         - Generates action links:
           - Approve: `{base_url}/v1/approvals/{approval_id}:decide?decision=approve`
           - Reject: `{base_url}/v1/approvals/{approval_id}:decide?decision=reject`
         - Supports inline keyboard markup (`inline_keyboard`) with `url` buttons for one-tap approvals from mobile Telegram clients.
         - Returns payload dict for Telegram Bot API `sendMessage`.
       - `format_discord_approval(approval_record: dict[str, Any], base_url: str) -> dict[str, Any]`:
         - Applies `redact_secrets` to all fields.
         - Constructs Discord embed with:
           - Title: `🚨 Approval Required: {tool_name} ({risk_level})`
           - Color: 0xFF9900 (orange for R3) or 0xFF0000 (red for R4).
           - Fields: Task ID, Step ID, Tool Name, Risk Class, Blast Radius Summary, and scrubbed JSON parameters in code block.
           - Description or field containing markdown links: `[✅ Approve]({base_url}/v1/approvals/{apr_id}:decide?decision=approve)  |  [❌ Reject]({base_url}/v1/approvals/{apr_id}:decide?decision=reject)`.
         - Returns payload dict for Discord webhook execution.
       - `format_decision_broadcast(approval_record: dict[str, Any], decision: str, comment: str = "") -> dict[str, Any]` for Telegram and Discord informing channels when a decision has been recorded.
    3. Implement `WebhookNotifier`:
       - `__init__(self, config: WebhookConfig | None = None)`
       - Maintains `sent_payloads: list[dict[str, Any]]` capturing all sent or dry-run messages.
       - `send_approval_request(self, approval_record: dict[str, Any]) -> dict[str, Any]`:
         - Formats payloads for configured targets.
         - If `config.dry_run` is True or target credentials not provided, appends payload to `self.sent_payloads` and returns `{"status": "dry_run"}`.
         - Dispatches HTTP POST requests via standard library `urllib.request.urlopen` with timeout and JSON headers.
         - Catches network/HTTP errors gracefully, logging warnings without crashing the calling workflow.
         - Returns result dict: `{"telegram": ..., "discord": ...}`.
       - `send_decision_broadcast(self, approval_record: dict[str, Any], decision: str, comment: str = "") -> dict[str, Any]`.
  </action>
  <verify>

  </verify>
  <done>
    `WebhookConfig`, `WebhookNotifier`, Telegram and Discord formatters are implemented in `src/harness_core/webhooks.py` with secret scrubbing, dry-run support, and clickable action URLs.
  </done>

  <name>Enhance Interactive Decision Endpoints & Integrate Webhooks into ToolGateway and Orchestrator</name>
  <files>src/harness_core/server.py, src/harness_core/gateway.py, src/harness_core/orchestrator.py</files>
  <action>
    Wire webhook dispatching and enhance the decision endpoint in `server.py`, `gateway.py`, and `orchestrator.py`:
    1. In `src/harness_core/server.py`:
       - Enhance route handler for `/v1/approvals/{approval_id}:decide`:
         - Allow both `GET` and `POST` methods (enabling direct clicks from Telegram/Discord links or browser bookmarks).
         - Parse decision from query string `?decision=...` or JSON body `{"decision": ...}`.
         - Normalize decision strings: "approve", "approved", "allow", "yes" -> "APPROVED"; "reject", "rejected", "deny", "denied", "no" -> "REJECTED".
         - Parse optional comment from `?comment=...` or JSON body `comment`.
         - Invoke `self.orch.ledger.decide_approval(apr_id, norm_decision, comment=comment)`.
         - If decision is `APPROVED` and `auto_resume` is True (default True): call `self.orch.resume_task(decided["task_id"])`.
         - If `self.orch.webhook_notifier`: dispatch `self.orch.webhook_notifier.send_decision_broadcast(decided, norm_decision, comment)`.
         - Response content negotiation:
           - If method is `GET` or `Accept` header contains `text/html`: return `(HTTPStatus.OK, html_page, "text/html; charset=utf-8")` presenting a clean, modern HTML confirmation card displaying decision (green badge for APPROVED, red for REJECTED), task resumption status, approval ID, task ID, timestamp, and a link to return to Dashboard (`/`).
           - If method is `POST` or `Accept` is `application/json`: return `(HTTPStatus.OK, decided, "application/json")`.
    2. In `src/harness_core/gateway.py`:
       - Accept `notifier: WebhookNotifier | None = None` in `ToolGateway.__init__`.
       - In `invoke()`: when `decision == PolicyDecisionType.REQUIRE_APPROVAL`, right after `approval = self.ledger.create_approval(...)`:
         - If `self.notifier`: call `self.notifier.send_approval_request(approval)`.
         - Re-raise `ApprovalRequiredInterrupt(approval)` so orchestrator pauses task and commits checkpoint.
    3. In `src/harness_core/orchestrator.py`:
       - Accept `webhook_notifier: WebhookNotifier | None = None` in `HarnessOrchestrator.__init__`.
       - If not provided, initialize with `WebhookNotifier(WebhookConfig.from_env())`.
       - Pass `self.webhook_notifier` to `ToolGateway(..., notifier=self.webhook_notifier)`.
       - Expose `self.webhook_notifier` for server access.
  </action>
  <verify>

  </verify>
