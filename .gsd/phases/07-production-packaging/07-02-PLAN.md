  <name>Implement Standard Health Checks (/livez, /healthz), Production ASGI Adapter & Graceful Draining</name>
  <files>src/harness_core/server.py, src/harness_core/asgi.py, src/harness_core/cli.py</files>
  <action>
    Enhance `src/harness_core/server.py`, create `src/harness_core/asgi.py`, and update `src/harness_core/cli.py`:
    1. In `src/harness_core/server.py`:
       - Add `self.start_time = time.time()` and `self.is_draining = False` to `HarnessAPIApp.__init__`.
       - Add route `GET /livez`:
         - Lightweight liveness check for container runtimes and process monitors.
         - Returns `(HTTPStatus.OK, {"status": "alive", "uptime_seconds": round(time.time() - self.start_time, 2), "version": "1.0.0"}, "application/json")`.
       - Add route `GET /healthz`:
         - Readiness check verifying whether the instance should receive inbound traffic.
         - If `self.is_draining` is True: returns `(HTTPStatus.SERVICE_UNAVAILABLE, {"status": "draining", "error": "Server is shutting down and draining tasks"}, "application/json")`.
         - Actively probes three key subsystem components:
           1. `database`: Runs a test query on `self.orch.ledger` (e.g. `list_workers()` or lightweight count). If query fails or raises exception, records component status `{"status": "error", "error": str(exc)}`.
           2. `cow_storage`: Verifies `self.orch.data_dir` exists, is accessible directory, and verifies write access by writing and removing a temporary canary file `.health_canary`. If failed, records `{"status": "error", "error": str(exc)}`.
           3. `workers`: Queries `self.orch.ledger.list_workers()`, calculates `total` workers and `healthy` workers (heartbeat within last 300 seconds). Records `{"status": "ok", "total": total, "healthy": healthy}`.
         - If all components OK: returns `(HTTPStatus.OK, {"status": "healthy", "components": components}, "application/json")`.
         - If any critical component (`database` or `cow_storage`) failed: returns `(HTTPStatus.SERVICE_UNAVAILABLE, {"status": "unhealthy", "components": components}, "application/json")`.
    2. Create `src/harness_core/asgi.py`:
       - Define `HarnessASGIAdapter` and callable `app(scope, receive, send)` implementing the ASGI 3.0 specification:
         - Handles `lifespan` scope:
           - On `lifespan.startup`: verifies database connectivity, triggers `lifespan.startup.complete`.
           - On `lifespan.shutdown`: sets `is_draining = True`, allows active requests to complete, triggers `lifespan.shutdown.complete`.
         - Handles `http` scope:
           - Reads incoming request body chunks asynchronously via `receive`.
           - Extracts method, path, query string, and headers from ASGI scope.
           - Calls `self.api_app.handle_request(method, path_with_query, body, headers)`.
           - Sends `http.response.start` with status code and headers.
           - Sends `http.response.body` with payload bytes.
       - Provide factory `get_asgi_app(data_dir=None, auth_token=None) -> HarnessASGIAdapter` and default module-level `app = get_asgi_app()`.
    3. Implement Graceful Shutdown & Signal Handling in `src/harness_core/server.py` and `src/harness_core/cli.py`:
       - Implement `GracefulServerRunner`:
         - Attaches signal handlers for `SIGINT` and `SIGTERM`.
         - On signal:
           1. Sets `app.is_draining = True` so `/healthz` immediately returns 503 to shed load from load balancers.
           2. Waits up to `drain_timeout` (default 5.0 seconds) for running tasks/requests to settle.
           3. Calls `server.shutdown()` and `server.server_close()`.
       - In `src/harness_core/cli.py`:
         - Add `--drain-timeout` (float, default 5.0) and `--asgi` flag to `harness up`.
         - If `--asgi` is passed and `uvicorn` is installed, runs `uvicorn.run(app, host=args.host, port=args.port)`; otherwise runs `run_http_server` with `GracefulServerRunner`.
  </action>

       - Storage: Dual-driver PostgreSQL 16+ connection pool with `SKIP LOCKED` and SQLite WAL local fallback.
       - Isolation & Durability: APFS clones (`cp -c -R`), Linux OverlayFS, Btrfs subvolumes, and sandbox isolation boundaries.
       - Two-Tier Model Pipeline: Tier-1 Local M4 MLX log compressor and Tier-2 Cloud Reasoners.
       - Distributed Workers: Fencing tokens, CAS leases, and CAS CoW delta archive sync.
       - Security Gates: SkillSpector supply-chain scanner, R0-R4 Tool Gateway, and remote Telegram/Discord approval webhooks.

       - CoW snapshot garbage collection: finding orphan attempt workspaces, pruning expired branches, and removing unreferenced CAS `.tar.gz` delta archives without data loss.

       - Inspecting suspicious AST patterns, YARA rule hits, prompt injection patterns, and OSV advisory alerts in `.harness_data/quarantine/`.
       - Remediation procedures: inspecting skill diffs, clearing false positives, or permanently revoking/blacklisting untrusted skill bundles.
    4. Task Cancellation, Stuck Lease Recovery & Zombie Worker Eviction:
       - Emergency cancellation of stuck or runaway tasks via CLI (`harness status <id>`, direct API cancel).
       - Automated lease expiration vs. manual lease reaping (`reap_expired_leases`).

    5. Harness Version Rollback & Database Downgrade:
       - Procedure for rolling back to a previous git tag or commit.
       - Safe execution of forward and backward database migrations with Alembic (`alembic downgrade -1`).
       - Backward compatibility verification for SQLite local profiles.
    6. Production ASGI / Systemd Deployment & Monitoring:
       - Production deployment guide using `uvicorn` behind an Nginx or Caddy reverse proxy.
       - Production `systemd` service unit file (`/etc/systemd/system/harness.service`) with `KillSignal=SIGTERM` and `TimeoutStopSec=30`.
