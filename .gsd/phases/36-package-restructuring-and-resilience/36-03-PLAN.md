# Plan 36.03: Local Server Socket Introspection & OS Keychain Vault

<objective>
Implement live local server socket and model introspection in `models/model_metadata.py` (supporting Ollama `/api/show`, LM Studio `/api/v0/models`, llama.cpp `/props`, and vLLM `/v1/models`) with blackhole sentry protection, and implement the OS Keychain secure credential vault in `storage/vault_keychain.py` with seamless migration from plaintext `~/.hex/config.yaml` and `.hex/credentials.env`.

Purpose: Enable real-time dynamic context window resolution for local inference servers without hardcoding, and elevate credential security from plaintext disk files to native hardware/OS keychains.
Output: Live socket introspection probes in `model_metadata.py`, OS Keychain vault in `vault_keychain.py`, and comprehensive unit tests.
</objective>

       - Implement `probe_local_server(base_url: str, model: Optional[str] = None) -> Optional[dict]`.
       - Cache successful probe results in `_endpoint_model_metadata_cache` with a 300s TTL.
       - Integrate discovered context length into `get_model_context_length(model, base_url=...)`.

    AVOID: Unbounded connection timeouts that freeze TUI or orchestrator startup when offline.
    USE: 1.0s timeout coupled with `_endpoint_blackholed` check on every socket probe.
  </action>

<task type="auto">
  <name>2. Implement OS Keychain Secure Vault and Plaintext Config Migration</name>
  <files>
    storage/vault_keychain.py
    harness_core/vault_keychain.py
    storage/__init__.py
  </files>
  <action>
    Create `storage/vault_keychain.py` (and re-export via `harness_core/vault_keychain.py` stub):
    1. Keyring Integration & OS Backend Auditing:
       - Integrate with standard `keyring` library (`import keyring`).
       - Implement `_is_os_keychain(backend) -> bool`: ensure backend is a genuine OS credential store (macOS Keychain, Linux Secret Service / KWallet, Windows DPAPI / Credential Manager), rejecting insecure stubs (`fail`, `null`, `keyrings.alt`).
       - Define exception `KeychainUnavailable(Exception)`.
       - Implement core API:
         - `is_keychain_available() -> bool`
         - `store_secret(service: str, account: str, secret: str) -> None`
         - `get_secret(service: str, account: str) -> Optional[str]`
         - `delete_secret(service: str, account: str) -> bool`
         - Service name constant: `SERVICE = "HEX Autonomous AI Workbench"`.
    2. Plaintext Credentials Migration:
       - Implement `migrate_plaintext_credentials(config_path: Optional[Path] = None, credentials_path: Optional[Path] = None) -> dict[str, str]`:
         - If `is_keychain_available()` is True:
           - Scan `~/.hex/config.yaml` and `.hex/credentials.env` for API keys (`*_API_KEY`, tokens).
           - Store each detected secret in OS Keychain under account `f"{provider}_api_key"`.
           - Scrub plaintext secrets from the config/env files on disk (writing atomically with `0600` permissions), replacing with keychain markers (`storage: keychain`) or referencing the vault account.
         - If keychain is unavailable (headless container, missing desktop session), leave files intact and log an informational message.

    AVOID: Raising unhandled exceptions on headless Linux servers where no Secret Service daemon runs.
    USE: Graceful detection of OS keychain availability with clean fallback.
  </action>
  <verify>python3 -c "from harness_core.vault_keychain import is_keychain_available, SERVICE; print(f'Keychain available: {is_keychain_available()}, Service: {SERVICE}')"</verify>
  <done>Vault keychain securely manages OS credentials and migrates plaintext config keys seamlessly.</done>
</task>
