<objective>

Purpose: Provide clean separation of concerns across engine subsystems as the codebase scales to Hermes parity and GPUI desktop integration, while avoiding breaking changes for any existing caller.
Output: Domain subpackages under `harness_core/` with forwarding stubs at top level, verified by complete test pass.
</objective>

    Create backward-compatibility forwarding stubs in `harness_core/` for each relocated module:
    1. For every module moved to a subpackage, maintain a top-level stub file (e.g. `harness_core/db.py`) that re-exports all symbols from its domain counterpart:
       ```python
       from harness_core.storage.db import *
       from harness_core.storage.db import __all__  # if defined
       ```
    2. In `harness_core/__init__.py`, expose:
       - Subpackage namespaces: `core`, `storage`, `cognition`, `runtime`, `client`, `capabilities`, `models`.
       - High-frequency root imports: `HarnessOrchestrator`, `LedgerStore`, `TwoTierModelRouter`, `ToolGateway`, `__version__`.
    3. Ensure `python -m harness_core.cli` and `from harness_core.<any_module> import <symbol>` work 100% identically to the pre-refactor state.

    AVOID: Omitting module attributes (`__all__`, `__doc__`, constants) in stub files, which causes wildcard import mismatches and subtle test failures.
    USE: Star re-exports combined with explicit `__all__` pass-through in every top-level stub module.
  </action>
  <verify>python3 -c "from harness_core.db import LedgerStore; from harness_core.orchestrator import HarnessOrchestrator; from harness_core.model_metadata import get_model_context_length; print('Backward-compatibility facade verified')"</verify>
