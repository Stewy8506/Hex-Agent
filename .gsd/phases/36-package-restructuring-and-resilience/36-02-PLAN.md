# Plan 36.02: Multi-Credential Pool & Transient Endpoint Blackholing

<objective>
Implement a resilient `CredentialPool` in `models/` providing multi-key pool management per provider, round-robin / least-utilized routing, automatic rotation on HTTP 429 / quota exhaustion with jittered backoff, model-specific cooldown queues (`(provider, model) -> cooldown_until`), and 30-second transient endpoint blackholing (`_endpoint_blackholed`) to prevent orchestrator thread lockup on dead local or custom servers.

Purpose: Guarantee zero-downtime model dispatch when providers throttle individual keys or models, and eliminate long synchronous connection timeouts when local inference endpoints become unreachable.
Output: `CredentialPool` engine, model cooldowns, endpoint blackhole sentry, and comprehensive unit test suite in `tests/models/test_credential_pool.py`.
</objective>

  <action>
    Create `models/credential_pool.py` (and re-export via `harness_core/credential_pool.py` stub) implementing `CredentialPool`:
    1. Key Management & Ingestion:
       - Ingest multiple API keys per provider from environment variables (e.g. `OPENAI_API_KEY`, `OPENAI_API_KEY_1`, `OPENAI_API_KEY_2`, or comma-separated lists), configuration mappings, or programmatic registration.
       - Track per-credential state: `id`, `provider`, `secret_value`, `status` (`STATUS_OK = "ok"`, `STATUS_EXHAUSTED = "exhausted"`, `STATUS_DEAD = "dead"`), `usage_count`, `last_used_at`, and `cooldown_until`.
    2. Selection Strategies:
       - `STRATEGY_ROUND_ROBIN`: cycle sequentially through available healthy keys.
       - `STRATEGY_LEAST_USED`: pick healthy key with lowest usage counter.
       - `STRATEGY_FILL_FIRST`: prioritize primary key until exhausted.
    3. Failover & Rotation Mechanics:
       - `mark_exhausted(provider, key_id, retry_after=None, reason=None)`: mark key exhausted with jittered backoff (honoring `retry_after` if present, default 60s for sole keys or 3600s for pooled keys).
       - Automatically rotates to next healthy key on exhaustion.
       - `mark_dead(provider, key_id, reason="invalid_token")`: mark key permanently invalid on terminal 401s, excluding it from future rotation.
       - Expired `exhausted` keys automatically recover to `STATUS_OK` upon cooldown expiry.

    AVOID: Sharing state globally without thread locks. Use `threading.Lock` across pool mutations.
    USE: Immutable or dataclass records for credential entries (`CredentialEntry`) with clear state transitions.
  </action>
  <verify>python3 -c "from harness_core.credential_pool import CredentialPool, STATUS_OK, STATUS_EXHAUSTED; pool = CredentialPool(); pool.add_key('openai', 'sk-1'); pool.add_key('openai', 'sk-2'); k = pool.get_key('openai'); assert k.secret_value in ('sk-1', 'sk-2'); print('CredentialPool basic rotation verified')"</verify>
  <done>CredentialPool instantiates, loads multi-keys per provider, and executes round-robin and least-used dispatch.</done>

  <files>

  <action>
    Extend `models/credential_pool.py` with model cooldown queues and transient endpoint blackholing:
    1. Model Cooldown Queues:
       - Track `(provider, model) -> cooldown_until` in `CredentialPool._model_cooldowns`.
       - Method `mark_model_cooldown(provider, model, duration_seconds=60, reason=None)`: marks a specific model as cooling down on 503 or transient overload.
       - Method `is_model_in_cooldown(provider, model) -> bool`: returns True if cooldown timestamp is in the future.
       - Sibling models on the same provider remain healthy and available.
    2. Transient Endpoint Blackholing:
       - Implement endpoint blackhole sentry:
         - `_endpoint_blackhole_cache: dict[str, float] = {}` (storing `host:port -> monotonic_timestamp`).
         - `_ENDPOINT_BLACKHOLE_TTL_SECONDS = 30.0`.
         - `_endpoint_host_key(base_url: str) -> Optional[str]`: parses `hostname:port` from HTTP/HTTPS base URL.
         - `_note_endpoint_blackholed(base_url: str) -> None`: records connect timeout for 30 seconds.
         - `_endpoint_blackholed(base_url: str) -> bool`: returns True if endpoint is within 30s blackhole window; clears stale entries.
         - `_is_connect_timeout(exc: BaseException) -> bool`: detects TCP connect timeouts (`httpx.ConnectTimeout`, `socket.timeout`, `urllib.error.URLError`).
    3. Orchestrator Protection:
       - Before initiating probes or requests to local/custom endpoints (Ollama, LM Studio, vLLM, llama.cpp), check `_endpoint_blackholed(base_url)`. If blackholed, fast-fail or bypass immediately without blocking for 10-30s.

    AVOID: Blackholing on HTTP 4xx/5xx responses; only blackhole on connection-phase timeouts where TCP handshake fails.
    USE: Monotonic time (`time.monotonic()`) for all cooldowns and TTL comparisons to prevent clock skew bugs.
  </action>
