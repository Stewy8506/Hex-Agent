# Plan 18.02: OrchestratorBenchmarkAdapter & Propose-Probe-Compose Rollout Engine

<objective>

  <name>Implement OrchestratorBenchmarkAdapter Conforming to harness2.core.spec.BenchmarkAdapter Protocol</name>
  <files>src/harness_core/harness2_adapter.py, src/harness_core/proof.py</files>
  <action>
    Create `src/harness_core/harness2_adapter.py`:
    1. Import `BenchmarkAdapter`, `BenchSpec`, `BenchPrompts`, `ChannelSpec`, `RunView`, `SubstrateLike` from `harness2.core.spec`. Import `OpencodeSubstrate` from `harness2.substrate.opencode`. Import `tree` as `h2_tree` from `harness2.core`.
    2. Implement `OrchestratorBenchmarkAdapter`:
       - `__init__(self, orchestrator: HarnessOrchestrator, runs_root: Path | str, base_harness_dir: Path | str | None = None, spec: BenchSpec | None = None)`:
         - Store `self.orchestrator = orchestrator`.
         - Store `self.runs_root = Path(runs_root).resolve()`.
         - Store `self.substrate = OpencodeSubstrate()`.
         - If `spec` is None, configure default `BenchSpec`:
           - `name="orchestrator_benchmark"`
           - `runs_root=self.runs_root / "runs"`
           - `install_mode="workspace_config"`
           - `prompts=BenchPrompts(work="execute autonomous coding and verification tasks")`
           - `channels={"proposer": ChannelSpec("opencode", "local/router"), "selector": ChannelSpec("opencode", "local/router")}`
         - Initialize base harness tree under `self.base_harness_dir` with valid `OPENCODE_SURFACE` components (`systemprompt.md`, `guardrails.md`, `LongTermMEMORY.md`, `tool_descriptions/tool_guidance.md`).
       - Task specification methods:
         - `tasks(self, split: str = "all") -> list[str]`: returns list of registered benchmark task IDs.
         - `domain_of(self, task_id: str) -> str`: returns domain classification (e.g., "software_engineering", "database", "api").
         - `task_prompt(self, task_id: str) -> str`: returns user prompt/goal for the task.
         - `task_files(self, task_id: str) -> Path | None`: returns directory with initial source material or None.
         - `base_harness(self) -> Path`: returns path to base harness directory.
         - `validate_tree(self, tree: dict[str, str]) -> None`: validates required harness files and raises `ValueError` on violations.
       - Execution and Rollout methods:
         - `execute(self, task_id: str, harness_dir: Path | None, run_id: str, *, timeout: int | None = None) -> Path`:
           - Creates isolated rollout directory: `run_dir = self.runs_root / "executions" / run_id`.
           - Creates dedicated workspace for this run: `ws_dir = run_dir / "workspace"`.
           - Copies or clones initial task files from `task_files(task_id)` into `ws_dir` if present, or prepares a clean workspace.
           - Applies candidate harness from `harness_dir` (or `base_harness()` if None) into `ws_dir`.
           - Submits and executes task through `self.orchestrator`:
             `task_res = self.orchestrator.submit_and_run(TaskSubmitRequest(goal=self.task_prompt(task_id), workspace_root=str(ws_dir), execution_mode="standard", project_id=f"bench_{run_id}"), auto_execute=True)`.
           - Extracts tool calls from `self.orchestrator.ledger.list_calls(task_res["task_id"])` and formats into standard `[ACTION] ... \n[OBSERVATION] ... \n` (or `[ERROR] ...`) trajectory log.
           - Writes formatted trajectory to `run_dir / "trajectory.md"`.
           - Collects deliverables (e.g. modified files, diffs, `answer.txt`) into `run_dir`.
           - Returns `run_dir`.
       - Verification and Scoring methods:
         - `delivered(self, run_dir: Path) -> bool`: checks if rollout produced expected deliverable files and task reached terminal success (`SUCCEEDED`).
         - `trajectory(self, run_dir: Path, *, obs_trunc: int = 50_000) -> str`: reads `run_dir / "trajectory.md"`, truncating observations longer than `obs_trunc`.
         - `deliverable_text(self, run_dir: Path) -> str`: extracts deliverable text from output files.
         - `deliverable_files(self, run_dir: Path) -> dict[str, str]`: maps deliverable filenames to text.
         - `score(self, run_dir: Path, task_id: str) -> dict | None`: returns evaluation score dict (e.g. `{"passed": True, "score": 1.0}`).
    3. In `src/harness_core/proof.py`:
       - Import and re-export `OrchestratorBenchmarkAdapter` from `src/harness_core/harness2_adapter.py`.

    AVOID: Modifying benchmark source files in-place without isolated workspace directories; each rollout must have independent CoW or cloned disk boundaries.
  </action>

  <done>OrchestratorBenchmarkAdapter strictly conforms to BenchmarkAdapter protocol, creates isolated run workspaces, captures trajectory in [ACTION]/[OBSERVATION] grammar, and produces deliverables.</done>

<task type="auto">
  <name>Connect Recursion Rollout Sweeps (run_parallel & run_sequential) and Wire hex harness2-eval CLI Subcommand</name>
  <files>src/harness_core/harness2_adapter.py, src/harness_core/cli.py</files>
  <action>
    In `src/harness_core/harness2_adapter.py`:
    1. Implement `run_orchestrator_sweep(adapter: OrchestratorBenchmarkAdapter, task_id: str, *, mode: str = "parallel", k: int = 1, proposer: Any = None, work_dir: Path | None = None) -> ModeResult`:
       - Import `recursion` as `h2_recursion` from `harness2.core`.
       - Import `RunView` from `harness2.core.spec`.
       - Set `work = Path(work_dir or adapter.runs_root / "work" / f"{task_id}_{mode}").resolve()`.
       - Execute base run: `base_dir = adapter.execute(task_id, adapter.base_harness(), f"{task_id}_base")`.
       - Construct initial `base_rv = RunView(label="base", run_id=f"{task_id}_base", run_dir=base_dir, ok=adapter.delivered(base_dir), delivered=adapter.delivered(base_dir))`.
       - If `proposer` is None, use `DemoProposer` from `harness2.demo` or a local router-backed proposer.
       - If `mode == "parallel"`: call `h2_recursion.run_parallel(task_id, k, [base_rv], adapter=adapter, prop=proposer, work_dir=work, run_id_of=lambda lbl: f"{task_id}_{lbl}", base_tree=h2_tree.read_tree(adapter.substrate.surface(), adapter.base_harness()))`.
       - Else if `mode == "sequential"`: call `h2_recursion.run_sequential(task_id, k, [base_rv], adapter=adapter, prop=proposer, work_dir=work, run_id_of=lambda lbl: f"{task_id}_{lbl}", base_tree=h2_tree.read_tree(adapter.substrate.surface(), adapter.base_harness()))`.
       - Return the resulting `ModeResult`.

    In `src/harness_core/cli.py`:
    2. Register `harness2-eval` CLI subcommand parser:
       - `p_h2_eval = sub.add_parser("harness2-eval", help="Run multi-rollout Propose-Probe-Compose sweep via OrchestratorBenchmarkAdapter")`.
       - Add arguments:
         - `--task-id`, default="demo-1", help="Task ID to evaluate"
         - `--mode`, choices=["parallel", "sequential"], default="parallel", help="Recursion execution mode"
         - `--k`, type=int, default=1, help="Number of candidate iterations / width"
         - `--runs-root`, default=None, help="Root directory for rollout executions and logs"
         - `--json`, action="store_true", help="Output results as JSON"
    3. Implement `harness2-eval` execution handler in `main()`:
       - Instantiate `HarnessOrchestrator` with `--data-dir`.
       - Instantiate `OrchestratorBenchmarkAdapter` with target runs root.
       - Invoke `run_orchestrator_sweep(adapter=adapter, task_id=args.task_id, mode=args.mode, k=args.k)`.
       - If `--json`: print `json.dumps(res.to_dict(), indent=2)`.
       - Else: format and print a human-readable summary table with mode, task_id, ok status, stages count, and winning finals.
    4. Ensure existing `harness2-demo` continues to function with zero regressions.

    AVOID: Breaking existing CLI commands or failing on systems where optional cloud APIs are not configured; default to deterministic local execution.
  </action>

  <done>run_orchestrator_sweep connects OrchestratorBenchmarkAdapter to Google Research's run_parallel and run_sequential recursion loops, and hex harness2-eval CLI runs sweeps with formatted output.</done>
