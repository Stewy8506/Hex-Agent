  <name>Task 1: SkillCompiler with Hermes Invariants, `verify:` Frontmatter & SkillSpector Gate</name>
  <files>src/harness_core/skills/__init__.py, src/harness_core/skills/compiler.py, src/harness_core/skillspector.py</files>
  <action>
    Create `src/harness_core/skills/__init__.py` and `src/harness_core/skills/compiler.py` implementing:
    1. `SkillCompiler`:
       - `compile_skill(source_input, name=None, description=None, verify_hook=None, is_global=False, workspace_root=None, references=None, scripts=None, dry_run=False)`:
         - Target directory resolution: `.hex/skills/<skill_name>/` (if `not is_global`) or `~/.hex/skills/<skill_name>/` (if `is_global=True`).
         - Standardize metadata according to Hermes HARDLINE authoring standards:
           - `name`: lowercase-hyphenated, `<=64` chars, no spaces.
           - `description`: 1 single sentence, strictly `<=60` chars, ending with a period. Reject or truncate marketing buzzwords.
           - `version`: "0.1.0" default.
           - `author`: "HEX" (never host username or git config).
         - Standard body section structure:
           1. `# <Title>` + 2-3 sentence overview
           2. `## When to Use`
           3. `## Prerequisites`
           4. `## How to Run`
           5. `## Quick Reference`
           6. `## Procedure`
           7. `## Pitfalls`
           8. `## Verification`
         - Knowledge-base skill layout: For large reference documents, write lean `SKILL.md` index + auxiliary `references/<chapter>.md` and `scripts/<tool>` files.
    2. YAML Frontmatter with `verify:` Hook:
       - Format supports either a concise command string (`verify: pytest tests/test_rpc.py`) or structured YAML block:
         ```yaml
         verify:
           command: "pytest tests/test_rpc.py"
           timeout_seconds: 30
           must_pass: true
           ast_invariant: "test_rpc_schema_sync in tests/test_rpc.py"
           test_filter: "-k test_rpc"
         ```
       - Enhance `parse_skill_frontmatter` in `src/harness_core/skillspector.py` to parse nested `verify` blocks (dicts or strings) cleanly.
    3. Mandatory SkillSpector Safety Gate:
       - Before persisting any compiled skill bundle to disk (unless `dry_run=True`), pass the candidate bundle directory through `SkillSpectorScanner.scan_bundle()`.
       - If `report.gate_decision == "QUARANTINE"`, refuse to install to `.hex/skills/` or `~/.hex/skills/`, write to `.hex/quarantine/<skill_name>/`, and raise `PermissionError` with the scan violation details.
       - If `report.gate_decision in ("ALLOW", "REQUIRE_APPROVAL")`, persist cleanly and return compilation summary.
    AVOID: Allowing unvetted skill files with malicious shell injections or prompt exploits to be written directly into `.hex/skills/` without running SkillSpector.
  </action>
  <verify>.venv/bin/pytest tests/skills/test_skill_synthesis.py -k "test_compiler or test_frontmatter or test_skillspector_gate" -v</verify>
  <done>SkillCompiler enforces Hermes name/description constraints, formats verify: blocks, isolates global vs local paths, and rejects/quarantines dangerous skills via SkillSpector.</done>
</task>

  <name>Task 2: Deterministic `verify:` Execution Hook Engine</name>
  <files>src/harness_core/skills/executor.py, src/harness_core/skills/__init__.py</files>
  <action>
    Create `src/harness_core/skills/executor.py` implementing the deterministic verification hook execution engine:
    1. Data Models:
       - `SkillVerificationHook`:
         - `command: str` (e.g. `pytest tests/test_rpc.py` or `cargo test`)
         - `timeout_seconds: float = 30.0`
         - `must_pass: bool = True`
         - `ast_invariant: str | None = None`
         - `test_filter: str | None = None`
       - `SkillVerificationResult`:
         - `skill_name: str`
         - `command: str`
         - `exit_code: int`
         - `stdout: str`
         - `stderr: str`
         - `passed: bool`
         - `duration_ms: float`
         - `error_message: str | None = None`
    2. `SkillExecutionEngine`:
       - `extract_verification_hook(skill_path_or_text: Path | str) -> SkillVerificationHook | None`:
         - Extracts and normalizes the `verify:` hook from `SKILL.md` frontmatter.
       - `run_skill_verification(hook: SkillVerificationHook, workspace_root: Path | str, env_overrides: dict | None = None) -> SkillVerificationResult`:
         - Runs the verification command inside `workspace_root` with subprocess timeout protection and output capture.
         - Validates AST invariant (if specified) against workspace files using `ast.parse` or token search.
         - Returns structured `SkillVerificationResult`.
    3. Regression Assertion Integration:
       - Provide helper `assert_skill_regression_free(skill_dir: Path | str, workspace_root: Path | str)` for orchestrator and test runner integration.
       - Export public API in `src/harness_core/skills/__init__.py`.
    AVOID: Unbounded subprocess execution without timeout protection or failing silently when a mandatory `must_pass: true` hook fails.
  </action>
