# Plan 02.02: Container Sandbox Isolation Engine & Gateway Integration

<objective>
Implement the container and sandbox execution engine in `src/harness_core/sandbox.py` supporting `bubblewrap` (`bwrap`), Docker/Podman, and `RestrictedSubprocessSandbox` fallbacks. Wire the sandbox engine into `ToolGateway` in `src/harness_core/gateway.py` so untrusted test execution and code evaluation run strictly bounded inside the attempt's isolated CoW workspace. <task type="auto">
  <name>Implement Container Sandbox Isolation Engine in src/harness_core/sandbox.py</name>
  <files>src/harness_core/sandbox.py</files>
  <action>
    Create `src/harness_core/sandbox.py` providing containment for untrusted tool invocations:
    1. Define `SandboxResult` dataclass:
       - `exit_code: int`: Process exit status.
       - `stdout: str`: Standard output from sandboxed execution.
       - `stderr: str`: Standard error from sandboxed execution.
       - `timed_out: bool = False`: Flag indicating timeout expiration.
       - `violation_detected: bool = False`: Flag indicating policy/boundary violation.
       - `violation_reason: str | None = None`: Description of violation (e.g. path escape, unauthorized network, credential access).
       - `sandbox_backend: str`: Backend name (`bubblewrap`, `docker`, `podman`, `restricted_subprocess`).
       - `duration_ms: float = 0.0`: Execution duration in milliseconds.
    2. Define `ExecutionSandbox` Protocol:
       - `backend_name: str`
       - `execute(cmd: list[str], cwd: Path | str, env: dict[str, str] | None = None, timeout: float = 30.0) -> SandboxResult`
    3. Implement `BubblewrapSandbox`:
       - Probes `shutil.which("bwrap")`.
       - Assembles `bwrap` command arguments:
         - `--unshare-net`: Complete network isolation (no internet/LAN socket access).
         - `--unshare-pid`: Isolated PID namespace.
         - `--unshare-ipc`: Inter-process communication isolation.
         - `--ro-bind /usr /usr`, `--ro-bind /bin /bin`, `--ro-bind /etc /etc` (and `/lib`, `/lib64` if present).
         - `--proc /proc`, `--dev /dev`, `--tmpfs /tmp`.
         - `--bind <cwd> <cwd>`: Strictly read-write mount only the CoW workspace directory.
         - `--chdir <cwd>`.
         - Purges sensitive environment variables from `env`.
    4. Implement `DockerPodmanSandbox`:
       - Probes `shutil.which("docker")` or `shutil.which("podman")` and checks daemon/socket availability.
       - Assembles container command:
         - `docker run --rm --network none -v <cwd>:<cwd>:rw -w <cwd> --read-only --tmpfs /tmp:rw,noexec,nosuid ...`
    5. Implement `RestrictedSubprocessSandbox` (safe, portable fallback for macOS and environments without container tools):
       - Strictly confines execution: validates that `cwd` is an existing directory and resolves canonical path. If `cwd` escapes or attempts directory traversal, marks `violation_detected=True` and aborts.
       - Strips sensitive credentials from environment: sanitizes `os.environ` and passed `env`, removing any key matching `(?i)(API_KEY|SECRET|TOKEN|PASS|PASSWORD|AUTH|CREDENTIAL|PRIVATE|AWS_|GITHUB_|GH_|HARNESS_)`.
       - Only forwards safe minimal environment variables (`PATH`, `LANG`, `LC_ALL`, `PYTHONPATH`, `SYSTEMROOT`).
       - Enforces resource limits on POSIX systems via `resource` module inside `preexec_fn`:
         - Set CPU time limit (`RLIMIT_CPU`) to `int(timeout) + 2`.
         - Set max child processes (`RLIMIT_NPROC`) to prevent fork-bomb denial-of-service.
       - Manages execution timeouts cleanly using `subprocess.Popen` with process group kill (`os.killpg`) to ensure no orphan background processes linger.
    6. Implement factory `get_default_sandbox(workspace_dir: Path | str | None = None) -> ExecutionSandbox`:
       - Prefers `BubblewrapSandbox` if `bwrap` is found on Linux.
       - Else prefers `DockerPodmanSandbox` if docker or podman is functional.
       - Falls back to `RestrictedSubprocessSandbox` with full logging of the active backend.
    AVOID: Using `shell=True` in subprocess execution; always use tokenized argument lists.
  </action>
  <verify>python3 -c "from harness_core.sandbox import get_default_sandbox, RestrictedSubprocessSandbox, BubblewrapSandbox, DockerPodmanSandbox; s = get_default_sandbox(); print('Sandbox detected:', s.backend_name)"</verify>
  <done>Sandbox classes and factory are implemented, validly typed, and instantiate without errors.</done>
</task>

       - Update `ToolGateway.__init__` to accept `sandbox: ExecutionSandbox | None = None`. Default to `get_default_sandbox()`.
       - Update `_tool_run_tests`:
         - Construct test command (`[sys.executable, "-m", "unittest", ...]`).
         - Delegate execution to `self.sandbox.execute(cmd=cmd, cwd=workspace_dir, env=sanitized_env, timeout=timeout)`.
         - If `result.violation_detected` is True, raise `PolicyBlockedError` or return structured failure with `violation_reason`.
         - Map `SandboxResult` into standard tool response dictionary:
           - `"ok"`: `result.exit_code == 0 and not result.timed_out and not result.violation_detected`
           - `"exit_code"`: `result.exit_code`
           - `"timed_out"`: `result.timed_out`
           - `"violation_detected"`: `result.violation_detected`
           - `"sandbox_backend"`: `result.sandbox_backend`
           - `"output"`: combined stdout/stderr, redacted with `redact_secrets()`, truncated to `result_size_cap`.
           - `"output_sha256"`: deterministic SHA-256 of combined output.
       - In `_resolve_confined_path`: enhance check to verify target path does not resolve outside `workspace_dir` even via tricky symlinks or relative references.
    2. In `src/harness_core/orchestrator.py`:
       - Update `HarnessOrchestrator.__init__` to accept optional `sandbox: ExecutionSandbox | None = None`.
       - Initialize `self.sandbox = sandbox or get_default_sandbox()`.
       - Pass `self.sandbox` when constructing `self.gateway = ToolGateway(self.ledger, self.graphify, sandbox=self.sandbox)`.
       - Update worker registration capabilities to record active sandbox backend (`sandbox_backend=self.sandbox.backend_name`).
    AVOID: Breaking existing callers that instantiate `ToolGateway(ledger, graphify)` without a sandbox argument.
  </action>
