<task type="auto">
  <name>Task 1: Core CuratedMemoryStore & StreamingContextScrubber in memory.py</name>
  <files>src/harness_core/memory.py</files>
  <action>
    Create `src/harness_core/memory.py` providing:
    1. Constants and entry delimiters:
       - `ENTRY_DELIMITER = "\n§\n"`
       - Default character limits: `USER_CHAR_LIMIT = 1375`, `MEMORY_CHAR_LIMIT = 2200`, `GUARDRAIL_CHAR_LIMIT = 2000`.
       - Location resolution: `USER.md` in `HEX_HOME` (default `~/.hex/USER.md`), `MEMORY.md` and `GUARDRAILS.md` in `.hex/memories/` (or `.hex/`) inside the workspace root.
    2. `CuratedMemoryStore`:
       - Atomic write operations (`add`, `replace`, `patch`, `remove`, `list_entries`) supporting both single operations and batch lists.
       - Enforce character caps before commit; return descriptive error when exceeding limits.
       - Tolerant old_text matching with quote/dash/whitespace normalization matching Hermes `_normalize_for_match`.
       - Atomic persistence using temporary file rename and file locking (`fcntl` with Windows `msvcrt` / fallback).
       - Drift detection: refuse to overwrite if external un-delimited modifications exceed limits, saving a `.bak` snapshot instead.
    3. `MemorySnapshot`:
       - `build_frozen_snapshot(workspace_root)`: reads `USER.md`, `MEMORY.md`, and `GUARDRAILS.md` at session start.
       - Deduplicates repeated recall lines across sections (`_drop_repeated_recall_lines`).
       - Renders into fenced `<memory-context>` block for Slot #4 system prompt assembly.
       - Frozen guarantee: once computed for a session, `MemorySnapshot` returns the exact byte-identical string throughout the session life.
    4. `StreamingContextScrubber`:
       - Port stateful streaming scrubber from Hermes `agent/memory_context.py`.
       - Methods: `feed(chunk: str) -> str`, `flush() -> str`, `reset()`.
       - Intercepts streaming tokens, holds back partial tag tails, and strips `<memory-context>...</memory-context>` spans so recalled system notes never leak to user chat displays.
    AVOID: Naive string appending without entry delimiters or size validation; avoid mutable in-place mutation of active system prompt during session execution.
  </action>
  <verify>.venv/bin/pytest tests/test_curated_memory.py -k "test_curated_store or test_scrubber or test_frozen_snapshot" -v</verify>
  <done>CuratedMemoryStore handles add/patch/remove with char caps and file locking; MemorySnapshot creates deduplicated fenced text; StreamingContextScrubber strips memory-context fences without leaking partial tags.</done>
</task>

  <files>src/harness_core/memory.py, src/harness_core/react_loop.py</files>
  <action>
    Implement negative constraint memory ("Anti-Patterns & Guardrails") in `src/harness_core/memory.py`:
    1. `GuardrailsManager`:
       - Manages `.hex/memories/GUARDRAILS.md`.
       - Invariant format: `- [AVOID] <Clear negative instruction explaining what not to do and why>`.
       - Methods: `record_avoid_invariant(rule: str)`, `list_guardrails() -> list[str]`, `format_guardrails() -> str`.
       - Enforces character limit (`GUARDRAIL_CHAR_LIMIT = 2000`) and deduplication.
    2. Automatic Failure Capture in `src/harness_core/react_loop.py`:
       - Track tool call error signatures across turns within `ReActLoop` (e.g. `(tool_name, error_signature)`).
       - When the same tool or command fails >= 2 consecutive times with identical error or syntax/type failure, extract the root cause signature and synthesize a concise `[AVOID]` invariant.
       - Automatically write the synthesized rule into `GUARDRAILS.md` via `GuardrailsManager`.
       - When a diff is rejected or rollback occurs, record a negative guardrail noting the failed approach.
    AVOID: Recording noisy transient errors (like 429 rate limits or network timeouts) into GUARDRAILS.md; only record deterministic tool/compiler/runtime code failures.
  </action>
  <verify>.venv/bin/pytest tests/test_curated_memory.py -k "test_guardrails" -v</verify>
  <done>GuardrailsManager writes clean [AVOID] invariants; ReActLoop captures repeat failures (>=2 times) and auto-populates GUARDRAILS.md.</done>
