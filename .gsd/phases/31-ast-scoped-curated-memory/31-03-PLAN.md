# Plan 31.03: Zettelkasten A-MEM Controller, Memory Lifecycle & Lightweight Rollback

<objective>
Implement the Zettelkasten A-MEM controller with automated contradiction resolution and `[[wiki-links]]`, the memory lifecycle engine (hit counting, promotion to SKILL/MEMORY, and demotion of >30d stale notes to cold SQLite FTS5 archival), and lightweight `.history/` timestamped rollback ergonomics.

<task type="auto">
  <name>Task 1: Zettelkasten A-MEM Controller & Contradiction Resolution</name>
  <files>src/harness_core/memory.py</files>
  <action>
    Implement `AMEMController` in `src/harness_core/memory.py`:
    1. CRUD Decision Engine:
       - Actions: `ADD`, `UPDATE`, `DELETE`, `NOOP`.
       - Structured memory item: `id`, `text`, `tags` (extracted from `[[tag]]`), `scope`, `hit_counter`, `created_at`, `last_referenced_at`.
    2. Contradiction Resolution:
       - Before writing a new memory bullet, scan existing entries in the target file (`MEMORY.md` or `USER.md`).
       - Compute lexical similarity and check semantic transition markers (e.g. "migrated from X to Y", "replaced X with Y", "switched DB to Z", "deprecated").
       - If an incoming note contradicts an existing bullet (e.g. "Use pytest instead of unittest" vs existing "Use unittest"), execute an `UPDATE` or `DELETE` on the superseded note rather than appending a duplicate or conflicting bullet.
    3. Wiki-Style Concept Linking:
       - Parse `[[concept-tag]]` tokens (e.g. `[[auth-flow]]`, `[[database-config]]`, `[[api-router]]`).
       - Maintain an inverted index of tags -> memory IDs.
       - Implement `get_linked_neighborhood(tag: str) -> list[MemoryItem]`: retrieves notes sharing the concept tag, allowing targeted retrieval of conceptual clusters without loading all memories into prompt context.
    AVOID: Blindly appending notes without checking for existing contradictions; avoid bloated vector DB requirements for local markdown files.
  </action>
  <verify>.venv/bin/pytest tests/test_amem_and_lifecycle.py -k "test_amem_crud or test_contradiction or test_wiki_links" -v</verify>
  <done>AMEMController resolves contradictory notes via UPDATE/DELETE; concept tags ([[tag]]) index and retrieve linked neighborhoods.</done>
</task>

<task type="auto">
  <name>Task 2: Memory Lifecycle Engine & SQLite FTS5 Cold Archival</name>
  <files>src/harness_core/memory.py</files>
  <action>
    Implement `MemoryLifecycleManager` in `src/harness_core/memory.py`:
    1. Hit Counters & Reference Tracking:
       - Track `hit_counter` (integer) and `last_referenced_at` (ISO timestamp) per memory entry.
       - Method `record_reference(entry_id: str)`: increments hit counter and updates timestamp.
    2. Promotion Protocol:
       - Method `check_promotions() -> list[dict]`: identifies reflections or episodic entries with `hit_counter >= 3` across distinct sessions.
       - Promotes verified reflections from `.hex/reflections/LESSONS.md` into active `MEMORY.md` or flags them for skill compilation.
    3. Demotion Protocol & SQLite FTS5 Cold Archival:
       - Create an `archived_memories` table with SQLite FTS5 virtual table indexing (`memory_id`, `target`, `content`, `tags`, `archived_at`, `reason`).
       - Method `run_demotion_sweep(retention_days=30)`:
         a. Scans active entries in `MEMORY.md` and `USER.md`.
         b. Identifies entries where `now - last_referenced_at > 30 days` or whose linked AST code hashes have permanently diverged.
         c. Prunes them from the active markdown file and moves them into `archived_memories`.
         d. Pruned entries no longer consume prompt tokens in Slot #4.
       - Method `search_archived_memories(query: str, limit=10) -> list[dict]`: BM25 lexical search over cold archived notes when needed.
    AVOID: Deleting memories permanently without cold archival; unreferenced notes must remain retrievable via search.
  </action>
  <verify>.venv/bin/pytest tests/test_amem_and_lifecycle.py -k "test_lifecycle or test_promotion or test_demotion_fts5" -v</verify>
  <done>Hit counters track reference frequency; reflections with >=3 hits promote; stale entries (>30 days) demote to SQLite FTS5 archival table.</done>
</task>
