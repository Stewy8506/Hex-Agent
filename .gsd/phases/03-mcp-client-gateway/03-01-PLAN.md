# Plan 03.01: MCP Client Adapters (stdio & SSE) & Dynamic Tool Discovery with R0–R4 Risk Mapping

<objective>
Implement `MCPClientAdapter`, `StdioMCPTransport`, and `HttpSSEMCPTransport` in `src/harness_core/mcp_client.py` conforming to the Model Context Protocol (MCP) JSON-RPC 2.0 specification. Support stdio subprocess transport, handshake negotiation, dynamic tool discovery (`tools/list`), dynamic `R0–R4` risk mapping with heuristic rules and per-server overrides, and tool invocation (`tools/call`) with execution timeouts and structured error handling. Build a local Python-based mock MCP server and unit test suite in `tests/test_mcp_client.py`.

Purpose: Enable the harness to communicate natively with external MCP tool providers over standard transports without external library dependencies.

<task type="auto">
  <name>Implement MCPClientAdapter, Stdio/SSE transports, and dynamic R0-R4 risk mapping</name>
  <files>src/harness_core/mcp_client.py</files>
  <action>
    Create `src/harness_core/mcp_client.py` providing zero-dependency MCP client connectivity:
    1. Define `MCPTransport` protocol / base class:
       - `send_request(method: str, params: dict[str, Any] | None = None, timeout: float = 30.0) -> dict[str, Any]`
       - `send_notification(method: str, params: dict[str, Any] | None = None) -> None`
       - `close() -> None`
    2. Implement `StdioMCPTransport(MCPTransport)`:
       - Accepts `command: list[str]`, `cwd: Path | str | None = None`, `env: dict[str, str] | None = None`.
       - Launches subprocess using `subprocess.Popen` with pipes for `stdin`, `stdout`, `stderr`.
       - Reads and writes JSON-RPC 2.0 messages over standard I/O (handling newline-delimited JSON messages and optional `Content-Length` headers).
       - Implements thread-safe message correlation: monotonic integer request IDs, dictionary of pending request futures/events (`dict[int, threading.Event]`), and response store.
       - Runs a background daemon thread for reading lines from stdout, demuxing responses and server notifications.
       - Captures stderr output in a rolling buffer for crash and debug diagnostics.
       - Implements `close()`: closes stdin, terminates child process gracefully with `SIGTERM`, waits up to 2.0s, and issues `kill()` if process remains alive.
    3. Implement `HttpSSEMCPTransport(MCPTransport)`:
       - Accepts `endpoint_url: str`, `headers: dict[str, str] | None = None`.
       - Uses Python stdlib `urllib.request` / `http.client` for JSON-RPC POST requests and background SSE stream consumption.
    4. Define `MCPToolDefinition` dataclass:
       - `name: str`
       - `description: str`
       - `input_schema: dict[str, Any]`
       - `risk_class: RiskClass`
       - `server_id: str`
    5. Implement `classify_mcp_tool_risk(name: str, description: str, overrides: dict[str, RiskClass] | None = None) -> RiskClass`:
       - If `overrides` contains `name`, immediately return `overrides[name]`.
       - Normalize `name` and `description` to lowercase.
       - Heuristic pattern rules:
         - **R4 (Root / Destructive / Policy / Secret):** Name or description matches `^(sudo|root|secret|auth|policy|revoke|grant|admin|eval|format_disk)\b` or keywords `root`, `admin`, `secret`, `credential`, `token`, `master_key`.
         - **R3 (Privileged / Execution / Shell / Network Outbound):** Name or description matches `^(exec|shell|bash|cmd|command|publish|deploy|git_push|post|send_email|external_call)\b` or keywords `exec`, `shell`, `command`, `deploy`, `publish`.
         - **R2 (Workspace Write / Build / Mutate / Test):** Name or description matches `^(write|create|update|modify|edit|append|patch|delete|remove|run_test|compile|build)\b` or keywords `write`, `update`, `delete`, `edit`, `modify`.
         - **R1 (Read-Only Inspection / Query / Search):** Name or description matches `^(get|read|list|fetch|search|query|describe|view|find|check|inspect)\b` or keywords `read`, `list`, `query`, `search`, `fetch`.
         - **Default (Safe Default-Deny):** If unrecognized, default to `RiskClass.R2` (never default to read-only R0/R1).
    6. Implement `MCPClientAdapter`:
       - `__init__(server_id: str, transport: MCPTransport, risk_overrides: dict[str, RiskClass] | None = None)`
       - `initialize(timeout: float = 30.0) -> dict[str, Any]`:
         - Sends `initialize` request with client info (`name="harness-mcp-client"`, `version="0.1.0"`) and protocolVersion (`"2024-11-05"`).
         - Receives server capabilities and server info.
         - Sends `notifications/initialized` notification.
         - Marks `self.initialized = True`.
       - `discover_tools(timeout: float = 30.0) -> list[MCPToolDefinition]`:
         - If not initialized, calls `initialize(timeout)`.
         - Sends `tools/list` request.
         - Iterates returned tools, extracts `name`, `description`, `inputSchema`.
         - Classifies risk with `classify_mcp_tool_risk(name, description, self.risk_overrides)`.
         - Populates `self.tools: dict[str, MCPToolDefinition]` and returns tool list.
       - `call_tool(tool_name: str, arguments: dict[str, Any], timeout: float = 30.0) -> dict[str, Any]`:
         - Sends `tools/call` with `{"name": tool_name, "arguments": arguments}`.
         - Extracts `content` (text or embedded items) and `isError`.
         - Formats into standard tool dictionary:
           `{"ok": not is_error, "output": combined_text, "content": content, "raw": response_result}`.
         - Raises `TimeoutError` if call exceeds timeout.
         - Raises `RuntimeError` or `ValueError` on JSON-RPC protocol error codes.
       - `get_manifest_data() -> dict[str, Any]`:
         - Returns dictionary of `{ "server_id": self.server_id, "tools": [t.to_dict() ...], "server_info": self.server_info }` suitable for SHA-256 manifest pinning and SkillSpector security scanning.
       - `close() -> None`:
         - Closes transport.
    AVOID: Blocking the process indefinitely on unresponsive subprocesses; enforce strict timeouts on all request waits and process teardown.
  </action>

  <done>MCPClientAdapter and transports are implemented, correctly typed, and risk classification works deterministically.</done>
