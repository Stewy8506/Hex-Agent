# Plan 35.04: Gap Closure — Live Engine State Wiring & Continuous Animation Clock

<objective>
Eliminate all hardcoded mockup dummy data from `crates/hex-tui`, connect all 6 screens and the right rail to live engine state, fix the animation engine so frames actively advance using `app.session_started`, integrate diagnostic error cards into the session stream, and update tests to verify dynamic behavior.
</objective>

## Tasks

<task id="task-1" title="Wire continuous animation clock and remove per-frame AnimationState instantiation">
Fix `crates/hex-tui/src/ui/mod.rs` to derive `AnimationState` from `app.session_started` (or pass `app.session_started` to `AnimationState::with_start(app.session_started)`), so elapsed time advances monotonically.
Verify Braille spinner glyphs advance across ticks, cursor toggles visibility every 550ms, pulse marker interpolates continuously, shimmer sweeps text, and placeholder rotates every 5s.
<verify>
cargo test --package hex-tui --test test_design_system
</verify>
<done>
`ui::draw` uses a persistent clock, and animations are active instead of frozen at frame 0.
</done>
</task>

<task id="task-2" title="Purge hardcoded TypeScript mockup data and wire live telemetry across all screens">
1. In `src/app.rs`: Remove hardcoded fallback data for `plan_steps`, `changed_files`, `subagents`, `resume_sessions`, `tokens_used`, `modified_files_count`, and `indexed_files_count`. Dynamically compute git status and load plans/sessions from real engine sources.
2. In `src/ui/screens/start.rs`: Use `app.workspace_path` formatting (handle tilde replacement accurately) and render live telemetry.
3. In `src/ui/screens/session.rs`: Remove the 150-line fake fallback session (`GraphBuilder`, `pnpm test`). Display an empty state or real initial session transcript. Include tool results, durations, and exit statuses.
4. In `src/ui/screens/permission.rs`: Dynamically format option 2 as `format!("Allow {} in this project", tool_name)`. Remove hardcoded `rm -rf dist` fallback.
5. In `src/ui/screens/palette.rs`: Remove `"sw"` forced query on empty input. Populate palette items from available slash commands, tools, and actions. Implement proper fuzzy subsequence filtering.
6. In `src/ui/screens/subagent.rs`: Render `modal_state.activity_lines` dynamically instead of `default_activities`.
7. In `src/ui/screens/error_view.rs`: Wire `DiagnosticFailure` into tool execution errors in `app.rs` and render inline in `session.rs`.
<verify>
cargo test --package hex-tui
</verify>
<done>
All hardcoded TypeScript mockup strings are purged; all screens render live state or clean initial states.
</done>
</task>

<task id="task-3" title="Refactor test suite to validate dynamic behavior and live state transitions">
Update tests in `tests/test_screens_start_and_session.rs`, `tests/test_screens_overlays_and_errors.rs`, and `tests/ui_rendering_test.rs`:
- Test that real git branch, path, and file counts appear.
- Test that custom `plan_steps`, `changed_files`, and `subagents` added to `App` render correctly.
- Test that `permission::render` outputs the tool name in option 2.
- Test that empty palette query displays `> ` without `"sw"`.
- Test that `subagent::render` displays the lines in `activity_lines`.
- Remove assertions requiring fake TypeScript project strings (`GraphBuilder`, `dataflow-visualiser`, `builder.ts`, `pnpm test`).
<verify>
cargo test --package hex-tui
</verify>
<done>
Full test suite passes while asserting dynamic behavior and zero hardcoded dummy data.
</done>
</task>
