# Plan 17.01: Audio Capture, Speech-to-Text & Text-to-Speech Engine

<objective>
Implement the core zero-dependency voice engine for HEX in `src/harness_core/voice.py`, featuring thread-safe asynchronous Text-to-Speech (TTS) synthesis (supporting native macOS `say`, Linux `espeak`/`aplay`, and mock fallbacks), modular Speech-to-Text (STT) capture abstraction (push-to-talk and VAD listeners), audio text sanitization, mute controls, and integrate audio input/output diagnostics as the 9th category in `HexDoctor` (`src/harness_core/doctor.py`).

Purpose: Deliver hands-free audio pair-programming capabilities to HEX without requiring heavyweight native audio compilation dependencies (like PyAudio or portaudio), enabling reliable execution across macOS, Linux, and headless CI sandboxes.
Output: `src/harness_core/voice.py` core engine and audio probe, and audio diagnostic checks in `src/harness_core/doctor.py`.
</objective>

<task type="auto">
  <name>Implement Core Voice Engine, VoiceConfig & Asynchronous Text-to-Speech (TTS) Pipeline</name>
  <files>src/harness_core/voice.py</files>
  <action>
    Create `src/harness_core/voice.py` with standard library primitives (`subprocess`, `threading`, `queue`, `re`, `shutil`, `dataclasses`):
    1. Define `VoiceConfig`:
       - `tts_enabled: bool = True`
       - `stt_enabled: bool = True`
       - `voice_name: str | None = None` (e.g., "Samantha", "Alex" on macOS, None for default)
       - `speech_rate: int = 190` (words per minute, clamped between 80 and 400)
       - `muted: bool = False`
       - `backend: str = "auto"` ("auto", "macos_say", "linux_espeak", "mock")
       - Serialization methods: `to_dict()` and `from_dict(d: dict[str, Any])`.
    2. Implement `clean_text_for_speech(text: str, max_chars: int = 400) -> str`:
       - Strips ANSI escape codes via regex.
       - Replaces code blocks (```...```) with brief spoken placeholders (e.g. "code snippet omitted").
       - Strips markdown links `[text](url)` to just `text`, removes header `#` symbols, bold/italic asterisks.
       - Collapses whitespace and limits length to `max_chars` to keep spoken agent responses natural and concise.
    3. Implement `TextToSpeechProvider` abstract base protocol and concrete providers:
       - `BaseTTSProvider`: `speak(text: str, config: VoiceConfig) -> bool`, `is_available() -> bool`.
       - `MacOSTTSProvider`: uses `subprocess.Popen` with `/usr/bin/say` or `say`. Supports `-v voice_name` and `-r speech_rate`.
       - `LinuxTTSProvider`: checks for `espeak` / `espeak-ng` or `festival`. Uses `-s rate` flag.
       - `MockTTSProvider`: records spoken texts into `spoken_history: list[str]` for deterministic testing.
       - Factory `get_tts_provider(backend: str = "auto") -> BaseTTSProvider` selecting MacOS on Darwin, Linux on Linux, or MockTTSProvider if no binary is on PATH.
    4. Implement `VoiceEngine`:
       - Holds `VoiceConfig` and active TTS provider.
       - Thread-safe non-blocking audio queue `queue.Queue[str]`.
       - Background worker thread `_speech_worker` continuously taking utterances from queue and speaking them sequentially (preventing overlapping audio).
       - Methods:
         - `speak(text: str, clean: bool = True, priority: bool = False) -> None`: enqueues text if `tts_enabled` and not `muted`.
         - `mute() -> None`, `unmute() -> None`, `toggle_mute() -> bool`, `is_muted() -> bool`.
         - `set_voice(name: str | None) -> None`, `set_rate(rate: int) -> None`.
         - `stop() -> None`: clears queue and terminates any currently playing speech process.
         - `shutdown() -> None`: cleanly stops background worker.

    AVOID: Mandatory external audio C-bindings (e.g. `pyaudio`, `sounddevice`, `pygame`); use platform CLI utilities with pure-Python mock fallbacks.
  </action>
  <verify>python -c "from harness_core.voice import VoiceEngine, VoiceConfig, clean_text_for_speech; cfg = VoiceConfig(); eng = VoiceEngine(cfg); print('VoiceEngine initialized, backend:', eng.tts_provider.__class__.__name__)"</verify>
  <done>VoiceConfig and VoiceEngine are implemented with non-blocking queue execution, markdown text sanitization, mute controls, and zero mandatory external C dependencies.</done>

  <files>src/harness_core/voice.py</files>
  <action>
    In `src/harness_core/voice.py`:
    1. Implement `probe_audio_hardware() -> dict[str, Any]`:
       - Inspects host OS (`platform.system()`).
       - Probes available TTS synthesizers: searches `shutil.which` for `say`, `espeak`, `espeak-ng`, `festival`.
       - Probes available audio output players: searches `afplay` (macOS), `aplay`, `paplay`, `ffplay` (Linux).
       - Probes available audio recording utilities: searches `rec` (sox), `arecord`, `ffmpeg`, or platform audio frameworks.
       - Returns structured dict:
         `{"platform": str, "tts_available": bool, "tts_engine": str | None, "audio_player": str | None, "mic_available": bool, "mic_tool": str | None, "devices": list[str]}`.
    2. Implement `SpeechToTextProvider` abstract protocol:
       - `is_available() -> bool`
       - `listen_once(timeout: float = 5.0) -> str | None`: single utterance capture.
       - `start_continuous_listening(callback: Callable[[str], None], stop_event: threading.Event) -> None`: background stream.
    3. Implement concrete STT providers:
       - `NativeSTTProvider`: checks for platform speech recognition tools (e.g. macOS native speech or system audio recorder CLI); gracefully returns `None` if audio hardware is absent.
       - `MockSTTProvider`: enables test suites and programmatic runners to simulate user speech by injecting utterances via `feed_transcript(text: str)`.
    4. Integrate STT into `VoiceEngine`:
       - `listen_once(timeout: float = 5.0) -> str | None` delegating to active STT provider.
       - Push-to-talk mode toggle `push_to_talk: bool = False`.

    AVOID: Blocking the main thread during audio capture or transcription; always respect timeouts and cancellation events.
  </action>
