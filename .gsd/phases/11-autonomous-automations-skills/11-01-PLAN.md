# Plan 11.01: Native Cron Scheduler, OS Daemon Installer & CLI Integration

<objective>
Implement the native background cron scheduler (`src/harness_core/scheduler.py`) and OS service daemon installer (`src/harness_core/daemon.py`), and wire them into the HEX CLI (`src/harness_core/cli.py`). Build `TaskScheduler` with a built-in 5-field cron parser, persistent job registry (`schedules.json`), due job execution via `HarnessOrchestrator`, and webhook alerts on failure. Build `DaemonInstaller` generating macOS `LaunchAgent` plist files and Linux `systemd` service units with environment variable forwarding and `--dry-run` inspection. Integrate `hex schedule` and `hex daemon` subcommands into `src/harness_core/cli.py`. Author a comprehensive test suite in `tests/test_scheduler_and_daemon.py`.

Purpose: Deliver the continuous background scheduling and OS residency foundation of Pillar 5 (Autonomous Background Automations & Autonomous Self-Synthesizing Skills), enabling HEX to run automations 24/7 without manual intervention.
Output: `src/harness_core/scheduler.py`, `src/harness_core/daemon.py`, updated `src/harness_core/cli.py`, and `tests/test_scheduler_and_daemon.py`.
</objective>

<task type="auto">
  <name>Implement Native 5-Field Cron Parser, ScheduledJob & TaskScheduler Engine with Webhook Alerts</name>
  <files>src/harness_core/scheduler.py</files>
  <action>
    Create `src/harness_core/scheduler.py`:
    1. Cron Expression Parser:
       - Implement `CronParser(cron_expr: str)`:
         - Standard 5 fields: `minute` (0-59), `hour` (0-23), `day_of_month` (1-31), `month` (1-12), `day_of_week` (0-6 or 0-7, where 0 and 7 represent Sunday).
         - Syntax support per field:
           - Wildcard `*` (all allowed values)
           - Step values `*/n` (e.g. `*/15` -> 0, 15, 30, 45)
           - Exact numbers (e.g. `5`)
           - Ranges `a-b` (e.g. `1-5`)
           - Lists `a,b,c` (e.g. `1,15,30`)
           - Step ranges `a-b/n` (e.g. `1-10/2` -> 1, 3, 5, 7, 9)
         - `is_valid() -> bool`: checks syntax and field boundaries.
         - `matches(dt: datetime) -> bool`: checks if the given datetime matches all 5 cron fields.
         - `next_run_after(base_dt: datetime) -> datetime`: computes the earliest datetime strictly after `base_dt` matching the cron expression. Evaluates minute by minute with reasonable ceiling (e.g. up to 1 year forward) to avoid infinite loops.
    2. Dataclass `ScheduledJob`:
       - `job_id: str` (e.g., `f"job_{uuid.uuid4().hex[:8]}"`)
       - `cron_expr: str`
       - `goal: str`
       - `project_id: str = "default"`
       - `enabled: bool = True`
       - `last_run: str | None = None` (ISO 8601 string)
       - `next_run: str | None = None` (ISO 8601 string)
       - `created_at: str = ""` (defaults to `utcnow_iso()`)
       - `to_dict() -> dict[str, Any]` and `classmethod from_dict(data: dict[str, Any]) -> ScheduledJob`.
    3. `TaskScheduler` Engine:
       - `__init__(self, storage_path: Path | str | None = None)`:
         - Default path: `Path.home() / ".hex" / "schedules.json"`, or project fallback `.hex/schedules.json` if environment points to repo. Supports explicit custom paths for testing.
       - `load_jobs() -> list[ScheduledJob]`: reads JSON registry file safely, returning list of jobs.
       - `save_jobs(jobs: list[ScheduledJob] | None = None)`: persists jobs to disk using atomic temporary file rename (`os.replace`) to prevent corruption during concurrent reads.
       - `add_job(cron_expr: str, goal: str, project_id: str = "default") -> ScheduledJob`:
         - Validates `cron_expr` using `CronParser`. Raises `ValueError` on malformed cron.
         - Computes initial `next_run`.
         - Appends to registry, saves to disk, and returns new `ScheduledJob`.
       - `remove_job(job_id: str) -> bool`:
         - Finds and removes job with matching `job_id`. Returns `True` if found and removed, `False` otherwise.
       - `list_jobs(include_disabled: bool = True) -> list[ScheduledJob]`:
         - Returns all registered jobs (optionally filtered by `enabled`).
       - `get_due_jobs(now: datetime | None = None) -> list[ScheduledJob]`:
         - Returns all enabled jobs where `next_run` is less than or equal to `now` (or where `next_run` is None/due).
       - `execute_due_jobs(orchestrator: HarnessOrchestrator, notifier: WebhookNotifier | None = None, now: datetime | None = None) -> list[dict[str, Any]]`:
         - Inspects `get_due_jobs(now)`.
         - For each due job:
           - Constructs `TaskSubmitRequest(goal=job.goal, project_id=job.project_id)`.
           - Executes via `orchestrator.submit_and_run(req, auto_execute=True)`.
           - Updates `job.last_run = utcnow_iso()`.
           - Computes new `job.next_run = CronParser(job.cron_expr).next_run_after(current_dt).isoformat()`.
           - In case of failure or uncaught exception:
             - Advances `job.next_run` so the job does not loop indefinitely.
             - If `notifier` is provided: dispatches an alert message/webhook payload describing the job failure.
           - Saves updated job state to disk.
         - Returns list of execution summary dicts.

    AVOID: Relying on third-party cron parsing packages (like `croniter`) that introduce heavy external dependencies; implement clean, zero-dependency parsing in pure Python.
  </action>
  <verify>
    <command>python3 -c "from harness_core.scheduler import CronParser, ScheduledJob, TaskScheduler; from datetime import datetime, timezone; p = CronParser('*/15 2 * * 1-5'); assert p.is_valid(); dt = datetime(2026, 11, 2, 2, 30, tzinfo=timezone.utc); assert p.matches(dt); next_dt = p.next_run_after(dt); assert next_dt.minute == 45; s = TaskScheduler('/tmp/test_hex_schedules.json'); j = s.add_job('0 3 * * *', 'Run audit'); assert j.job_id.startswith('job_'); assert len(s.list_jobs()) == 1; s.remove_job(j.job_id); assert len(s.list_jobs()) == 0; print('SCHEDULER_CORE_OK')"</command>
  </verify>
  <done>
    `CronParser`, `ScheduledJob`, and `TaskScheduler` with pure Python 5-field parsing, next run computation, atomic JSON storage, due job execution, and webhook alert notification are implemented in `src/harness_core/scheduler.py`.
  </done>

<task type="auto">
  <name>Implement OS Daemon Service Installer for macOS LaunchAgent & Linux Systemd</name>
  <files>src/harness_core/daemon.py</files>
  <action>
    Create `src/harness_core/daemon.py`:
    1. Configuration dataclass `DaemonConfig`:
       - `service_name: str = "ai.hex.daemon"`
       - `description: str = "HEX Autonomous AI Background Daemon"`
       - `python_path: str = field(default_factory=lambda: sys.executable)`
       - `hex_args: list[str] = field(default_factory=lambda: ["schedule", "run-due"])`
       - `working_dir: str | None = None`
       - `data_dir: str | None = None`
       - `config_dir: str | None = None`
       - `interval_seconds: int = 60`
       - `run_at_load: bool = True`
       - `keep_alive: bool = True`
       - `log_dir: Path | str | None = None` (defaults to `~/.hex/logs`)
    2. Class `DaemonInstaller`:
       - `__init__(self, config: DaemonConfig | None = None)`
       - `generate_launchd_plist() -> str`:
         - Produces valid Apple XML plist format (`<!DOCTYPE plist PUBLIC ...>`).
         - Configures:
           - `<key>Label</key><string>{config.service_name}</string>`
           - `<key>ProgramArguments</key><array>` with `[config.python_path, "-m", "harness_core.cli", *config.hex_args]`
           - `<key>RunAtLoad</key><true/>`
           - `<key>StartInterval</key><integer>{config.interval_seconds}</integer>`
           - `<key>EnvironmentVariables</key><dict>` with `HEX_DATA_DIR`, `HEX_CONFIG`, `PATH`
           - `<key>StandardOutPath</key><string>{log_dir}/daemon.stdout.log</string>`
           - `<key>StandardErrorPath</key><string>{log_dir}/daemon.stderr.log</string>`
       - `install_launchd(target_path: Path | str | None = None, dry_run: bool = False) -> dict[str, Any]`:
         - Default target: `Path.home() / "Library" / "LaunchAgents" / f"{config.service_name}.plist"`.
         - If `dry_run` is True: returns `{"status": "dry_run", "platform": "launchd", "path": str(target), "content": plist_content}`.
         - Otherwise: ensures directory exists, writes plist with `0644` permissions, returns `{"status": "installed", "path": str(target)}`.
       - `generate_systemd_unit(user: bool = True) -> str`:
         - Produces valid systemd `.service` INI file:
           - `[Unit]\nDescription={config.description}\nAfter=network.target\n`
           - `[Service]\nType=simple\n`
           - `ExecStart={config.python_path} -m harness_core.cli {" ".join(config.hex_args)}\n`
           - `Restart=always\nRestartSec=30\n`
           - Environment directives: `Environment=HEX_DATA_DIR=...`, `Environment=PATH=...`
           - Working directory if specified.
           - `[Install]\nWantedBy={"default.target" if user else "multi-user.target"}\n`
       - `install_systemd(user: bool = True, target_path: Path | str | None = None, dry_run: bool = False) -> dict[str, Any]`:
         - Default user target: `Path.home() / ".config" / "systemd" / "user" / f"{config.service_name}.service"`.
         - Default system target: `Path("/etc/systemd/system") / f"{config.service_name}.service"`.
         - If `dry_run` is True: returns `{"status": "dry_run", "platform": "systemd", "user": user, "path": str(target), "content": unit_content}`.
         - Otherwise: ensures parent directory exists, writes unit file with `0644` permissions, returns `{"status": "installed", "path": str(target)}`.
       - `get_daemon_status() -> dict[str, Any]`:
         - Detects OS platform (`Darwin` -> `launchd`, `Linux` -> `systemd`).
         - Checks for presence of plist or service unit files at standard locations.
         - Returns diagnostic dictionary `{"platform": platform, "installed": bool, "service_path": str | None, "active": bool}`.

    AVOID: Calling system reboot or interactive sudo prompts directly; provide `--dry-run` and clean path overrides so installation is deterministic and non-disruptive in test and CI environments.
  </action>
  <verify>
    <command>python3 -c "from harness_core.daemon import DaemonConfig, DaemonInstaller; inst = DaemonInstaller(DaemonConfig(service_name='ai.hex.test')); plist = inst.generate_launchd_plist(); assert '<key>Label</key>' in plist and 'ai.hex.test' in plist; unit = inst.generate_systemd_unit(user=True); assert '[Unit]' in unit and 'ExecStart=' in unit; res = inst.install_launchd(dry_run=True); assert res['status'] == 'dry_run'; print('DAEMON_CORE_OK')"</command>
  </verify>
  <done>
    `DaemonConfig` and `DaemonInstaller` with macOS LaunchAgent plist generation, Linux systemd service unit generation, dry-run safety, and platform status inspection are implemented in `src/harness_core/daemon.py`.
  </done>
