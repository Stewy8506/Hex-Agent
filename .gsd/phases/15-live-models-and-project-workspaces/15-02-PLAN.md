# Plan 15.02: Project Workspace Registry & Daily Project Switcher

<objective>
Implement a persistent global project registry in `~/.hex/projects.json`, an interactive daily project switcher ("What project do you want to work on today?") when launched outside a workspace, automatic project binding when launched inside a repository, and complete folder-scoped context isolation (`config.yaml`, `graph.json`, `reflections/LESSONS.md`, and `data/`).

Purpose: Allow operators to manage multiple projects cleanly without cross-project state pollution, context leakage, or manual path configuration.
Output: `ProjectRegistry` class, `hex project` CLI commands, daily picker in `cli.py`, and folder-scoped isolation in `project_registry.py` and `onboard.py`.
</objective>

<task type="auto">
  <name>Implement ProjectRegistry and folder-scoped context layout</name>
  <files>
    src/harness_core/project_registry.py
    src/harness_core/onboard.py
  </files>
  <action>
    1. Create `src/harness_core/project_registry.py`:
       - Define `@dataclass class ProjectRecord`:
         * `name: str`
         * `path: str` (absolute canonical directory path)
         * `stack: str` (e.g. `python`, `node`, `rust`, `go`, `generic`)
         * `last_active: str` (ISO 8601 UTC timestamp)
         * `task_count: int = 0`
         * `config_path: str = ""` (`<path>/.hex/config.yaml`)
         * `to_dict() -> dict[str, Any]` and `from_dict(data: dict[str, Any]) -> ProjectRecord`
       - Define `class ProjectRegistry`:
         * `__init__(self, registry_file: Path | str | None = None)`: defaults to `Path.home() / ".hex" / "projects.json"`.
         * `list_projects() -> list[ProjectRecord]`: returns projects sorted by `last_active` descending.
         * `get_project(name_or_path: str) -> ProjectRecord | None`: lookup by exact name or resolved path.
         * `register_project(path: Path | str, name: str | None = None, stack: str | None = None) -> ProjectRecord`:
           - Resolve canonical path. Ensure directory exists.
           - Detect stack using `detect_project_stack` if omitted.
           - Ensure `<project_dir>/.hex/` directory exists with isolated sub-structures:
             * `config.yaml`: generated via `init_project` if missing.
             * `reflections/LESSONS.md`: created with header `# Project Reflections & Work Memory: {name}\n\n## Lessons Learned\n` if missing.
             * `data/`: created for CoW snapshots and task databases.
             * `graph.json`: path verified for AST cache.
           - Insert or update record in `projects.json`, updating `last_active` and returning `ProjectRecord`.
         * `touch_active(path: Path | str, increment_tasks: bool = False) -> None`: updates `last_active` timestamp and optionally increments `task_count`.
         * `detect_enclosing_project(start_dir: Path | str) -> ProjectRecord | None`:
           - Traverse parent directories starting from `start_dir`.
           - If `.hex` directory or `.git` directory is found, register or load the directory as a `ProjectRecord` and return it.
           - If filesystem root reached without match, return `None`.

    2. In `src/harness_core/onboard.py`:
       - Update `init_project(repo_root: Path | str, *, force: bool = False)`:
         * Ensure `<repo_root>/.hex/reflections/LESSONS.md` is initialized.
         * Ensure `<repo_root>/.hex/data` directory is created.
         * Automatically call `ProjectRegistry().register_project(repo_root)` so initialized projects are registered.

    AVOID: Modifying global state when a project-scoped directory is active.
    AVOID: Insecure file operations. Use atomic JSON write (`.tmp` write and `os.replace`).
  </action>
  <verify>
    python3 -c "from harness_core.project_registry import ProjectRegistry; reg = ProjectRegistry('/tmp/test_reg.json'); p = reg.register_project('/tmp'); assert p.path == '/tmp'; assert len(reg.list_projects()) == 1"
  </verify>
  <done>
    `ProjectRegistry` manages `projects.json`, registers projects, ensures `.hex/` folder isolation, and detects enclosing projects.
  </done>
</task>

<task type="auto">
  <name>Implement daily project switcher picker, hex project CLI, and TUI /project command</name>
  <files>
    src/harness_core/cli.py
    src/harness_core/tui.py
  </files>
  <action>
    1. In `src/harness_core/cli.py`:
       - Add `p_proj = sub.add_parser("project", help="Manage project workspace registry and daily switching")`:
         * Subcommands: `list`, `add`, `use`, `switch`.
         * `hex project list [--json]`: format table with columns `PROJECT`, `STACK`, `TASKS`, `LAST ACTIVE`, `PATH`.
         * `hex project add <path> [--name <name>]`: register directory as project and output JSON/text.
         * `hex project use <name|path>` / `hex project switch <name|path>`: set as active and display project configuration.
       - Implement workspace and data directory binding in `main()`:
         * If `--workspace` is explicitly passed: use it, register in `ProjectRegistry`, touch `last_active`, and set project data dir to `<workspace>/.hex/data` if exists.
         * If `--workspace` is NOT passed:
           - Call `registry.detect_enclosing_project(Path.cwd())`.
           - If enclosing project found:
             Bind `workspace_root = project.path`, set `data_dir = project.path / ".hex" / "data"`, touch `last_active`.
           - If NO enclosing project found (e.g. running from `$HOME` or outside any project) and `args.cmd in (None, 'chat', 'tui')`:
             If interactive terminal (`sys.stdin.isatty()`):
               * Display prompt: `What project do you want to work on today?`
               * Options:
                 1. List registered projects from `registry.list_projects()`:
                    `f"{proj.name} ({proj.stack} • {proj.path})"`
                 2. `("[+] Register an existing directory as project", "[+] Register an existing directory as project")`
                 3. `("[★] Initialize current directory as project", f"[★] Initialize current directory ({Path.cwd().name}) as project")`
               * Use `select_option` from `ui_selector.py`.
               * If registered project chosen: bind workspace to that project.
               * If register existing chosen: prompt for directory path, register, and bind.
               * If initialize current chosen: call `init_project(Path.cwd())` and bind.
             If non-interactive: fallback to `repo_root` or default directory.

    2. In `src/harness_core/tui.py`:
       - Add `_cmd_project(self, arg: str = "")`:
         * If `arg` is empty: print current active project card (name, path, stack, lessons count, data dir).
         * If `arg` is `list`: print all registered projects from `ProjectRegistry`.
         * If `arg.startswith("switch ")` or `arg`: lookup target project, switch `self.workspace_root` and rebind AST graphify and reflections memory.

    AVOID: Prompting the daily switcher when the operator is already inside a git or `.hex` project directory. Inside a project, HEX must bind silently and immediately.
  </action>
  <verify>
    python3 -c "import subprocess; out = subprocess.check_output(['hex', 'project', 'list', '--json'], text=True); print(out)"
  </verify>
  <done>
    `hex project` CLI commands function cleanly, daily project switcher activates only when outside a project, and TUI `/project` allows inspecting and switching workspace context.
  </done>
</task>
