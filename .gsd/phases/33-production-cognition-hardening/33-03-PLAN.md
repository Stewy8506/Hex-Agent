# Plan 33.03: Durable Lifecycle & Idle Reflection Workers (Fixes F-02, F-05, F-06)

<objective>
Fix memory lifecycle and transactional execution gaps by enforcing strict archive-before-delete semantics and wiring promotion/demotion into production runtime state transitions (F-02), implementing all-or-nothing transactional batch mutations in `CuratedMemoryStore.execute_operations()` with disk deletion verification (F-05), and building an idle reflection worker that drains queued candidates from `.hex/reflections/pending_reflections.json` (F-06).

Purpose: Guarantee zero data loss during memory decay, maintain metadata-to-disk consistency across multi-step contradiction resolution, and make the autonomous learning loop truly close when the system is idle.
Output: Updated `memory.py`, `orchestrator.py`, and test suite in `tests/cognition/test_durable_lifecycle_and_reflection.py`.

  <name>Task 1: Enforce archive-before-delete in `run_demotion_sweep()`; add unique constraints to `archive.db`; wire lifecycle maintenance into orchestrator/daemon lifecycle (Fixes F-02)</name>
  <files>src/harness_core/memory.py, src/harness_core/orchestrator.py, tests/cognition/test_durable_lifecycle_and_reflection.py</files>
  <action>
    Fix Audit Finding F-02 across memory archival, demotion, and runtime scheduling:
    1. In `src/harness_core/memory.py`:
       - Harden SQLite cold archive in `MemoryLifecycleManager`:
         - Schema: Ensure `archived_memories` has `memory_id TEXT PRIMARY KEY` (unique constraint).
         - In `archive_entry()`:
           - Execute within an explicit database transaction.
           - Delete any prior matching row in `archived_memories_fts` before inserting into FTS5:
             `DELETE FROM archived_memories_fts WHERE memory_id = ?;`
           - Return `True` only after transaction successfully commits; catch any database error, log error, and return `False`.
       - Enforce archive-before-delete in `run_demotion_sweep(retention_days=30)`:
         - Capture `archived_ok = self.archive_entry(...)`.
         - If `not archived_ok`:
           - Log error: `"Archive failed for memory %s; retaining in active markdown store"`.
           - Do NOT call `self.controller.delete_memory()`. Active memory is strictly preserved!
         - If `archived_ok is True`:
           - Proceed to `del_res = self.controller.delete_memory(item.id, target=item.scope)`.
           - Only append to demoted list if deletion succeeds.
    2. In `src/harness_core/orchestrator.py`:
       - Wire promotion checks into task completion:
         - At the end of `_execute_standard_dag()` after a task completes successfully:
           - Call `self.memory.lifecycle_mgr.check_promotions()` to automatically promote reflected lessons with $\ge 3$ hits to `MEMORY.md`.
       - Add lifecycle maintenance helper `run_lifecycle_maintenance(workspace_root)`:
         - Executes `run_demotion_sweep()` on workspace open or session teardown.
    3. In `tests/cognition/test_durable_lifecycle_and_reflection.py`:
       - Test archive failure injection: mock `archive_entry` returning False; verify that note remains in `MEMORY.md` / `USER.md` and metadata is not removed.
       - Test idempotency: re-archiving an existing memory updates the row and does not duplicate rows in `archived_memories_fts`.
       - Test promotion execution: note with 3 hits promotes automatically on task completion.
    AVOID: Deleting active memory items before verifying that cold archival committed; avoid duplicate rows in FTS5 on archive retry.
  </action>

<task type="auto">
  <name>Task 2: Transactional multi-operation execution in `CuratedMemoryStore.execute_operations()` with rollback on failure; check `remove()` disk result in `delete_memory()` (Fixes F-05)</name>
  <files>src/harness_core/memory.py, tests/cognition/test_durable_lifecycle_and_reflection.py</files>
  <action>
    Fix Audit Finding F-05 across batch memory mutations and deletion verification:
    1. In `src/harness_core/memory.py`:
       - In `CuratedMemoryStore.execute_operations(target, operations)`:
         - Acquire target file locks in deterministic order.
         - Read original contents of all target files and create in-memory staging copies and rollback snapshots.
         - Simulate and validate the entire sequence of operations against the in-memory staging state:
           - Check that `add` content fits within the target's character budget.
           - Check that `replace` and `patch` find their `old_text` exactly and the replacement fits the character budget.
           - Check that `remove` finds the text to be deleted.
         - If any operation fails validation or budget constraints:
           - Abort immediately without modifying any physical files on disk.
           - Return `{"ok": False, "success": False, "error": error_msg, "failed_op": op}`.
         - If all operations pass validation:
           - Atomically write all affected staged files to disk (writing to `.tmp` and renaming).
           - If a disk write exception occurs during multi-file updates, restore previously written files from rollback snapshots before raising.
       - In `AMEMController.delete_memory(item_id, target)`:
         - Inspect the return dictionary from `res = self.store.remove(old_text=target_item.text, target=scope)`.
         - If `not res.get("ok")`:
           - Do NOT remove item from `self._items` or `self._tag_index`.
           - Do NOT save metadata.
           - Return `{"ok": False, "success": False, "error": f"Failed to remove memory from physical store: {res.get('error')}"}`.
         - Only remove in-memory items and save metadata if the physical file removal succeeded.
    2. In `tests/cognition/test_durable_lifecycle_and_reflection.py`:
       - Test transactional rollback: submit a batch of 2 operations where Op 1 is valid and Op 2 fails (e.g. exceeds budget or invalid old_text); verify that Op 1 is NOT committed to disk and file content is unchanged.
       - Test deletion disk check: mock `store.remove()` returning failure; assert `delete_memory()` fails and item remains present in `_items` and `_tag_index`.
    AVOID: Incrementally writing partial batch mutations to disk; avoid mutating in-memory metadata when physical disk delete fails.
  </action>
  <verify>.venv/bin/pytest tests/cognition/test_durable_lifecycle_and_reflection.py -k "test_batch_transaction_rollback or test_delete_memory_disk_check" -v</verify>
  <done>CuratedMemoryStore executes batch operations transactionally with full rollback, and AMEMController verifies physical disk delete before pruning metadata.</done>
</task>

<task type="auto">
  <name>Task 3: Implement idle reflection worker to drain `.hex/reflections/pending_reflections.json` when system is idle (Fixes F-06)</name>
  <files>src/harness_core/orchestrator.py, tests/cognition/test_durable_lifecycle_and_reflection.py</files>
  <action>
    Fix Audit Finding F-06 by implementing the idle reflection worker:
    1. In `src/harness_core/orchestrator.py`:
       - Implement `process_pending_reflections(workspace_root: Path | str, is_idle: bool = True, max_items: int = 5) -> dict[str, Any]`:
         - Read `.hex/reflections/pending_reflections.json` under file lock.
         - Filter items with `status == "pending"`.
         - If no pending items or `is_idle` is False (and policy is `idle`), return immediately.
         - For each pending candidate:
           - Re-evaluate `should_execute_background_reflection(policy, router, is_idle=is_idle)`. If not allowed, break or stop.
           - Mark item `status = "processing"`.
           - Invoke `ReflectionSynthesizer.synthesize_lesson()` using candidate's `task_id`, `goal`, `error_traces`, `final_patch`, `modified_files`, and `source_nodes`.
           - Append lesson to `LESSONS.md`, register reflection with memory lifecycle manager, and update guardrails if applicable.
           - Mark item `status = "completed"` with `synthesized_at` timestamp.
           - If synthesis fails with exception, mark `status = "failed"` with error message and increment `retry_count`. Skip items with `retry_count >= 3`.
         - Save updated `pending_reflections.json` atomically.
         - Return summary `{"processed": count, "completed": completed_ids, "failed": failed_ids}`.
       - Add method `check_and_run_idle_workers(workspace_root)` called when the orchestrator is in an idle state (e.g. no active running tasks or in daemon idle ticks).
    2. In `tests/cognition/test_durable_lifecycle_and_reflection.py`:
       - Test idle worker execution: create pending candidates in `pending_reflections.json`; invoke `process_pending_reflections(..., is_idle=True)`; assert candidates are processed into `LESSONS.md` and marked `completed`.
       - Test non-idle gate: with `auto_reflect: idle`, calling `process_pending_reflections(..., is_idle=False)` leaves pending items untouched.
       - Test retry ceiling: candidate failing 3 times is not repeatedly retried.
    AVOID: Leaving pending reflections orphaned in pending_reflections.json without a worker to synthesize them; avoid running idle reflection when system is busy.
  </action>
