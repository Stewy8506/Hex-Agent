# Plan 33.01: Execution Gates & Session Isolation (Fixes F-01, F-04, F-08)

<objective>
Harden the execution boundary by wiring deterministic skill `verify:` hooks into the orchestrator task completion flow with sandbox isolation, minimal environments, and SkillSpector hash verification (F-01), while isolating Turn-0 memory snapshots per `session_id` (F-04), strictly enforcing the `MAX_SOUL_CHARS` budget cap, and recognizing user-authored workspace soul provenance (F-08).

  <files>skill_engine/executor.py, harness_core/skillspector.py, harness_core/orchestrator.py, tests/skills/test_skill_verification_wiring.py</files>
  <action>
    Fix Audit Finding F-01 across skill execution and orchestrator completion:
    1. In `skill_engine/executor.py`:
       - Update `SkillExecutionEngine.run_skill_verification()`:
         - Accept `sandbox: Optional[Any] = None` and `skill_bundle_dir: Optional[Path | str] = None`.
         - Replace `env = os.environ.copy()` with a strict minimal allowlist: only inherit safe system variables (`PATH`, `HOME`, `TMPDIR`, `USER`, `LANG`, `LC_ALL`, `TERM`). Explicitly strip and exclude all AI provider keys (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`), cloud credentials, database connection strings, SSH configuration, and tokens.
         - If `sandbox` is supplied (an instance of `BaseSandbox` or compatible), execute the hook command through the sandbox's `execute()` or `run_command()` confined to `workspace_root` rather than unconfined `subprocess.run(shell=True)`.
         - Bundle Hash Verification: If `skill_bundle_dir` is provided, compute the candidate bundle hash (SHA-256 of `SKILL.md` and referenced files) and verify against the record approved by `SkillSpectorScanner`. If the hash does not match approved registration or the skill is unvetted, refuse execution and raise `SecurityError("Skill bundle hash mismatch or unapproved skill")`.
    2. In `harness_core/orchestrator.py`:
       - Add a post-edit skill verification integration point in `_execute_standard_dag()` during the `VERIFYING` phase (around lines 1800-1840, alongside LSP preflight and proof service):
         - Identify skills referenced or utilized by the current task (from task constraints, plan metadata, or active registered skills in `.hex/skills/` whose scope or AST nodes match the task's modified files).
         - For each referenced skill that defines a `verify:` hook:
           - Execute the hook via `SkillExecutionEngine.run_skill_verification` using `self.sandbox` (or default confined sandbox) and minimal environment.
           - If `hook.must_pass` is True and the hook execution fails (`passed == False`, non-zero exit code, timeout, or AST invariant failure):
             - Record `SKILL_VERIFICATION_FAILED` event in ledger with stdout/stderr details.
             - Mark `ver_outcome["passed"] = False` with `ver_outcome["verification_results"]["skill_verification"]` containing the failure output and error message.
             - This blocks transition to `SUCCEEDED` and escalates to the autonomous repair loop or `NEEDS_ATTENTION`.
    3. In `tests/skills/test_skill_verification_wiring.py`:
       - Test that `run_skill_verification` strips provider keys and sensitive environment variables.
       - Test that tampered skill bundle triggers hash verification failure.
       - Test end-to-end task completion: a task modifying code with an active `must_pass: true` skill hook fails verification if the hook fails, and succeeds if the hook passes.
    AVOID: Running `shell=True` on unconfined host processes with inherited credentials; avoid skipping verification when skills are present.
  </action>

    1. In `harness_core/memory.py`:
       - Update `MemorySnapshot.build_frozen_snapshot()` and `CuratedMemoryStore.get_frozen_turn0_snapshot()`:
         - Accept `session_id: Optional[str] = None`.
         - When `session_id` is passed, key the cache by `f"{ws}:{gh}:{session_id}"`.
         - Add `reset_session_snapshot(session_id: str)` and `clear_all_snapshots()`.
         - Ensure that within a single session, the snapshot remains 100% byte-frozen (preserving KV-cache stability), but a new session with a new `session_id` immediately hydrates the latest contents of `USER.md`, `MEMORY.md`, and `GUARDRAILS.md`.
    2. In `harness_core/orchestrator.py` & `harness_core/prompt_builder.py`:
       - Pass `session_id` (task_id or session UUID) into `PromptBuilder.build_system_prompt(..., session_id=session_id)`.
       - Slot #4 fetches the session-isolated snapshot for `session_id`.
    3. In `harness_core/soul.py`:
       - Fix `_enforce_budget()`:
         - Define `TRUNCATION_MARKER = "\n... [truncated to fit 500-token budget]"`.
         - If `len(content) > MAX_SOUL_CHARS`:
           - Calculate `keep_len = MAX_SOUL_CHARS - len(TRUNCATION_MARKER)`.
           - Return `content[:keep_len].rstrip() + TRUNCATION_MARKER`.
         - Ensure `len(result) <= MAX_SOUL_CHARS` unconditionally holds true.
       - Introduce explicit soul provenance types (`SoulProvenance`): `global_user`, `workspace_user`, `repository`, `remote_profile`, `distribution`.
       - In `resolve_soul()`: A `.hex/SOUL.md` located in the local workspace is tagged with provenance `workspace_user` (or `repository` if committed template).
    4. In `harness_core/prompt_builder.py`:
       - Update Slot #1 soul scanning:
         - Check provenance: if `provenance in ("global_user", "workspace_user")`, mark `user_authored=True`.
         - Local workspace souls authored by the user generate warnings on heuristic injection patterns rather than being hard-blocked like third-party distribution profiles.
    5. In `tests/cognition/test_session_isolated_snapshots.py`:
       - Test two sessions in the same process: mutate `MEMORY.md` between sessions; assert Session A retains frozen memory while Session B gets the updated memory.
       - Test that `_enforce_budget` guarantees length `<= MAX_SOUL_CHARS` even after suffixing.
       - Test that user-authored `.hex/SOUL.md` in workspace is classified as `workspace_user` and treated as user-authored.
    AVOID: Allowing truncated soul strings to exceed MAX_SOUL_CHARS; avoid process-global memory snapshot sharing across distinct sessions.
