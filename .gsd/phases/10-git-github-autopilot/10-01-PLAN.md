<task type="auto">
  <name>Implement Git Autopilot Engine, Pluggable GitHub Transports & PR Formatter</name>
  <files>src/harness_core/git_autopilot.py</files>
  <action>
    Create `src/harness_core/git_autopilot.py`:
    1. Configuration dataclass `GitAutopilotConfig`:
       - `author_name: str = "hex-bot"`
       - `author_email: str = "hex-bot@users.noreply.github.com"`
       - `branch_prefix: str = "hex/"`
       - `default_base_branch: str = "main"`
       - `github_token: str | None = None`
       - `repo_slug: str | None = None` (e.g. "owner/repo")
       - `dry_run: bool = False`
       - `from_env() -> GitAutopilotConfig`: parses `HEX_GITHUB_TOKEN` / `GITHUB_TOKEN`, `HEX_GIT_AUTHOR_NAME`, `HEX_GIT_AUTHOR_EMAIL`, `HEX_GIT_BRANCH_PREFIX`, `HEX_GITHUB_REPOSITORY` / `GITHUB_REPOSITORY`, and `HEX_GIT_DEFAULT_BASE`.
    2. GitHub Transport Abstraction:
       - `GitHubTransport` (protocol or ABC):
         - `create_pull_request(repo_slug: str, title: str, body: str, head_branch: str, base_branch: str) -> dict[str, Any]`
         - `post_issue_comment(repo_slug: str, issue_number: int, body: str) -> dict[str, Any]`
         - `get_pull_request(repo_slug: str, pr_number: int) -> dict[str, Any]`
       - `SubprocessGitHubTransport`:
         - If `gh` CLI is installed and in PATH, executes `gh pr create --title ... --body ... --head ... --base ...` or `gh issue comment ...`.
         - If `gh` CLI is unavailable but `github_token` is provided, executes GitHub REST API calls (`POST https://api.github.com/repos/{owner}/{repo}/pulls`, `POST https://api.github.com/repos/{owner}/{repo}/issues/{issue_number}/comments`) via `urllib.request` with `Authorization: Bearer <token>` and `Accept: application/vnd.github+json`.
         - Gracefully captures subprocess/network errors and returns informative status dictionaries.
       - `MockGitHubTransport`:
         - In-memory mock tracking calls (`created_prs`, `comments`, etc.). Returns customizable responses `{"number": 101, "html_url": "https://github.com/owner/repo/pull/101", "status": "created"}`.
    3. `GitAutopilot` engine class:
       - `__init__(self, workspace_root: Path | str, config: GitAutopilotConfig | None = None, transport: GitHubTransport | None = None)`
       - `slugify(text: str, max_length: int = 30) -> str`: converts text to lowercase alphanumeric with single hyphens, stripped at edges.
       - `create_task_branch(task_id: str, goal: str, base_branch: str | None = None) -> str`:
         - Clean task ID: removes `task_` prefix or non-alphanumeric chars.
         - Generates branch name: `{config.branch_prefix}task-{clean_id}-{slug}`.
         - If not in `dry_run` mode and workspace is a git repo: runs `git checkout -b <branch>` (or `git checkout -B` if existing).
         - Returns branch name.
       - `commit_task_changes(task_id: str, scope: str, description: str, files: list[str] | None = None, commit_type: str = "feat") -> str`:
         - Validates conventional commit format: `<commit_type>(<scope>): <description>\n\nTask-ID: <task_id>\nAutomated-By: HEX Autonomous Workbench`.
         - If `dry_run` is True: returns mock commit SHA `mock-sha-{task_id[:8]}`.
         - Otherwise: runs `git add <files>` (or `git add -A`), runs `git commit` with `--author="{config.author_name} <{config.author_email}>" -m "{message}"`.
         - Retrieves and returns the created commit SHA via `git rev-parse HEAD`.
       - `generate_pr_summary(task_id: str, goal: str, proof_bundle: dict[str, Any] | None = None, ast_impact: dict[str, Any] | None = None) -> str`:
         - Formats rich Markdown PR body:
           - `## 🤖 HEX Automated Pull Request`
           - `### 🎯 Objective`: blockquote of `goal`.
           - `### 📋 Summary of Changes`: summary description with commit/task reference.
           - `### 🔍 Active Graphify AST Impact Matrix`:
             - Table: `| Symbol / File | Impact Kind | Affected Callers / Tests | Risk Class |`
             - Populated from `ast_impact` (modified symbols, 1-hop/2-hop callers, pinned tests).
           - `### 🛡️ Proof-Carrying Artifact Verification`:
             - Table: `| Metric | Verification Value |`
             - Rows for Diff SHA-256, Merkle Tree SHA-256, Verification Status (`✅ Passed`), Exit Code, Tests Run, Runtime Digest, and Ledger Signature excerpt.
           - Footer with Task ID, timestamp, and signature reference.
       - `create_pull_request(branch: str, title: str, body: str, base: str | None = None) -> dict[str, Any]`:
         - Uses `self.transport.create_pull_request(self.config.repo_slug, title, body, head_branch=branch, base_branch=base or self.config.default_base_branch)`.
         - Returns metadata dict with `number`, `url`, `status`.

    AVOID: Shell injection or executing arbitrary shell strings with `shell=True`. Always invoke subprocesses with argument lists (`["git", "checkout", "-b", branch]`).
  </action>

<task type="auto">
  <name>Wire `hex run` and `hex exec` CLI Commands with `--pr` and `--branch` Auto-Git Flags</name>
  <files>src/harness_core/cli.py</files>
  <action>
    Update `src/harness_core/cli.py` to integrate Git Autopilot workflows:
    1. Add `run` subcommand with alias `exec` to argparse subparsers (preserving existing `submit` subcommand for backward compatibility):
       - `goal`: required positional argument (description of task goal).
       - `--project`: project ID (default "default").
       - `--mode`: choices `["auto", "fast_path", "standard"]` (default "auto").
       - `--workspace`: path to repository workspace (default repository root).
       - `--branch`: optional custom branch name or auto-generated if `--branch` / `--pr` specified.
       - `--pr`: boolean flag (`action="store_true"`), automatically creates a PR on task success.
       - `--base-branch`: base branch for PR (default "main").
       - `--dry-run`: boolean flag (`action="store_true"`), runs git and GitHub operations in mock/dry-run mode without external mutations.
    2. In the CLI execution handler for `run` / `exec`:
       - If `--pr` or `--branch` is requested:
         - Instantiate `GitAutopilotConfig` with `dry_run=args.dry_run`, `default_base_branch=args.base_branch`, etc.
         - Instantiate `GitAutopilot(workspace_root=workspace, config=cfg)`.
         - Generate task branch: `branch = args.branch if (args.branch and args.branch is not True) else autopilot.create_task_branch(task_id_placeholder, args.goal)`.
       - Execute task via `orch.submit_and_run(req, auto_execute=True)`.
       - If task succeeds:
         - If `--branch` or `--pr` was specified:
           - Retrieve proof bundle from `orch.ledger.get_proof_bundle(task["task_id"])`.
           - Switch/create the actual task branch if not already created.
           - Commit changes via `autopilot.commit_task_changes(task_id=task["task_id"], scope=args.project, description=args.goal)`.
           - If `--pr` is specified:
             - Generate PR summary markdown via `autopilot.generate_pr_summary(task["task_id"], args.goal, proof_bundle, proof_bundle.get("ast_impact"))`.
             - Call `autopilot.create_pull_request(branch=branch, title=f"feat({args.project}): {args.goal}", body=summary, base=args.base_branch)`.
             - Print JSON output containing task, proof, branch, commit, and PR metadata.
           - Else:
             - Print JSON output containing task, proof, branch, and commit.
         - Else (neither `--branch` nor `--pr` specified):
           - Print standard JSON output `{"task": task, "proof": proof}`.
       - If task fails:
         - Print failure JSON without committing or opening PR.
         - Return non-zero exit code (1).

    AVOID: Creating or pushing git branches if task verification fails or if tests are broken. Git operations must only execute on verified successful tasks.
  </action>

  </verify>
