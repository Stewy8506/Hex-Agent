  <name>Implement GitHub Action Configuration, Event Dispatcher & Bot Trigger Parser</name>
  <files>src/harness_core/github_action.py</files>
  <action>
    Create `src/harness_core/github_action.py`:
    1. Dataclass `GitHubActionConfig`:
       - `event_name: str = ""`
       - `event_path: str | Path = ""`
       - `token: str | None = None`
       - `repository: str = ""` (e.g., "owner/repo")
       - `ref: str | None = None` (e.g., "refs/heads/feature" or "refs/pull/42/merge")
       - `sha: str | None = None`
       - `bot_names: set[str] = field(default_factory=lambda: {"@hex-bot", "/hex", "@hex"})`
       - `dry_run: bool = False`
       - `from_env() -> GitHubActionConfig`: parses standard GitHub Actions environment variables (`GITHUB_EVENT_NAME`, `GITHUB_EVENT_PATH`, `GITHUB_TOKEN` / `HEX_GITHUB_TOKEN`, `GITHUB_REPOSITORY`, `GITHUB_REF`, `GITHUB_SHA`, `HEX_BOT_NAMES`, `HEX_DRY_RUN`).
    2. Dataclass `TriggerMatch`:
       - `matched: bool`
       - `trigger_type: str` ("mention", "slash_command", "label", "dispatch")
       - `command: str` ("fix", "run", "explain", "review", or "custom")
       - `instruction: str` (the extracted task goal to execute)
       - `author: str` (GitHub username of the comment/event author)
       - `issue_number: int | None = None`
       - `pr_number: int | None = None`
       - `branch: str | None = None`
       - `head_sha: str | None = None`
    3. Engine class `GitHubActionRunner`:
       - `__init__(self, config: GitHubActionConfig, transport: GitHubTransport | None = None, autopilot: GitAutopilot | None = None)`
       - `parse_event_payload(self, raw_payload: str | bytes | dict) -> dict[str, Any]`:
         - Parses JSON string or dict safely.
       - `detect_trigger(self, event_name: str, payload: dict[str, Any]) -> TriggerMatch | None`:
         - Case `issue_comment`:
           - Extracts `comment.body`, `comment.user.login`.
           - Determines if issue or PR: checks `issue.pull_request` presence.
           - Checks comment body for bot triggers (`@hex-bot <cmd> <instruction>`, `/hex <cmd> <instruction>`, `@hex <cmd> <instruction>`).
           - If matched: extracts command (e.g. "fix") and remaining text as instruction. Returns `TriggerMatch`.
           - If no bot mention found: returns `None` (graceful skip).
         - Case `pull_request`:
           - Checks `action` (`opened`, `synchronize`, `labeled`).
           - Checks title/body or label for bot instructions.
         - Case `issues`:
           - Checks `action` (`opened`, `labeled`).
           - Checks title/body or label for bot instructions.
         - Case `workflow_dispatch`:
           - Extracts `inputs.goal` or `inputs.task` as instruction.
         - Default: returns `None` for unhandled events.

    AVOID: Crashing or failing when receiving unrecognized events or comment bodies that do not mention the bot. The runner must quietly return None to allow standard non-bot comments to pass without errors.
  </action>

<task type="auto">
  <name>Implement CoW Task Execution, Comment Response with Proof Bundle & CLI Subcommand `hex gh-action`</name>
  <files>src/harness_core/github_action.py, src/harness_core/cli.py</files>
  <action>
    1. In `src/harness_core/github_action.py`, implement full action execution cycle:
       - `format_ack_comment(self, trigger: TriggerMatch) -> str`:
         - Formats markdown acknowledgement comment:
           `🤖 **HEX Autopilot Activated**\n\nTask acknowledged from @{trigger.author}. Running verification inside isolated CoW workspace...`
       - `format_completion_comment(self, trigger: TriggerMatch, task: dict[str, Any], proof_bundle: dict[str, Any] | None, ast_impact: dict[str, Any] | None) -> str`:
         - Formats comprehensive markdown response:
           - Header: `## 🤖 HEX Task Succeeded`
           - Instruction: `> {trigger.instruction}`
           - Active Graphify AST Impact Matrix table.
           - Proof-Carrying Artifact verification bundle table (Merkle tree SHA, test result, runtime digest).
           - Conventional commit and branch details if committed/pushed.
       - `format_failure_comment(self, trigger: TriggerMatch, task: dict[str, Any] | None, error_message: str) -> str`:
         - Formats clean error response with task trace and diagnostics.
       - `execute_action(self, orchestrator: HarnessOrchestrator, event_name: str, payload: dict[str, Any]) -> dict[str, Any]`:
         - 1. Runs `trigger = self.detect_trigger(event_name, payload)`.
         - 2. If `trigger is None`: returns `{"status": "skipped", "reason": "No bot trigger detected in event payload"}`.
         - 3. Posts initial acknowledgement comment via `self.transport.post_issue_comment(...)` if `issue_number` or `pr_number` is available and not in dry-run mode.
         - 4. Submits task to `orchestrator.submit_and_run(TaskSubmitRequest(goal=trigger.instruction, project_id=self.config.repository or 'gh-action'))`.
         - 5. If task succeeds:
           - Fetches `proof_bundle` from `orchestrator.ledger.get_proof_bundle(task["task_id"])`.
           - If git repo available, uses `GitAutopilot` to commit task changes.
           - Formats completion comment with AST impact and proof bundle.
           - Posts response comment via `self.transport.post_issue_comment(...)`.
           - Returns `{"status": "completed", "task_id": task["task_id"], "proof": proof_bundle, "trigger": trigger}`.
         - 6. If task fails:
           - Formats failure comment and posts to issue/PR.
           - Returns `{"status": "failed", "task_id": task.get("task_id"), "error": "Task verification failed"}`.
    2. In `src/harness_core/cli.py`, add `hex gh-action` subcommand:
       - Subcommand arguments:
         - `--event-path`: path to GitHub event JSON file (defaults to `GITHUB_EVENT_PATH` env var).
         - `--event-name`: GitHub event name (defaults to `GITHUB_EVENT_NAME` env var).
         - `--dry-run`: simulate git push and comment posting without external network calls.
         - `--workspace`: path to repository workspace.
         - `--data-dir`: path to local HEX ledger and CoW storage.
       - Handler in `main()`:
         - Loads event JSON from `--event-path` or stdin.
         - Initializes `GitHubActionConfig` and `GitHubActionRunner`.
         - Calls `runner.execute_action(orch, event_name, payload)`.
         - Prints JSON output. If `status == "failed"`, returns exit code 1; otherwise returns 0.

    AVOID: Emitting unredacted tokens or internal paths in posted GitHub comments. All comment bodies must pass through secret redaction.
  </action>

  </verify>

    CoW task execution, proof bundle comment posting, and `hex gh-action` CLI subcommand are implemented in `src/harness_core/github_action.py` and `src/harness_core/cli.py`.
