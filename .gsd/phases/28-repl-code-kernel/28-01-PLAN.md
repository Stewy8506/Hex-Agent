# Plan 28.01: Persistent In-Memory Python CodeKernel & KernelRegistry Engine Core

<objective>
Implement the persistent REPL code kernel engine in `src/harness_core/code_kernel.py` matching the Hermes Agent reference (`benchmarks/hermes-agent/tools/code_kernel.py`). This delivers an isolated, persistent child Python subprocess that maintains execution state (variables, functions, imports) across consecutive calls within a workspace directory, communicates via a secure sentinel framed protocol over stdin/stdout, enforces a 1 MB output cap with disk spill fallback, tracks stale modules modified on disk after import, terminates wedged processes via SIGKILL on execution timeout, and manages kernel lifecycles via a thread-safe, bounded `KernelRegistry`.

Purpose: Enable multi-turn code execution where models and developers can inspect data, define helper routines, train intermediate structures, and interactively iterate across consecutive turns without re-running initialization code or losing runtime state.
Output: Core module `src/harness_core/code_kernel.py` and comprehensive unit test suite `tests/test_code_kernel.py`.
</objective>

  <name>Task 1: Runner Script, Framed Protocol & Persistent CodeKernel Subprocess Engine</name>
  <files>
    src/harness_core/code_kernel.py

  <action>
    Create `src/harness_core/code_kernel.py` with the child runner generator, framed wire protocol, and `CodeKernel` subprocess supervisor:

    1. Define `KERNEL_RUNNER_SOURCE` template string (matching Hermes `KERNEL_RUNNER_SOURCE` / `RUNNER_CELL_SOURCE`):
       - Runner maintains persistent `GLOBALS = {"__name__": "__main__", "__builtins__": __builtins__}`.
       - Read JSON request line from `sys.stdin`: `{"id": str, "code": str}`.
       - In-memory output redirection via `contextlib.redirect_stdout` and `contextlib.redirect_stderr`.
       - Output clipping: `_CAPTURE_LIMIT = 1_000_000` (1 MB cap). If output exceeds cap, clip text and set `clipped = True`.
       - Disk spill: If stdout is clipped and `HEX_KERNEL_SPILL_DIR` is set, write full unclipped output up to 5 MB into `cell_XXXXXX_stdout.txt` in the spill directory.
       - Stale module tracking: `_scan_edited_modules(report: bool)` scans `sys.modules`, filters out stdlib (`os.path.dirname(os.__file__)`) and `site-packages` / `dist-packages`. Stores `_MODULE_RECORDS[name] = (mtime_ns, spec)`. When `report=True`, detects modules whose file mtime changed while the import spec remained identical, returning a list of edited module names.
       - Wire protocol framing: writes framed response to `sys.stdout.buffer` using sentinel:
         `b"\n" + sentinel.encode() + b" " + str(len(body)).encode() + b"\n" + body`.
       - Catches `SystemExit` (status: `"exit"`) and `BaseException` (status: `"error"`, formats traceback).

    2. Implement `_BoundedBuffer`:
       - Thread-safe byte buffer capping total stored bytes at `cap` (default 1 MB).
       - Method `append(data: bytes, cap: int) -> None`.
       - Method `drain() -> str`: decodes accumulated bytes to UTF-8 with `errors="replace"` and clears buffer.

    3. Implement `CodeKernel` (SessionKernel child manager):
       - Fields: `kernel_id: str`, `owner: str`, `cwd: str`, `tmpdir: str`, `sentinel: str`, `proc: subprocess.Popen | None`, `response_q: queue.Queue`, `raw_buffer: _BoundedBuffer`, `stderr_buffer: _BoundedBuffer`, `execution_count: int`, `last_used: float`, `lock: threading.Lock`.
       - Method `spawn()`:
         - Creates isolated temporary directory `tempfile.mkdtemp(prefix="hex_kernel_")`.
         - Writes `hex_kernel_runner.py` into `tmpdir`.
         - Generates random cryptographic sentinel: `"@@HEX-KERNEL-" + secrets.token_urlsafe(16) + "@@"`.
         - Builds child environment with `HEX_KERNEL_SENTINEL` and `HEX_KERNEL_SPILL_DIR = tmpdir`.
         - Spawns subprocess using `sys.executable` running `hex_kernel_runner.py` with `stdin=PIPE, stdout=PIPE, stderr=PIPE`, working directory `cwd`.
         - Starts background daemon threads:
           - `_stdout_reader`: reads chunks from `proc.stdout`, splits into sentinel framed responses (parsing JSON payload and putting into `response_q`) and non-framed raw stdout (appended to `raw_buffer`).
           - `_stderr_reader`: reads chunks from `proc.stderr` and appends to `stderr_buffer`.
       - Method `execute(code: str, timeout: float = 30.0) -> dict[str, Any]`:
         - If process is not alive, calls `spawn()`.
         - Increments `execution_count`, updates `last_used`.
         - Sends JSON line `json.dumps({"id": req_id, "code": code}) + "\n"` to `proc.stdin`.
         - Waits on `response_q.get(timeout=0.05)` until response arrives or `deadline = time.monotonic() + timeout` is exceeded.
         - On timeout: forcefully terminates process tree (`proc.terminate()`, wait 0.5s, `proc.kill()`), closes pipes, drains buffers, and returns status `"timeout"`.
         - On clean response: returns dictionary with:
           `status`, `stdout`, `stderr`, `execution_count`, `stale_modules`, `stdout_spill_path`, `traceback`, `duration_seconds`.
       - Method `reset()`:
         - Terminates active child process if alive, cleans up `tmpdir`, and clears buffers.
         - Spawns fresh runner process on next execution with clean `GLOBALS`.
       - Method `close()` / `teardown()`:
         - Terminates child process, cleans up temp directories, and marks kernel closed.

    AVOID: Blocking the host process on child stdout reads or leaking zombie child processes.
    USE: Buffered non-blocking chunk reads (`read1` or small chunk reads) and background listener threads.
  </action>

  </verify>
  <done>
    `CodeKernel` successfully spawns an isolated child Python process, executes code in a persistent `GLOBALS` namespace, captures stdout/stderr via sentinel framing, caps output at 1 MB, and handles sequential state retention across cells.
  </done>

<task type="auto">
  <name>Task 2: KernelRegistry, LRU / Idle Eviction, Stale Warning Formatter & Unit Test Suite</name>
  <files>

  <action>
    Implement `KernelRegistry` lifecycle management, stale module helper, and full unit test suite:

    1. Implement `KernelRegistry` in `src/harness_core/code_kernel.py`:
       - Thread-safe kernel storage `self._kernels: dict[tuple[str, str], CodeKernel]` keyed by `(owner, cwd)`.
       - Configurable limits: `max_kernels = 4`, `idle_timeout = 1800` (seconds).
       - Method `get_or_create(owner: str, cwd: str, reset: bool = False) -> tuple[CodeKernel, bool]`:
         - Thread-locked check for existing kernel.
         - If `reset=True` or existing kernel is dead (`not kernel.alive()`), discards old kernel and flags `state_reset = True`.
         - If kernel does not exist, instantiates new `CodeKernel` and registers it.
         - Enforces LRU capacity: if count of unpinned kernels exceeds `max_kernels`, evicts oldest idle kernels.
         - Sweeps expired idle kernels past `idle_timeout`.
         - Returns `(kernel, state_reset)`.
       - Method `discard(owner: str, cwd: str) -> None`: removes and tears down matching kernel.
       - Method `shutdown(owner: str | None = None) -> None`: tears down all kernels or all kernels belonging to `owner`.
       - Background idle reaper thread: periodically runs sweep every `min(300, max(30, idle_timeout / 6))` seconds.
       - Helper `stale_modules_warning(stale_modules: list[str]) -> str`: formats model-friendly advisory pointing out that files were modified on disk after import and suggesting `importlib.reload(...)` or `reset=True`.
       - Global singleton accessors: `get_kernel_registry()` and `reset_kernel_registry()`.
       - Register `atexit.register` to call `shutdown()` on host process exit.

    2. Authored comprehensive unit test suite in `tests/test_code_kernel.py`:
       - `test_cross_call_variable_persistence`: define variables/functions in cell 1, read/invoke them in cell 2.
       - `test_stdout_and_stderr_separation`: verify `sys.stdout.write` and `sys.stderr.write` land in separate output fields.
       - `test_output_capping_and_spill`: execute cell generating >1 MB output; verify output is clipped to 1 MB and `stdout_spill_path` points to readable on-disk file containing full output.
       - `test_stale_module_detection`: create a temporary python module file, import it in cell 1, modify module file on disk, run cell 2, and verify module name is reported in `stale_modules`.
       - `test_execution_timeout_kills_process`: run infinite loop or sleep exceeding timeout; verify kernel reports timeout, terminates child process, and next execution recovers in a fresh kernel.
       - `test_kernel_reset_clears_state`: verify variable present before `reset()` raises `NameError` after reset.
       - `test_registry_isolation_and_lru_eviction`: verify kernels with distinct `(owner, cwd)` do not share variables, and verifying LRU eviction when exceeding `max_kernels`.
       - `test_syntax_and_runtime_exception_formatting`: verify tracebacks are cleanly returned without breaking kernel subprocess.
  </action>
