# Plan 37-03: Temporal Approval Leasing & Mobile Reaction Bridge

<objective>
Implement temporal approval leasing (`approval_lease.py`) for safe command prefixes and directories with time-to-live (TTL) expiration, alongside an asynchronous mobile reaction listener bridge (`reaction_listener.py`) enabling remote approval workflows from Discord and Telegram with fallback timeouts.
</objective>

<tasks>
<task>
<name>1. Implement Temporal Approval Leasing Engine</name>
<files>
agent/approval_lease.py
agent/__init__.py
storage/db.py
agent/react_loop.py
hex_cli/tui.py
tests/core/test_approval_lease.py
</files>
<action>
1. Create `agent/approval_lease.py`:
   - Define `ApprovalLease`:
     - Fields: `lease_id`, `task_id`, `command_prefix`, `allowed_paths`, `granted_at`, `ttl_seconds`, `expires_at`, `scope` (`"session"` | `"temporal"`), `is_revoked`.
     - `is_valid() -> bool`: Returns `True` if `not is_revoked and time.time() < expires_at`.
   - Define `ApprovalLeaseManager`:
     - `grant_lease(command_prefix: str | None = None, allowed_paths: list[str] | None = None, ttl_seconds: int = 900, task_id: str | None = None) -> ApprovalLease`: Creates and registers an active lease with expiration timestamp.
     - `check_lease(tool_name: str, arguments: dict[str, Any]) -> tuple[bool, str | None]`:
       - Normalizes command or path arguments from tool invocations (`run_command`, `write_file`, etc.).
       - Matches command line against `command_prefix` (e.g. `pytest` matches `pytest tests/test_core.py -v`).
       - Matches file targets against `allowed_paths` (prefix directory matches).
       - Returns `(True, lease_id)` if an active valid lease covers the invocation; returns `(False, None)` otherwise.
     - `revoke_lease(lease_id: str) -> bool`: Explicitly revokes an active lease.
     - `cleanup_expired() -> int`: Prunes expired leases from memory and ledger.
     - `list_active_leases() -> list[ApprovalLease]`.
2. Enhance `LedgerStore` in `storage/db.py`:
   - Record granted and revoked leases in the `leases` table or ledger approvals log for audit traceability.
3. Integrate into `ToolGateway` / `ReActLoop` and `HexConsole`:
   - In `ReActLoop._execute_tool`: check `ApprovalLeaseManager.check_lease()`. If granted, record `policy_decision = "LEASE_APPROVED"` and proceed with 0ms delay, bypassing interactive prompt.
   - In `HexConsole`: add slash command `/lease [grant <prefix> [ttl] | list | revoke <id>]`.
4. Export `ApprovalLeaseManager` and `ApprovalLease` in `agent/__init__.py`.
5. Author comprehensive unit and integration tests in `tests/core/test_approval_lease.py`:
   - Lease creation with default and custom TTLs.
   - Command prefix matching (exact, flags, subcommands).
   - Path-based lease matching.
   - Expiration behavior: valid before TTL, rejected after TTL.
   - Explicit revocation and ledger audit persistence.
</action>
<verify>
pytest tests/core/test_approval_lease.py -v
</verify>
<done>
Temporal approval leasing grants time-bounded auto-approval for matched commands and paths, eliminates repetitive interactive prompts during valid TTL windows, and passes all unit tests.
</done>
</task>

<name>2. Implement Asynchronous Mobile Reaction Listener Bridge</name>
<files>

<action>
1. Create `capabilities/gateways/reaction_listener.py`:
   - Define `ApprovalRequest`: `request_id`, `task_id`, `tool_name`, `arguments`, `risk_class`, `created_at`, `timeout_seconds`.
   - Define `ApprovalDecision`: `decision` (`"APPROVE"` | `"DENY"` | `"TIMEOUT"`), `responder_id`, `platform`, `timestamp`.
   - Implement `MobileApprovalBridge`:
     - `request_approval_async(request: ApprovalRequest) -> ApprovalDecision`:
       - Dispatches structured approval notification cards to active Telegram and Discord chat channels.
       - Attaches interactive inline action buttons (`[Approve]`, `[Deny]`, `[View Diff]`) and listens for reaction emojis (thumbs up / thumbs down).
       - Creates a thread-safe `asyncio.Event` or `threading.Event` keyed by `request_id`.
       - Waits for resolution up to `request.timeout_seconds` (default 60s, configurable via `HEX_APPROVAL_TIMEOUT`).
       - On operator response from authorized user ID whitelist: marks event complete, logs decision provenance, and returns `ApprovalDecision`.
       - On timeout: withdraws pending message status, logs `TIMEOUT`, and safely returns `ApprovalDecision(decision="TIMEOUT")`.
2. Integrate with `TelegramBotGateway` and `DiscordBotGateway`:
   - Telegram: handles button callback queries (`approve:<req_id>`, `deny:<req_id>`) and message reactions; verifies user ID against `allowed_user_ids`.
   - Discord: handles button interaction components and reaction additions; verifies user ID against whitelist.
   - Updates message cards in-place with outcome badge (`[APPROVED by @user]`, `[DENIED by @user]`, `[TIMED OUT]`).
3. Wire into `ToolGateway` approval flow:
   - When an R2/R3 dangerous command requires human approval and remote gateways are running, invoke `MobileApprovalBridge.request_approval_async()`.
   - If bridge resolves with `APPROVE`, continue tool execution.
   - If bridge times out or resolves with `DENY`, fall back to standard local CLI prompt or reject cleanly without hanging the orchestrator.
4. Export `MobileApprovalBridge` in `capabilities/gateways/__init__.py`.
5. Author comprehensive integration tests in `tests/capabilities/test_mobile_reaction_listener.py`:
   - Remote approval acceptance unblocks the waiting task.
   - Remote denial halts tool execution.
   - Timeout triggers fallback cleanly without blocking the loop indefinitely.
   - Unauthorized user callbacks and reactions are rejected.
</action>

pytest tests/capabilities/test_mobile_reaction_listener.py -v
</verify>
<done>
Mobile reaction listener bridge enables remote approval via Telegram and Discord buttons/reactions, handles timeouts safely, and passes all integration tests.
</done>
