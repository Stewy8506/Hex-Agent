# Plan 37-02: Mixture-of-Agents Architecture & Repetition Sentry

<objective>
Implement the Mixture-of-Agents (`moa.py`) proposer-aggregator multi-model synthesis engine for complex reasoning turns, alongside the Degenerate Loop and Repetition Sentry (`repetition_sentry.py`) to intercept token repetition, tool call thrashing, and action loops with steering prompt injections and thinking tag scrubbing.
</objective>

<name>1. Implement Mixture-of-Agents (MoA) Proposer-Aggregator Engine</name>
<files>

src/harness_core/core/orchestrator.py
src/harness_core/core/react_loop.py

</files>
<action>
1. Create `src/harness_core/core/moa.py`:
   - Define `ProposerConfig`: model name, temperature, provider, timeout_seconds (default 15.0).
   - Define `MoAConfig`: list of `proposers: list[ProposerConfig]`, `aggregator: ProposerConfig`, `min_proposers_required: int` (default 1), `max_parallel_workers: int` (default 4).
   - Define `ProposerOutput`: candidate index, model name, content, latency_ms, tokens_used, is_error.
   - Define `MoAResult`: final synthesized text, individual proposer outputs, total_latency_ms, aggregator_model.
   - Implement `MixtureOfAgents`:
     - `query_proposers(prompt: str, messages: list[dict[str, Any]]) -> list[ProposerOutput]`: Executes calls across all proposers in parallel using `concurrent.futures.ThreadPoolExecutor` or `asyncio.gather`. Handles timeouts and individual exceptions gracefully.
     - `build_aggregator_prompt(prompt: str, proposer_outputs: list[ProposerOutput]) -> list[dict[str, Any]]`: Formats candidate solutions into an authoritative prompt:
       `"You have been provided with responses from candidate reasoning models. Synthesize the most accurate, cohesive, and complete solution. Reconcile contradictions and eliminate errors."`
     - `synthesize(prompt: str, messages: list[dict[str, Any]]) -> MoAResult`: Orchestrates proposer querying, aggregates successful responses, calls the primary aggregator model, and formats structured output.
2. Wire `MixtureOfAgents` into `HarnessOrchestrator` and `ReActLoop`:
   - Add optional `moa_config` to `ReActConfig`.
   - When enabled, reasoning turns route prompt evaluations through `MixtureOfAgents` before tool decision execution.
   - Record token usage and latencies in `LedgerStore` step metrics.
3. Export `MixtureOfAgents` and `MoAConfig` in `src/harness_core/core/__init__.py`.
4. Author comprehensive test suite in `tests/test_mixture_of_agents.py`:
   - Parallel proposer execution and mock responses.
   - Partial proposer failure and timeout resilience (continues as long as `min_proposers_required` succeed).
   - Fallback behavior when all proposers fail (falls back directly to primary aggregator alone).
   - Aggregator prompt compilation and token accounting.
</action>

</verify>

Mixture-of-Agents concurrently queries multiple proposer models, synthesizes cohesive outputs via the primary aggregator, handles partial failures gracefully, and passes all unit and integration tests.

<name>2. Implement Degenerate Loop / Repetition Sentry & Thinking Tag Scrubber</name>
<files>

<action>
1. Create `src/harness_core/cognition/repetition_sentry.py`:
   - Token & N-Gram Repetition Detection:
     - `is_repetition_dominated(text: str, dominance_ratio: float = 0.5) -> bool`:
       - Fast path: single normalized line duplicated enough to cover 50% of the fragment.
       - Window-count scan: 60-character sliding window recurring $\ge 5$ times covering 50% of text.
       - Periodic run scan: detects repeating phrases across evenly spaced anchors and measures true repeating period length.
     - `is_runaway_repetition(text: str) -> bool`: Stricter check requiring both window dominance and distinct non-empty line ratio $\le 0.5$.
   - Tool Call Thrashing & Action Loop Detection:
     - `ActionLoopDetector`: Tracks recent tool invocations `(tool_name, hash(arguments), result_status)`.
     - Identifies degenerate thrashing:
       - Identical call repetition: Same tool and identical arguments repeated $\ge 3$ consecutive times with identical error or empty output.
       - Ping-pong action cycle: Repeating sequence of 2-3 tools (e.g. `ToolA -> ToolB -> ToolA -> ToolB`) without state progression.
   - Out-of-Band Steering Generator:
     - `generate_steering_prompt(loop_type: str, details: dict[str, Any]) -> str`: Returns authoritative system injection:
       `"[SYSTEM STEERING: Degenerate action loop detected on {tool_name}. Repeating this exact operation will not succeed. Halt immediately and adopt an alternative approach or report the blocker.]"`
   - Leaked Thinking Tag Scrubber:
     - `strip_thinking_tags(text: str) -> tuple[str, str | None]`:
       - Extracts contents of `<think>...</think>` (complete or unclosed streaming tail `<think>...$`) into `reasoning_content`.
       - Strips `<think>` blocks from user-visible / storage text, preventing reasoning leakage to output channels.
2. Integrate into `ReActLoop` (`src/harness_core/core/react_loop.py`):
   - In `_invoke_caller`: feed output through `is_runaway_repetition()`; if tripped, truncate and inject repetition warning.
   - In tool execution cycle: evaluate tool call against `ActionLoopDetector`. If thrashing is detected, skip redundant execution, inject out-of-band steering prompt as observation, and decrement remaining loop retries.
   - Clean all model outputs with `strip_thinking_tags()` before persisting to dialogue history or ledger.
3. Export `RepetitionSentry`, `ActionLoopDetector`, and `strip_thinking_tags` in `src/harness_core/cognition/__init__.py`.
4. Author comprehensive test suite in `tests/test_repetition_sentry.py`:
   - Verbatim line repeats and sliding window dominance detection.
   - Legitimate repetitive text (batch inserts, markdown tables) allowed without false positives.
   - Action thrashing detection for repeat tool calls and ping-pong cycles.
   - Steering prompt injection and loop disruption.
   - Thinking tag extraction and sanitization on closed and open tags.
</action>

pytest tests/test_repetition_sentry.py -v
</verify>
<done>
Repetition sentry accurately detects token repetition and action thrashing, injects out-of-band steering prompts to break loops, scrubs thinking tags cleanly, and passes all unit tests.
</done>
