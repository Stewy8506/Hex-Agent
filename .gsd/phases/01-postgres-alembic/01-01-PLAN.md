  <name>Configure Alembic migration environment files</name>
  <files>alembic.ini, migrations/env.py, migrations/script.py.mako</files>
  <action>
    Create and configure the core Alembic infrastructure:
    1. Create `alembic.ini` in project root pointing `script_location = migrations`. Configure file template naming `%%(year)d_%%(month).2d_%%(day).2d_%%(rev)s_%%(slug)s` or sequential revisions.
    2. Create `migrations/script.py.mako` providing the standard revision template with docstring, revision identifiers, `upgrade()`, and `downgrade()`.
    3. Implement `migrations/env.py` to:
       - Dynamically read connection URL from environment variable `HARNESS_DATABASE_URL` or `DATABASE_URL`.
       - Fallback cleanly to a local SQLite database file (e.g. `sqlite:///migrations/alembic_dev.db`) if no PostgreSQL URL is configured.
       - Support both offline migrations (`run_migrations_offline`) emitting SQL DDL and online migrations (`run_migrations_online`).
       - For SQLite connections, configure `render_as_batch=True` on `context.configure` to support alter operations.
    AVOID: Hardcoding database passwords or failing with an unhandled exception when optional PostgreSQL libraries are not present during SQLite offline inspection.
  </action>
  <verify>python3 -c "import alembic.config; cfg = alembic.config.Config('alembic.ini'); print('Alembic config valid:', cfg.get_main_option('script_location'))"</verify>
  <done>alembic.ini and migrations/env.py parse without errors and locate the migrations directory.</done>
