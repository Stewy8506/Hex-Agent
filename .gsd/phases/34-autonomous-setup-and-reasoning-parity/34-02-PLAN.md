# Plan 34.02: Autonomous Agent Self-Setup & Environment Auto-Discovery

<objective>
Enable HEX to autonomously configure itself based on host environment facts, reaching parity with Hermes's conversational onboarding and self-setup capabilities. Build `src/harness_core/auto_setup.py`, wire `hex setup --auto`, auto-configure messaging gateways, and implement conversational TUI onboarding.

Purpose: Allow operators to bootstrap HEX in 5 seconds with zero manual configuration, or ask the agent in natural language to finish setting itself up.
Output: `auto_setup.py`, CLI/TUI integration, and `tests/test_auto_setup.py`.
</objective>

<tasks>
<task>
<name>1. Implement Environment Discovery & Auto-Setup Synthesizer</name>
<action>
Create `src/harness_core/auto_setup.py` with:
1. `EnvironmentSnapshot` dataclass:
   - Hardware: OS, arch, RAM, Apple Silicon, Metal, CUDA.
   - Devtools: presence of `git`, `docker`, `python3`, `node`, `clang`, `rustc`, `brew`.
   - IDE credentials: resolved Antigravity IDE OAuth session.
   - Environment keys: Anthropic, OpenAI, Gemini, OpenRouter, DeepSeek, etc.
   - Messaging tokens: Telegram bot token, Discord bot token, allowed users.
2. `detect_environment(config_dir: Path | None = None) -> EnvironmentSnapshot`:
   - Runs non-invasive discovery across filesystem, paths, and environment variables.
3. `synthesize_optimal_config(env: EnvironmentSnapshot) -> dict[str, Any]`:
   - Priority hierarchy for model:
     a) Google Antigravity (if IDE session exists) -> included subscription quota.
     b) Anthropic (if ANTHROPIC_API_KEY) -> Claude 3.7 with reasoning effort medium.
     c) OpenAI (if OPENAI_API_KEY) -> GPT-4o / o3-mini.
     d) Gemini (if GEMINI_API_KEY) -> Gemini 2.5 Pro.
     e) Local Ollama (if running on localhost:11434) -> local offline zero-egress.
     f) Fallback to local offline profile.
   - Sets deterministic compressor on Apple Silicon M4 / Darwin ARM64.
   - Configures DuckDuckGo free search by default.
   - Validates and enables Telegram/Discord gateways if tokens exist.
4. `execute_auto_setup(config_dir: Path | None = None) -> dict[str, Any]`:
   - Writes `config.yaml` and `credentials.env` atomically.
</action>
<verify>
Run unit tests in `tests/test_auto_setup.py` validating synthesis across Antigravity, Anthropic, OpenAI, local Ollama, and messaging token scenarios.
</verify>
<done>
Autonomous setup synthesizer produces valid production configuration across all environment fixtures.
</done>
</task>

<task>
<name>2. Wire CLI '--auto' and Conversational TUI Onboarding</name>
<action>
1. In `src/harness_core/cli.py`:
   - Add `--auto` flag to `hex setup` / `hex onboard`.
   - Call `execute_auto_setup()` when `--auto` is passed.
2. In `src/harness_core/onboard.py`:
   - Integrate auto-setup path and display clear summary of auto-configured values.
3. In `src/harness_core/tui.py`:
   - In unconfigured launch intercept, if interactive, offer conversational option:
     `[1] Auto-Configure (Recommended: detects IDE tokens, dev tools, and optimal model)`
     `[2] Step-by-Step Custom Wizard`
   - If user types "just set yourself up", "auto", or "make it work", trigger auto-setup and resume immediately.
</action>
<verify>
Execute `hex setup --auto --config-dir /tmp/test_hex_auto` and verify generated `.hex/config.yaml` and `.hex/credentials.env`.
</verify>
<done>
`hex setup --auto` runs cleanly non-interactively and conversational onboarding correctly intercepts unconfigured sessions.
</done>
</task>
</tasks>
