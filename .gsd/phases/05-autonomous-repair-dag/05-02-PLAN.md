# Plan 05.02: Dynamic DAG Replanning & Autonomous Repair Benchmark

<objective>
Implement Dynamic DAG Replanning and Selective Subgraph Invalidation in `HarnessOrchestrator` (`src/harness_core/orchestrator.py`) and `LedgerStore` (`src/harness_core/db.py`). When an execution step produces unexpected side-effects (e.g. modifies files outside declared scope, or Active Graphify detects new downstream callers), the orchestrator dynamically mutates the task DAG. It selectively invalidates only downstream dependent steps without discarding already-verified independent steps, dynamically pins newly impacted tests to the verification plan, records a monotonic plan revision increment (`revision` and `supersedes_revision`), and logs a cryptographically hash-chained `PLAN_REVISED` task event. Author comprehensive unit and integration tests in `tests/test_dag_replanning.py`, and run full repository regression verification.

Purpose: Enable the harness to adaptively adjust its execution plan when runtime modifications introduce unexpected dependencies, avoiding unnecessary re-execution of independent work while guaranteeing that all affected downstream components and tests are re-evaluated.
Output: Dynamic DAG replanning engine, selective invalidation algorithms, and comprehensive test suite in `tests/test_dag_replanning.py`.
</objective>

  <name>Implement Dynamic DAG Replanning and Selective Subgraph Invalidation</name>
  <files>src/harness_core/orchestrator.py, src/harness_core/db.py</files>
  <action>
    Implement dynamic DAG replanning and selective invalidation in `src/harness_core/orchestrator.py` and `src/harness_core/db.py`:
    1. In `src/harness_core/orchestrator.py`, implement `replan_dag(self, task_id: str, current_plan: dict[str, Any], mutated_step_id: str, actual_modified_files: list[str], attempt_ws: Path) -> dict[str, Any]`:
       - Parse the active DAG nodes from `current_plan.get("dag") or []`.
       - Downstream Dependency Analysis:
         - Construct a directed adjacency graph of step dependencies based on `node.get("depends_on", [])`.
         - Perform reachability traversal (BFS/DFS) from `mutated_step_id` to identify all transitive downstream dependent step IDs.
         - Also check if any step's input files or declared targets overlap with `actual_modified_files` or blast-radius symbols.
       - Selective Invalidation:
         - For each node in the DAG:
           - If node `step_id` is in the transitive downstream set:
             - Mark `node["status"] = "INVALIDATED"`.
             - Remove from `completed_step_ids` set so the step will be re-executed.
           - Else if node `step_id` was already completed and is NOT in the downstream set:
             - Preserve `node["status"] = "COMPLETED"`.
             - Keep in `completed_step_ids` without re-executing.
       - Dynamic Blast-Radius Test Pinning:
         - Invoke `blast_report = self.graphify.compute_blast_radius(attempt_ws, actual_modified_files)`.
         - Extract newly discovered `impacted_tests = blast_report.impacted_tests`.
         - Merge with existing plan `blast_radius_checks`:
           `existing_checks = list(current_plan.get("blast_radius_checks") or [])`
           `combined_checks = sorted(set(existing_checks) | set(impacted_tests))`
       - Monotonic Plan Revision & Ledger Event:
         - Call `self.ledger.save_plan(task_id, dag_nodes, blast_radius_checks=combined_checks, rationale=f"Dynamic replan triggered by step {mutated_step_id}")`.
           - Note: `save_plan` automatically calculates `revision = prev_rev + 1` and sets `supersedes_revision = prev_rev`.
         - Record a hash-chained task event:
           `self.ledger.record_event(`
           `    task_id,`
           `    event_type="PLAN_REVISED",`
           `    reason_code="SELECTIVE_SUBGRAPH_INVALIDATION",`
           `    workspace_tree_sha=self.cow.compute_tree_sha(attempt_ws),`
           `    payload={`
           `        "mutated_step_id": mutated_step_id,`
           `        "invalidated_step_ids": sorted(downstream_ids),`
           `        "preserved_step_ids": sorted(preserved_ids),`
           `        "pinned_blast_radius_tests": combined_checks,`
           `        "new_revision": new_plan["revision"],`
           `    },`
           `)`
       - Return `new_plan`.
    2. In `_execute_standard_dag` in `src/harness_core/orchestrator.py`:
       - After executing each step:
         - Check for unexpected side-effects:
           - Declared side effects: `declared = set(node.get("side_effects") or [])`.
           - Actual modified files written by the step: `actual = set(step_modified_files)`.
           - If `actual - declared`: unexpected file modifications occurred!
           - Or if step payload specifies `trigger_replan=True` or blast radius detects new downstream symbols:
             - Invoke `plan = self.replan_dag(task_id, plan, step_id, list(actual), attempt_ws)`.
             - Update `dag_nodes = list(plan.get("dag") or [])`.
             - Continue DAG loop over pending/invalidated nodes.
    AVOID: Re-running all steps from scratch upon replanning; independent completed steps must remain completed and valid.
  </action>
