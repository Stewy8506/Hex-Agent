# Plan 05.01: Multi-Turn Autonomous Repair Loop & Retry Escalation

<objective>
Implement the multi-turn autonomous repair loop in `HarnessOrchestrator` (`src/harness_core/orchestrator.py`). When a verification step (`run_tests`) fails during execution of an R2 coding step, the orchestrator enters an iterative repair loop (`RUNNING` -> `VERIFYING` -> `RUNNING` -> `VERIFYING` -> `SUCCEEDED` / `NEEDS_ATTENTION`). The harness uses the Tier-1 M4 Log Compressor to extract dense failure traces (exact failing file, line, and assertion), computes Active Graphify blast-radius warnings, requests a repair patch from the model router, applies the patch to the isolated CoW workspace (`attempt_ws`), and re-executes pinned verification tests. If retries (`TaskBudget.max_retries_per_step`) or task budget limits are exhausted, the orchestrator preserves an immutable forensic CoW snapshot and checkpoint of the dirty workspace and safely escalates to `NEEDS_ATTENTION`. Validate end-to-end with unit and integration tests in `tests/test_autonomous_repair.py`.

Purpose: Enable the harness to autonomously fix bugs and test failures within budget, eliminating premature task failures while guaranteeing safe escalation with forensic snapshots when repairs cannot be resolved.
Output: Core multi-turn repair engine, forensic snapshot preservation, and comprehensive test suite in `tests/test_autonomous_repair.py`.
</objective>

    Enhance `HarnessOrchestrator` in `src/harness_core/orchestrator.py` to support multi-turn iterative repair:
    1. In `HarnessOrchestrator.__init__`, accept an optional `repair_patch_generator: Callable[..., list[dict[str, Any]]] | None = None` to allow injecting deterministic or custom repair strategies for testing and benchmarking alongside the default model router pipeline.
    2. Implement `generate_repair_patch(self, task_id: str, attempt_ws: Path, failure_digest: str, blast_report: Any, modified_files: list[str]) -> list[dict[str, Any]]`:
       - If `self.repair_patch_generator` is provided, call it.
       - Otherwise, formulate a prompt containing:
         - Compressed failure digest (failing file, line number, assertion).
         - Active Graphify blast-radius warning and impacted caller symbols.
         - Current code contents of the failing files.
         - Request for concrete file modification actions (`[{"tool_id": "write_file", "args": {"path": ..., "content": ...}}]`).
       - Query `self.router.execute_routed_request` with `task_class="repair"`, `risk_class="R2"`, prompt, and task budget.
       - Parse response to extract file modification operations. If model returns pure Python code or fallback text, provide resilient fallback parsing to generate valid file write operations.
    3. In `_execute_standard_dag` around lines 420–460:
       - When initial execution completes, execute verification:
         `ver_outcome = self.proof_service.run_verification_and_build_proof(...)`
       - If `not ver_outcome["passed"]`:
         - Determine maximum repair retries:
           `task_budget = TaskBudget.from_dict(task.get("budget"))`
           `max_repair_retries = int(constraints.get("max_repair_attempts") or task_budget.max_retries_per_step or 2)`
         - Initialize repair tracking: `repair_attempt = 0`.
         - Loop while `not ver_outcome["passed"]` and `repair_attempt < max_repair_retries`:
           - Check budget limits (`task_budget.max_cost_usd`, etc.). If exceeded, break to escalation.
           - Increment `repair_attempt += 1`.
           - Extract raw test failure output:
             `raw_output = ver_outcome.get("verification_results", {}).get("test_output_excerpt", "")`
           - Invoke Tier-1 log compression:
             `comp_result = self.router.compress_verbose_log(raw_output)`
             `failure_digest = comp_result.get("compressed_text", raw_output)`
           - Compute current blast-radius report:
             `blast_report = self.graphify.compute_blast_radius(attempt_ws, modified_files)`
           - Transition state machine: `VERIFYING` -> `RUNNING`
             `reason_code="AUTONOMOUS_REPAIR_ATTEMPT"`
             `payload={"repair_attempt": repair_attempt, "max_retries": max_repair_retries, "failure_digest": failure_digest[:500]}`
           - Generate repair patch using `self.generate_repair_patch(...)`.
           - Apply repair patch operations to `attempt_ws` via `self.gateway.invoke(...)` or `self.gateway.execute_code_mode_composition(...)`.
           - For any file written, append path to `modified_files` if not already present.
           - Transition state machine: `RUNNING` -> `VERIFYING`
             `reason_code="REPAIR_VERIFICATION_ATTEMPT"`
             `payload={"repair_attempt": repair_attempt}`
           - Re-execute verification:
             `ver_outcome = self.proof_service.run_verification_and_build_proof(...)`
       - If `ver_outcome["passed"]`:
         - Sync verified `attempt_ws` changes back to `source_ws` if `modified_files`.
         - Update attempt status to `"SUCCEEDED"`.
         - Record episodic memory summary.
         - Transition task: `VERIFYING` -> `SUCCEEDED` (reason: `"PROOF_VERIFIED"`, payload including `"repair_attempts": repair_attempt`, `"proof_id": ver_outcome["proof"]["proof_id"]`).
    AVOID: Terminating immediately upon the first verification failure; always attempt bounded multi-turn repair within budget.
  </action>

           - If budget ceiling breached: `failure_class = "BUDGET_EXCEEDED"`, `reason_code = "BUDGET_EXHAUSTED"`

           `self.ledger.update_attempt(attempt_id, status="FAILED", head_tree_sha=forensic_sha, failure_class=failure_class)`

           `        "verification_results": ver_outcome["verification_results"],`

           `    },`
