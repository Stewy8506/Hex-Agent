  <name>Native Tool Schema History Formatting & Transient Error Retry Resilience</name>
  <files>src/harness_core/react_loop.py</files>
  <action>
    1. In `src/harness_core/react_loop.py`:
       - Update message history appending following tool execution in `ReActLoop.run`:
         - When appending tool execution results to `self.messages`, emit native `role: "tool"` messages alongside the observation payload:
           ```python
           self.messages.append(
               {
                   "role": "tool",
                   "tool_call_id": tool_res.call_id,
                   "name": tool_res.name,
                   "content": obs_payload,
                   "observation": obs_content,
               }
           )
           ```
         - This satisfies OpenAI/Anthropic/Gemini API contracts requiring `role: "tool"` matching the preceding assistant's tool call id, while preserving `observation` containing the XML tag `<observation tool="...">` for backward compatibility with existing tests and prompting engines.
       - In `_format_messages_to_prompt(messages)`:
         - Support `role == "tool"` (or `role == "TOOL"`) when formatting chat messages into plain-text fallback prompts:
           ```python
           if role == "TOOL":
               tool_name = msg.get("name", "tool")
               lines.append(f"[TOOL ({tool_name})]\n{content}")
           ```
       - Implement transient error retry with exponential backoff and jitter in `_call_model`:
         - Add configurable retry parameters to `ReActConfig`:
           - `max_retries: int = 3` (total attempts = 4)
           - `initial_retry_delay: float = 0.5`
           - `backoff_factor: float = 2.0`
           - `retry_jitter: float = 0.1`
         - Implement transient error detection helper `_is_transient_error(exc: Exception) -> bool`:
           - Check for HTTP 429 (rate limit), HTTP 503 (service unavailable / overloaded), connection timeouts, read timeouts, socket timeouts, and `ProviderUnavailableError` or `urllib.error.HTTPError` with transient status codes or messages.
         - Wrap model caller execution in an iterative retry loop:
           - On transient error and attempt < max_retries: calculate exponential backoff delay `delay = initial_retry_delay * (backoff_factor ** attempt) + random.uniform(0, retry_jitter)`, sleep using `time.sleep(delay)`, and retry.
           - On non-transient error (e.g. HTTP 400, 401, ValueError, syntax error), do not retry; raise immediately.
           - If retries are exhausted, raise the final exception so the loop logs the failure cleanly with `termination_reason="error"`.
    AVOID: Retrying non-transient 400 Bad Request or 401 Unauthorized errors which waste user quota.
  </action>
