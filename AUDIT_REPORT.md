## 5. Core Subsystem Audit Findings (Step 3 Breakdown)

1. **Durable CoW Workbench & Sandboxes ([cow.py](file:///Users/anv./Development/Harness/src/harness_core/cow.py), [sandbox.py](file:///Users/anv./Development/Harness/src/harness_core/sandbox.py)):**
   - `APFSAndPortableCoWProvider` probes and executes `/bin/cp -c -R` on macOS Darwin APFS.
   - `OverlayFSSnapshotProvider` manages `lowerdir`, `upperdir`, `workdir`, and `merged` mounts via `fuse-overlayfs`, `unshare -m -U -r mount -t overlay`, or kernel `mount -t overlay` with `atexit` unmount cleanup.
   - `BtrfsSnapshotProvider` executes `btrfs subvolume snapshot -r` and `btrfs subvolume delete`.
   - `BubblewrapSandbox` (`--unshare-net --unshare-pid --unshare-ipc --ro-bind /usr ... --clearenv`), `DockerPodmanSandbox` (`--network none --read-only --tmpfs /tmp:rw,noexec,nosuid`), and `RestrictedSubprocessSandbox` enforce workspace containment, `sanitize_environment()` credential stripping, process group termination (`os.setsid` / `os.killpg`), and POSIX `RLIMIT_CPU`/`RLIMIT_NPROC` limits.
2. **Default-Deny Tool Gateway & 0ms Journal Replay ([gateway.py](file:///Users/anv./Development/Harness/src/harness_core/gateway.py)):**
   - Enforces `R0`–`R4` risk tiers (`R4` unconditionally denied, `R3` raises `ApprovalRequiredInterrupt` unless pre-approved, `fast_path` restricted to `R0`/`R1`).
   - Scrubs secrets via `redact_secrets()` across strings, dicts, and lists before journaling or returning tool output.
   - Replays previously `SEALED` tool calls in `~0.1–0.5ms` (`< 15ms` verified in `test_cross_machine_cow_sync.py` and `test_mcp_gateway_journal.py`) without re-invoking underlying handlers or MCP subprocesses.
3. **Dual-Driver Storage & Alembic Migrations ([db.py](file:///Users/anv./Development/Harness/src/harness_core/db.py), [0001_initial_schema.py](file:///Users/anv./Development/Harness/migrations/versions/0001_initial_schema.py)):**
   - `LedgerStore` routes transparently between PostgreSQL (`postgresql://` / `postgresql+asyncpg://`) using `asyncpg` connection pools and `FOR UPDATE SKIP LOCKED`, and SQLite WAL (`PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;`).
   - [0001_initial_schema.py](file:///Users/anv./Development/Harness/migrations/versions/0001_initial_schema.py) defines `upgrade()` and reverse-FK `downgrade()` across all 16 authoritative tables, including `uq_task_events_task_seq`, `uq_plans_task_revision`, and `idx_tool_calls_lookup`.
4. **External MCP Server Client ([mcp_client.py](file:///Users/anv./Development/Harness/src/harness_core/mcp_client.py)):**

## 6. Architectural & Security Observations

### Key Strengths
- **Defense-in-Depth Supply-Chain & Execution Containment:** Combining static AST/YARA pattern scanning, OSV dependency checks, Tier-1 semantic purpose alignment, SHA-256 runtime bundle verification (`verify_skill_runtime_integrity`), and MCP manifest hash pinning prevents both initial ingestion and post-registration tampering of skills or MCP tools.
- **Zero-Ambiguity Crash & Failover Recovery:** Pairing pre-execution `PENDING` -> `SEALED` call-journal memoization with Merkle-hashed CoW snapshots (`workspace_tree_sha`) and monotonic lease fencing tokens eliminates split-brain writes and duplicate external side effects during worker crashes or network partitions.
- **Resilient Zero-Dependency Fallbacks:** Every external integration (`mlx_lm`, `asyncpg`, `uvicorn`, `networkx`, `bwrap`/`docker`) has a verified standard-library fallback, enabling hermetic local execution and testing on any POSIX host without sacrificing production scalability.

### Operational Caveats & Recommendations for Future Releases
1. **Unauthenticated One-Click `GET /v1/approvals/{id}:decide` Links:** To support one-click approval from Telegram/Discord clients, `server.py` exempts `/v1/approvals/{id}:decide` from the `X-Worker-Token` header check and relies on the unguessability of `approval_id` (`apr_<12-hex-chars>`). For internet-facing control planes (`HARNESS_PUBLIC_BASE_URL`), signing decision URLs with an expiring HMAC query parameter (e.g., `?decision=approve&sig=<hmac>&exp=<ts>`) and preventing link-preview bots from triggering state changes on `GET` (by rendering a confirmation button on `GET` that submits a `POST`, or checking `User-Agent` against Telegram/Discord preview crawlers) is recommended.
2. **Test Cleanup Warning in `test_worker_daemon.py`:** Under Python 3.14, `test_rest_client_auth_rejection` and `test_rest_client_concurrency_fencing_conflict` emit a benign `ResourceWarning` from `urllib.error.HTTPError` holding an unclosed `io.BytesIO` stream in `make_mock_urlopen`. Closing the `HTTPError` in `RestWorkerClient._request`'s `except urllib.error.HTTPError as exc:` block (`exc.close()`) will silence this warning on Python 3.14+.
3. **Sandboxed Test Runner Socket Permissions:** `TestGracefulServerRunner` in [tests/test_production_server.py](file:///Users/anv./Development/Harness/tests/test_production_server.py) binds `ThreadingHTTPServer(("127.0.0.1", 0), ...)`. When running inside strict OS sandboxes that block `bind()` on `127.0.0.1` by default, loopback network permission must be enabled for those 2 tests to bind an ephemeral port.
